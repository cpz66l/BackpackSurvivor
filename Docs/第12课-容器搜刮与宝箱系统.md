## 一、这节课实现了什么

### 台阶 1~4 · 宝箱交互链路（IInteractable 第二次签约）

- `LootChest` 实现 `IInteractable`：**探测器/HUD/E 键玩家侧零改动**——上节课签的接口这节课直接兑现
- 开箱 = 对自己的 dropPoint 调一次 `LootManager.TrySpawnDrop`（掉落管线"来源无关"伏笔回收）
- 退役三件套：`opened` 置位 → trigger 碰撞器关闭（探测器自然看不见，物理层替你广播）→ 模型变黑留残骸当"已搜"路标
- 三级宝箱束表（Common/Uncommon/Rare）→ 三级装备叶表，**稀有度地板数据驱动**（GDD 11.5 隐藏箱至少绿装）

### 台阶 5 · 宝箱池化 + 残骸回收

- `LootChest` 实现 `IPoolable`；归零清单：opened / 碰撞器 / 颜色（Awake 缓存 originalColor）/ 计时器
- 残骸回收策略决策：**选 A 计时回收（30s）**，未开箱不消失；B（挤压回收）留待地图课
- `ActiveCount` 静态计数（OnGetFromPool++ / OnReturnPool--，配平成立因为无池路径不过池回调）

### 台阶 6 · ChestSpawner 生成器

- 击杀触发：`EnemyAI.OnEnemyDied` 静态事件 → 每 K 杀（20）→ 生成一个；波次触发将来只换触发源
- 等级掷骰：嵌套 `[Serializable] ChestTier`（名字+颜色+束+权重），累加区间权重随机
- **拒绝采样**选点：候选 → 离玩家距离验证 → 不合格重摇，10 次预算上限
- 守卫顺序：场上上限（整数比较）→ 选点（最多 10 次随机）→ 掷等级 → 才动池子
- 击杀计数只成功才清零（背压：场上满时配额攒着）
- **出池即配置**：`pool.Get(pos)` → `Initialize(名字, 颜色, 束)`，池子只存中性预制体

### 台阶 7 · 飞出散落动画（首次协程）

- `LootManager.TrySpawnDrop`：`void → List<GameObject>`，敌人调用处零改动（C# 允许忽略返回值）
- `DropItem.PlayScatterFlight(from, to)`：掉落物自己会飞（Tell, Don't Ask），宝箱只管下命令
- 协程 `FlyRoutine`：关碰撞器 → 归一化 t 走 `Lerp + 4t(1-t)` 抛物线 → 落地显式归位 → 开碰撞器
- `OnGetFromPool` 追加碰撞器复位（防飞行中回收的中毒态）

### 地图边界（夹进来的关卡设计课）

- `MapBounds` 单一事实源：半径 40m 圆形竞技场（推导：5m/s × 16s 直线 ≈ 直径 80m，绕行体验 25~30s 甜点区）
- 地图知识归地图：GetRandomPoint / IsInside / ClampToInside；生成策略（离玩家距离/重试/上限）留 Spawner
- `OnDrawGizmos` 黄线圈，Scene 视图不调 Play 直调地图
- 玩家 clamp 一行：`transform.position = mapBounds.ClampToInside(transform.position)`
- 宝箱 minDistToPlayer 20 → 12（40m 图里 20m 排除圈会把宝箱全挤到外环）

## 二、最终代码

### LootChest.cs（三合同：IPoolable + IInteractable + 等级变体）

```csharp
public class LootChest : MonoBehaviour, IInteractable, IPoolable
{
    [SerializeField] private string chestName = "宝箱";
    [SerializeField] private LootTableData lootBundle;
    [SerializeField] private Renderer chestModel;      // 预制体里拖 Cube 子的 MeshRenderer
    [SerializeField] private Transform dropPoint;
    [SerializeField] private float survivalTime = 30f; // 残骸存活

    public static int ActiveCount { get; private set; }

    private float survivalTimer = 0f;
    private Collider chestCollider;
    private LootManager lootManager;
    private bool opened = false;
    private Color originalColor;
    private ObjectPool pool;

    private void Awake()
    {
        lootManager = FindAnyObjectByType<LootManager>();
        chestCollider = GetComponent<Collider>();
        originalColor = chestModel.material.color;      // 出厂色缓存（池化还原用）
    }

    private void Update()
    {
        if (!opened) return;                            // 未开箱永不消失
        survivalTimer += Time.deltaTime;
        if (survivalTimer >= survivalTime) Recycle();
    }

    // 出池即配置：生成器灌入等级三件套
    public void Initialize(string name, Color color, LootTableData bundle)
    {
        chestName = name;
        chestModel.material.color = color;
        lootBundle = bundle;
    }

    public string GetPrompt() => $"按 E 打开 {chestName}";

    public void Interact()
    {
        if (opened) return;
        opened = true;
        chestCollider.enabled = false;                  // 探测器自然失联，HUD 自动隐藏
        chestModel.material.color = Color.black;        // 残骸=已搜路标
        lootManager.TrySpawnDrop(dropPoint == null ? transform.position : dropPoint.position, lootBundle);
    }

    public void SetPool(ObjectPool p) => pool = p;
    public void Recycle() { if (pool != null) pool.Return(gameObject); else Destroy(gameObject); }

    public void OnGetFromPool()   // 归零清单：计时/状态位/碰撞器/颜色/计数
    {
        survivalTimer = 0f;
        opened = false;
        chestCollider.enabled = true;
        chestModel.material.color = originalColor;
        ActiveCount++;
    }
    public void OnReturnPool() { ActiveCount--; }
}
```

### ChestSpawner.cs（击杀触发 + 拒绝采样 + 出池即配置）

```csharp
public class ChestSpawner : MonoBehaviour
{
    [Serializable]
    public class ChestTier                            // 嵌套类：生成器内部配置，不值得 SO
    {
        public string chestName;
        public Color color;
        public LootTableData bundle;
        public int weight;
    }
    [SerializeField] private ChestTier[] tiers;
    [SerializeField] private ObjectPool chestPool;
    [SerializeField] private int killsToSpawn = 20;
    [SerializeField] private float minDistToPlayer = 12f;
    [SerializeField] private int maxAttempts = 10;
    [SerializeField] private int maxFieldCount = 5;

    private int killsCount = 0;
    private Health playerH;
    private MapBounds mapBounds;

    private void Awake()
    {
        playerH = GameObject.FindGameObjectWithTag("Player").GetComponent<Health>();
        mapBounds = FindAnyObjectByType<MapBounds>();
    }
    private void OnEnable()  { EnemyAI.OnEnemyDied += AddKillsCount; }
    private void OnDisable() { EnemyAI.OnEnemyDied -= AddKillsCount; }

    private void AddKillsCount()
    {
        killsCount++;
        if (killsCount >= killsToSpawn)
            if (TrySpawnChest()) killsCount = 0;      // 只成功才清零（背压）
    }

    private bool TrySpawnChest()
    {
        if (LootChest.ActiveCount >= maxFieldCount) return false;   // 最便宜的先判
        if (!TryFindSpawnPoint(out Vector3 pos)) return false;
        if (tiers == null) return false;
        ChestTier tier = PickByWeight(tiers);
        if (tier == null) return false;
        chestPool.Get(pos).GetComponent<LootChest>()
                 .Initialize(tier.chestName, tier.color, tier.bundle);
        return true;
    }

    private bool TryFindSpawnPoint(out Vector3 result)   // 拒绝采样：候选→验证→重摇→预算
    {
        for (int i = 0; i < maxAttempts; i++)
        {
            Vector3 pos = mapBounds.GetRandomPoint();     // 地图知识问地图
            if ((pos - playerH.Position).sqrMagnitude < minDistToPlayer * minDistToPlayer)
                continue;                                 // 刷脸，重摇
            pos.y = 0.5f;
            result = pos;
            return true;
        }
        result = Vector3.zero;
        return false;                                     // 预算耗尽，这轮放弃
    }
    // PickByWeight：累加区间权重随机（第三处专用实现，类型不同不复用 LootRoller）
}
```

### MapBounds.cs（单一事实源，40m 圆形竞技场）

```csharp
namespace BS   // 待迁：应挪 Scripts/Core/ → BS.Core（挂账）
{
    public class MapBounds : MonoBehaviour
    {
        [SerializeField] private float radius = 40f;
        public float Radius => radius;
        public Vector3 Center => transform.position;    // 自己的位置=圆心（白嫖的配置）

        public Vector3 GetRandomPoint()
        {
            Vector2 offset = Random.insideUnitCircle * radius;
            return transform.position + new Vector3(offset.x, 0, offset.y);
        }
        public bool IsInside(Vector3 pos) { /* 拍平 y 比 sqrMagnitude */ }
        public Vector3 ClampToInside(Vector3 pos)
        {
            Vector3 offset = pos - Center;
            offset.y = 0f;                              // 拍平：边界是二维概念
            if (offset.sqrMagnitude <= radius * radius) return pos;   // 早返回
            Vector3 clamped = Center + offset.normalized * radius;    // 方向不变压长度
            clamped.y = pos.y;                          // y 还回去：高度归物理管
            return clamped;
        }
        private void OnDrawGizmos() { Gizmos.color = Color.yellow; Gizmos.DrawWireSphere(transform.position, radius); }
    }
}
```

### DropItem.cs（台阶 7 增量：会飞的掉落物 + 幂等收货口）

```csharp
[SerializeField] private float flightDuration = 0.4f;
[SerializeField] private float arcHeight = 2f;
private bool isCollected;

public void PlayScatterFlight(Vector3 from, Vector3 to)
{
    transform.position = from;
    StartCoroutine(FlyRoutine(from, to));
}
private IEnumerator FlyRoutine(Vector3 from, Vector3 to)
{
    itemCollider.enabled = false;                     // 飞行期间不可交互
    float t = 0f;
    while (t < 1f)
    {
        t += Time.deltaTime / flightDuration;         // 归一化进度
        if (t > 1f) t = 1f;                           // 钳制防低帧率过冲
        Vector3 horizontal = Vector3.Lerp(from, to, t);
        float height = arcHeight * 4f * t * (1f - t); // 零成本抛物线，t=0.5 峰值
        transform.position = horizontal + Vector3.up * height;
        yield return null;
    }
    transform.position = to;                          // 显式对齐终态，消浮点累计
    itemCollider.enabled = true;
}

public void Collect()
{
    if (isCollected) return;                          // 幂等守卫：同一生命周期只收一次
    isCollected = true;
    OnCollected?.Invoke(lootEntry);
    Recycle();
}
public void OnGetFromPool()                           // 归零清单：计时/碰撞器/幂等位
{
    survivalTimer = 0f;
    itemCollider.enabled = true;
    isCollected = false;
}
```

## 三、周期链路

### 宝箱生成链路

```
敌人 Die() → OnEnemyDied 广播 → ChestSpawner.AddKillsCount
  → 满 K 杀 → ActiveCount < 上限?
  → TryFindSpawnPoint: MapBounds.GetRandomPoint → 离玩家 ≥12m? → 最多 10 次
  → PickByWeight(tiers) 掷等级
  → chestPool.Get(pos) → OnGetFromPool 归零五项 → Initialize(名字/颜色/束)
  → 宝箱出厂：等级色、可交互、计数+1
```

### 开箱 → 散落 → 拾取链路

```
玩家近身 → detector 发现宝箱 → HUD "按 E 打开 XX宝箱"
  → E → Interact(): opened ✓ → 碰撞器关 → 变黑留残骸
  → LootManager.TrySpawnDrop(dropPoint, 宝箱束) → 装备生成于箱顶（叠放）
  → 每个 DropItem.PlayScatterFlight(箱顶, 随机地面点)
      → 关碰撞器 → 0.4s Lerp+抛物线 → 落地归位 → 开碰撞器
  → 玩家走近某件 → HUD 提示 → E → Collect()（幂等）→ OnCollected → 入包
  → 残骸 30s 后 Recycle → 计数-1 → 生成配额释放
```

## 四、设计思考（这节课真正学的东西）

### 1. 接口复用的回头钱，当天兑现

宝箱接入后，玩家侧的探测器、HUD、E 键、提示框**一行没改**。第 11 课签 `IInteractable` 时的设计预判（"宝箱/终端后续同接口复用"）当天变现。这就是面向接口编程最直白的证据：**新玩法 = 新实现类，不是新系统**。以后补给终端、医疗箱、撤离点全是这条路。

### 2. 出池即配置：池子存中性，变体靠灌入

宝箱池只存一个中性预制体，等级三件套（名字/颜色/束）在 `Get` 后由 `Initialize` 灌入——和 `DropItem.Initialize(entry)` 同一模式。要点是**复位分两层**：`OnGetFromPool` 归零到中性出厂态（原色/未开/可碰），`Initialize` 施加变体配置（等级色/束）。两层都在，互相兜底。

### 3. 拒绝采样：程序化生成的通用手法

"生成候选 → 验条件 → 不合格重摇 → 设预算防死循环"。四行循环，却是刷怪点、宝箱点、以后地图装饰物、roguelike 房间布局的共用骨架。要点：**重试必须有预算**（10 次），失败要有退路（这轮不刷），条件和候选解耦（刷脸判定是生成策略，随机点是地图知识）。

### 4. 协程 vs Update：一次性时间线 vs 持续行为

Update+字段服务"每帧都要判断的持续状态"（磁吸、计时器）；协程服务"有明确起止的一次性动作"（飞 0.4s）。协程把中间状态收进局部变量，方法结束状态消亡——**池化归零清单不用为它加长**。但协程跑在池化对象上要答一道附加题：回池即 SetActive(false) 会杀协程，被中断留下的副作用（关着的碰撞器）必须进归零清单。

### 5. 地图边界：单一事实源 + 知识归属切分

边界只有一个主人 `MapBounds`，所有系统（生成器/玩家/将来的相机/危险区）问它。切分标准一句话：**换地图时要改的进 MapBounds，换玩法时要改的留各系统**。圆心用 `transform.position` 而不是序列化 Vector3——策划拖一下物体就挪了地图，组件自己的 transform 是白嫖的配置维度。

### 6. 幂等设计：让重复执行无害

`Collect()` 加 `isCollected` 守卫后，执行一次和执行 N 次效果相同——这就是幂等。配合消费者端"用完即清"（探测器交互后立即清目标），双端设防解决了"缓存的池化引用是会过期的支票"这个结构性矛盾。大厂面试"如何处理对象生命周期与缓存引用的矛盾"，这就是答题骨架。

## 五、踩坑记录

| 坑 | 根因 | 修法 | 沉淀 |
|---|---|---|---|
| Renderer NRE 三连（Awake/Interact/OnGetFromPool） | MeshRenderer 在子物体 Cube 上，`GetComponent` 不查孩子 | 预制体拖槽（或 GetComponentInChildren） | GetComponent 家族按层级选：自己/后代/祖先 |
| TryFindSpawnPoint NRE | 生成器不是玩家，`GetComponent<Health>()` 复制错了挂载对象 | FindGameObjectWithTag("Player") | **复制模式先看挂在谁身上** |
| 位置公式乘法 | `center * insideUnitCircle * radius`——缩放≠平移，原点时恒为零点 | 圆心 **+** 偏移 | 加法=平移，乘法=缩放 |
| `private new Collider collider` / CS0108 | 遮盖 MonoBehaviour 内置属性 | 改名 chestCollider | 编译器警告就是设计在报警 |
| 颜色还原漏写（池化第五考 2/3） | OnGetFromPool 漏 originalColor 还原 | 归零清单加颜色 | 归零要机械执行，不靠记性 |
| **BUG-005 双重回收** | 拾取后 0.1s 窗口内探测器持过期目标，连按 E 二次 Collect → 重复归还+双重入包 | 生产者幂等（isCollected）+ 消费者用完即清 | 池的防重警告是报警器不是噪音；池化引用=会过期的支票 |
| 角色飞天 | 把"偏移"当"绝对坐标"传参 + y 清零 → 每帧按进地面 → CC 去穿透向上弹射 | 三行删成一行 clamp | 调 API 看契约；调用方不替方法预处理 |
| using 事故 ×2 | DebugUI（#7）、`using static UnityEditor.PlayerSettings`（#8）混进运行时代码 | 删除 | **commit 前扫改动文件头部 using——新强制闸** |

## 六、面试问答

**Q：协程和 Update 怎么选？协程在对象池上有什么坑？**
A：持续行为（每帧判断的状态机、计时器）用 Update；有明确起止的一次性动作（飞行动画、淡入淡出）用协程——中间状态全是局部变量，方法结束自动消亡。池化对象上跑协程的坑：回池 SetActive(false) 会杀协程，被中断时留下的副作用（比如关掉的碰撞器）必须在 OnGetFromPool 复位。

**Q：什么是拒绝采样？为什么要设重试预算？**
A：生成候选→验证条件→不合格重摇的采样策略，程序化生成（刷怪点/宝箱/房间布局）的通用手法。必须设预算：条件苛刻时可能理论上永远摇不出（玩家站圆心+排除圈大），无预算就死循环。失败要有降级（这轮不刷），不能硬塞。

**Q：地图边界系统怎么设计？**
A：单一事实源——一个 MapBounds 组件垄断边界知识（随机点/在不在内/clamp），所有系统向它查询，改地图只改一处。形状选型跟着数学走：圆形和 insideUnitCircle 撒点、向量 clamp 天然吻合。边界判定只算水平（拍平 y），高度归物理管。配 OnDrawGizmos 让策划不进 Play 就能调。

**Q：你们对象池的防重复归还警告触发了，说明什么？怎么修？**
A：说明有逻辑路径在重复回收（池子本身没坏，警告是报警器）。实际案例：探测器 0.1s 扫描间隙缓存了过期目标，连按 E 对同一尸体二次 Collect——双重归还+双重入包。修法双端设防：生产者 Collect 幂等化（isCollected 守卫，同生命周期只收一次），消费者交互后立刻清缓存目标。

**Q：宝箱等级系统怎么做的数据驱动？**
A："出池即配置"：池子只存中性预制体，生成器按权重掷出等级（嵌套 [Serializable] ChestTier：名字+颜色+掉落束+权重），Get 后 Initialize 灌入。等级→稀有度地板的映射全靠 SO 表配置（Rare 宝箱束只接 Rare 装备叶表），加新等级不用改代码。嵌套类 vs SO 的选型：使用范围只在生成器内部就嵌套类，跨系统复用或策划独立调表才升级 SO。

**Q：GetComponent / GetComponentInChildren / GetComponentInParent 怎么区分使用？**
A：分别搜自己/自己与后代/自己与祖先。实际踩坑：脚本在根物体、Renderer 在子物体，GetComponent 返回 null 导致三连 NRE。 prefab 结构复杂时优先序列化字段拖槽（一次接线永久有效），代码查找注意 GetComponentInChildren 的性能成本（遍历整棵子树，启动时用别每帧用）。

## 八、思考题（附复习参考）

**Q1：`ActiveCount` 静态计数和 TargetRegistry 一样有"多场景隐患"，为什么现在还能用？**
> 当前项目只有一个战斗场景（01-Run），静态数据跨场景污染的问题暴露不出来；且计数自增自减严格配平在池回调里（无池路径不过回调，天然平衡）。隐患在引入多场景/场景切换时才发作——静态数据不会在场景切换时自动清零。已知债，场景流课时连 TargetRegistry 一起处理。

**Q2：协程和 Update+字段的分界线？把磁吸加速改写成协程行不行？**
> 分界线是"一次性时间线 vs 持续行为"。磁吸不行：它没有预定终点——每帧要根据玩家实时位置重算方向，是持续响应型行为，协程的"剧本式时间线"反而不灵活。飞出动画有明确的起点终点时长，是剧本，协程正合适。判断口诀：**动作剧本写死了吗？写死了用协程，要随机应变的用 Update**。

**Q3：`TrySpawnDrop` 从 void 改成返回 List，凭什么敢不改调用方？**
> C# 允许调用方忽略返回值，EnemyAI 的调用语句语法上依然合法、行为不变。这是"对扩展开放、对修改关闭"的轻量实践：新需求（宝箱要拿列表）通过扩展签名满足，老调用方零感知。但注意仅限"加返回值"这种兼容改动——改参数列表就是破坏性变更了。

**Q4：`insideUnitCircle`、`onUnitSphere`、随机角度×随机半径，三种"随机点"分布差别？**
> `insideUnitCircle`：圆盘内面积均匀（撒宝箱要的效果）；`onUnitSphere`：球面上均匀，只是方向不是位置；随机角度×`Random.Range(0,R)` 半径：角度均匀但半径上线性均匀→**圆心附近密度偏高**（半径小的圆环面积小却分到同样多的点）。撒布要面积均匀就选 insideUnitCircle，要环带均匀（刷怪）才用角度×半径。

**Q5：地图圆心用 `transform.position` 而不是序列化 `Vector3 center` 字段，好在哪？**
> 组件自己的 transform 是白嫖的配置维度：策划调地图直接在 Scene 里拖 Map 物体，所见即所得，还能配合 Gizmos 实时看圆圈挪动。序列化 Vector3 要在 Inspector 里敲三个数，调一次看不了效果。原则：**能长在场景里的配置就别藏在数字框里**。

**Q6："宝箱不许刷进危险区"这条规则该归谁？（归属切分练习）**
> 危险区的位置知识归 Zones 系统（或未来的 HazardRegistry），"不许刷进去"是生成策略归 ChestSpawner。落地方式：Spawner 在拒绝采样的验证环节加一个条件——向危险区系统查询"这个点在你的哪个区里吗"。不归 MapBounds：它只管"图内图外"，不懂图内的语义分区。归属判断口诀：**谁拥有数据，谁提供查询；策略归需求方**。
