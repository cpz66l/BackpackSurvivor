# 第25课 · 背包价值与物品价值显示

> 课程周期：2026-08-03  
> 前置：第24课《金币掉落与局内经济 HUD》  
> 关键词：物品价值、背包总价值、唯一物品去重、结算快照、UI 投影、RunResult

---

## 一、这节课实现了什么

第25课把“搜刮价值”从配置表里的数字，推进到了玩家可见的局内反馈和结算反馈。  
现在物品有单件价值，背包能显示总价值，结算页也能冻结本局结束时的背包价值。

### 任务 1 · LootEntry 到 Item 的价值链路

- `LootEntry.scoreValue` 作为静态配置源。
- `Item.ScoreValue` 作为运行时物品只读属性。
- `InventorySystem.CreateItemFromLootEntry()` 创建物品时传入 `scoreValue`。
- `DiscardToWorld()` 还原 `Item -> LootEntry` 时保留 `scoreValue`。

这保证了物品从地面进入背包、从背包丢回世界、再被捡起时，价值不会丢。

### 任务 2 · ItemView 显示单件价值

- `ItemView` 新增 `valueText`。
- `Bind(item)` 时显示 `item.ScoreValue`。
- 价值文本只是表现层，不反查掉落表，不根据 `item.Id` 写 if-else。
- `ValueText` 关闭 Raycast Target，不吃拖拽射线。

### 任务 3 · InventoryGrid 计算背包总价值

- `InventoryGrid.GetTotalScoreValue()` 遍历 `GetUniqueItems()`。
- 使用唯一物品列表累加，避免 2x2 物品按 4 个格子重复计算。
- 背包总价值仍然属于数据查询，不放在 UI 里硬算。

### 任务 4 · 背包面板显示总价值

- `InventoryUIController` 新增 `totalValueText`。
- `Redraw()` 后调用 `RefreshTotalValue()`。
- 文案显示为 `背包价值：￥X`。
- 拖拽期间仍沿用原门闸，结束后统一重绘并刷新价值。

### 任务 5 · 结算页接入背包价值快照

- `RunResult` 新增 `BackpackValue`。
- `GameSession.EndRun()` 结束时读取 `inventorySystem.Grid.GetTotalScoreValue()`。
- `ResultView` 在结算统计中显示背包价值。
- 结算页读的是 `RunResult` 快照，而不是实时查背包。

## 二、最终代码（关键片段）

### 1. Item 保存运行时价值

```csharp
public int ScoreValue { get; }
public float EffectValue { get; }

public Item(
    string id,
    Rarity rarity,
    int width,
    int height,
    ItemTag itemTag,
    ConnectableSides connectableSides,
    int scoreValue,
    float effectValue)
{
    Id = id;
    baseWidth = width;
    baseHeight = height;
    Rarity = rarity;
    Rotated = false;
    Level = 1;
    MaxLevel = 3;
    Tag = itemTag;
    LocalConnectableSides = connectableSides;
    ScoreValue = scoreValue;
    EffectValue = effectValue;
}
```

`ScoreValue` 进了 `Item`，就意味着背包系统不需要再反查配置表。  
运行时物品自己携带“我值多少钱”这个事实。

### 2. LootEntry 创建 Item 时保留价值

```csharp
private Item CreateItemFromLootEntry(LootEntry entry)
{
    if (entry == null) return null;

    return new Item(
        entry.id,
        entry.rarity,
        entry.width,
        entry.height,
        entry.itemTag,
        entry.connectableSides,
        entry.scoreValue,
        entry.effectValue);
}
```

这是本课最关键的数据入口。  
掉落配置只在创建运行时物品时被读取一次，之后 UI 和结算都读 `Item`。

### 3. Item 丢回世界时保留 scoreValue

```csharp
LootEntry entry = new LootEntry
{
    category = DropCategory.Equipment,
    id = item.Id,
    rarity = item.Rarity,
    width = item.Width,
    height = item.Height,
    amount = 1,
    itemTag = item.Tag,
    connectableSides = item.LocalConnectableSides,
    scoreValue = item.ScoreValue,
    effectValue = item.EffectValue,
};
```

这一步是“往返保真”。  
如果丢弃时忘记 `scoreValue`，玩家丢出去再捡回来，价值就会变成 0。

### 4. ItemView 显示单件价值

```csharp
if (valueText != null)
{
    if (item.ScoreValue <= 0)
        valueText.text = "￥ 0";
    else
        valueText.text = $"￥{item.ScoreValue}";
}
```

`ItemView` 只读 `Item.ScoreValue`，不参与任何价值计算。  
这保持了 UI 作为“投影层”的边界。

### 5. InventoryGrid 计算唯一物品总价值

```csharp
public int GetTotalScoreValue()
{
    int total = 0;
    foreach (Item item in GetUniqueItems())
    {
        if (item == null) continue;
        total += item.ScoreValue;
    }
    return total;
}
```

核心点是 `GetUniqueItems()`。  
背包是二维格子，但价值属于物品，不属于格子；大物品占几格都只能算一次。

### 6. 背包 UI 刷新总价值

```csharp
private void RefreshTotalValue()
{
    if (totalValueText == null) return;
    if (grid == null) return;

    totalValueText.text = $"背包价值：￥{grid.GetTotalScoreValue()}";
}
```

`InventoryUIController` 本来就是背包数据的表现投影，所以总价值文本放在这里很自然。  
它不保存总价值，只在需要重绘时读一次数据层。

### 7. RunResult 冻结背包价值

```csharp
public int BackpackValue { get; }

public RunResult(
    GameState finalState,
    float elapsed,
    int level,
    int totalXp,
    int killCount,
    int backpackValue)
{
    FinalState = finalState;
    Elapsed = elapsed;
    Level = level;
    TotalXp = totalXp;
    KillCount = killCount;
    BackpackValue = backpackValue;
}
```

结算页显示的是“结束那一刻”的成绩。  
所以背包价值进入 `RunResult`，而不是让 `ResultView` 实时查背包。

### 8. GameSession 生成结算快照

```csharp
int backpackValue = 0;
if (inventorySystem != null && inventorySystem.Grid != null)
    backpackValue = inventorySystem.Grid.GetTotalScoreValue();

RunResult runResult = new RunResult(
    finalState,
    Elapsed,
    Level,
    TotalXp,
    killCount,
    backpackValue);
```

`GameSession` 是一局规则主人，终局时由它收集结算数据最合适。  
`ResultView` 只展示 `RunResult`，不自己拼规则。

### 9. ResultView 展示背包价值

```csharp
statsText.text =
    $"存活时间：{FormatTime(runResult.Elapsed)}\r\n" +
    $"等级：{runResult.Level}\r\n" +
    $"总经验：{runResult.TotalXp}\r\n" +
    $"击杀数：{runResult.KillCount}\r\n" +
    $"背包价值：{runResult.BackpackValue}";
```

结算面板现在不只是战斗表现，也开始展示搜刮收益。  
这对“背包幸存者”这个项目名很重要：玩家能看到背包管理带来的成果。

## 三、周期链路

### 单件价值链路

```text
LootTableData.LootEntry.scoreValue
  ↓
InventorySystem.CreateItemFromLootEntry(entry)
  ↓
new Item(..., entry.scoreValue, entry.effectValue)
  ↓
Item.ScoreValue
  ↓
ItemView.Bind(item)
  ↓
ValueText 显示 ￥X
```

### 背包总价值链路

```text
InventoryGrid.cells[x,y]
  ↓
GetUniqueItems()
  ↓
HashSet<Item> 去重
  ↓
GetTotalScoreValue()
  ↓
累加每个唯一 Item.ScoreValue
  ↓
InventoryUIController.RefreshTotalValue()
  ↓
TotalValueText 显示 背包价值
```

### 结算快照链路

```text
玩家死亡 / 时间到
  ↓
GameSession.EndRun(finalState)
  ↓
inventorySystem.Grid.GetTotalScoreValue()
  ↓
new RunResult(..., backpackValue)
  ↓
OnRunEnded(runResult)
  ↓
ResultView.HandleRunEnded(runResult)
  ↓
结算页显示背包价值
```

### 丢弃往返保真链路

```text
Item.ScoreValue
  ↓
InventorySystem.DiscardToWorld(item)
  ↓
new LootEntry { scoreValue = item.ScoreValue }
  ↓
LootManager.SpawnEntry(entry, position)
  ↓
DropItem.Initialize(entry)
  ↓
再次拾取时 CreateItemFromLootEntry(entry)
  ↓
价值不丢失
```

## 四、设计思考

### 1. 为什么价值要从 LootEntry 传进 Item？

`LootEntry` 是静态配置，`Item` 是运行时物品。  
玩家真正放进背包、旋转、合并、丢弃的对象是 `Item`，不是 `LootEntry`。

所以正确方向是：

```text
配置表决定初始值
运行时物品保存当前值
UI 和结算只读运行时物品
```

这为第26课“合并升级后价值成长”留好了口子。

### 2. 为什么总价值不能按格子算？

背包用二维数组存占格，2x2 物品会占 4 个格子。  
如果直接遍历 `cells[x,y]` 累加，就会把同一个物品算 4 次。

背包里“占格”是空间问题，“价值”是物品问题。  
所以先拿唯一物品，再累加价值。

### 3. 为什么总价值放在 InventoryGrid，而不是 UI？

`InventoryGrid` 拥有当前背包里有哪些物品这个事实。  
`InventoryUIController` 只是把事实画出来。

如果 UI 自己遍历格子算价值，后面结算页、调试面板、任务系统也都要各算一遍，很容易规则不一致。  
把 `GetTotalScoreValue()` 放在数据层，所有消费方都读同一个结果。

### 4. 为什么结算页要读 RunResult 快照？

结算页展示的是一局结束时的成绩，不应该随着后续对象变化而变化。  
`RunResult` 的意义就是把终局瞬间的数据冻结下来。

所以正确顺序是：

```text
GameSession 终局收集数据
RunResult 冻结数据
ResultView 展示数据
```

这比 `ResultView` 自己去场景里找背包可靠。

### 5. 金币和背包价值为什么先不混在一起？

金币是局内货币，背包价值是物品搜刮价值。  
它们都属于经济反馈，但语义不同。

当前先把背包价值独立显示，后续可以再设计：

```text
金币收入
背包携带价值
击杀/等级战斗分
最终评分
```

不要太早把它们混成一个总数，否则玩家不知道自己到底是靠打怪、捡钱，还是背包装备拿分。

## 五、踩坑记录

### 1. 大物品不能按格子重复算价值

- **现象风险**：2x2 物品价值 100，如果按格子遍历会算成 400。
- **根因**：背包格子保存的是物品引用，同一个物品会出现在多个格子里。
- **修复**：复用 `GetUniqueItems()`，用 `HashSet<Item>` 去重后再累加。
- **沉淀**：背包空间按格子算，物品价值按唯一物品算。

### 2. UI 不应该反查掉落表

- **现象风险**：`ItemView` 根据 `item.Id` 查表或写 if-else，后续调价格容易出现 UI 和数据不一致。
- **根因**：把显示层误当成规则层。
- **修复**：`ItemView.Bind()` 只读 `item.ScoreValue`。
- **沉淀**：UI 是投影，不是事实源。

### 3. 丢弃路径也要保留新增字段

- **现象风险**：物品丢出背包后再捡回来，价值或效果值变成默认值。
- **根因**：`Item -> LootEntry` 还原时漏字段。
- **修复**：`DiscardToWorld()` 同步写回 `scoreValue` 和 `effectValue`。
- **沉淀**：任何往返路径新增字段都要两边查，入口和出口都不能漏。

### 4. 结算页必须读快照，不读实时状态

- **现象风险**：结算显示直接查背包，重开、清理对象或后续状态变化会让结果不稳定。
- **根因**：结果页和规则层边界不清。
- **修复**：`RunResult.BackpackValue` 在 `EndRun()` 时冻结。
- **沉淀**：结算数据先快照，再展示。

### 5. 纯展示 TMP 要关 Raycast Target

- **现象风险**：UI 文本覆盖背包区域后，拖拽可能被透明/文本控件吃掉射线。
- **处理**：`ValueText` 和 `TotalValueText` 作为纯展示控件关闭 Raycast Target。
- **沉淀**：射线家族规则继续执行：不负责交互的 UI 一律不挡输入。

## 六、面试问答

**Q1：你怎么实现背包总价值，如何避免大物品重复计算？**  
> 我没有直接遍历格子累加，而是先通过 `GetUniqueItems()` 拿到背包里的唯一物品列表，再累加每个 `Item.ScoreValue`。因为 2x2 物品会占多个格子，但价值属于物品本身，只能算一次。

**Q2：为什么价值字段放在 Item，而不是 UI 直接查 LootEntry？**  
> `LootEntry` 是静态配置，`Item` 是运行时物品。玩家拖拽、丢弃、合并的都是 `Item`。UI 直接查配置会让表现层知道太多规则，而且后续合并升级改变价值时，配置表已经不能代表当前运行时状态。

**Q3：为什么 `DiscardToWorld()` 也要处理 scoreValue？**  
> 因为丢弃是 `Item -> LootEntry` 的反向路径。如果只在拾取时传 `scoreValue`，丢弃时不写回，那么物品再次生成到世界后就会丢失价值。新增字段必须检查双向链路。

**Q4：为什么结算页使用 RunResult，而不是 ResultView 自己查背包？**  
> 结算页展示的是终局瞬间的数据，应该由 `GameSession.EndRun()` 统一收集并冻结在 `RunResult` 里。`ResultView` 是纯展示层，读快照比实时查场景对象更稳定。

**Q5：背包价值和金币有什么区别？**  
> 背包价值是携带物品的搜刮价值，金币是局内货币收入。它们都属于经济系统，但语义不同。后续最终评分可以把两者合成，但当前分别展示能让玩家看清收益来源。

**Q6：为什么第26课还要做合并升级收益？**  
> 第25课只是把当前 `ScoreValue / EffectValue` 显示出来。现在合并只提升 `Level`，价值和效果值还不会随等级变化。第26课要让合并真正有收益，避免“升级只改文字”。

## 七、习惯清单

1. 静态配置进运行时对象后，UI 和结算只读运行时对象。
2. 大物品占多格，价值按唯一物品算，不按格子算。
3. 新增字段要查双向链路：`LootEntry -> Item` 和 `Item -> LootEntry`。
4. UI 显示数据，不保存玩法状态，不反查配置表。
5. 背包总价值放数据层查询，多个表现层共享同一规则。
6. 结算页读 `RunResult` 快照，不实时查场景状态。
7. 纯展示 TMP / Image 继续关闭 Raycast Target。
8. 字段命名要稳定：`ScoreValue` 表示搜刮/结算价值，`EffectValue` 表示战斗效果。
9. Demo 冲刺期优先做玩家能看见的反馈，再补深层经济系统。

## 八、思考题（附复习参考）

**Q1：如果第26课要让 Lv.2 物品价值翻倍，应该直接改 ScoreValue 的 get 吗？**  
> 不建议直接把只读字段硬改成复杂公式。更稳的是先明确“基础价值”和“当前价值”的关系，例如保留 baseScoreValue，再提供 `CurrentScoreValue` 或让升级时更新运行时值。这样 UI 和结算读当前值，配置仍是初始值。

**Q2：如果后续金币也要进入最终评分，应该放在 BackpackValue 里吗？**  
> 不应该。金币和背包价值语义不同。可以在 `RunResult` 增加 `GoldEarned`，最终评分再单独计算 `FinalScore = BackpackValue + GoldEarned + CombatScore`，不要把所有东西提前塞进一个字段。

**Q3：如果背包里一个物品因为 bug 被同一实例放了两次，GetTotalScoreValue 会怎样？**  
> `GetUniqueItems()` 用 `HashSet<Item>` 去重，所以同一实例只会算一次。但这只能防止统计重复，不代表允许同一实例多处放置；根因仍应由 `Place()` 的 `Contains(item)` 守卫处理。

**Q4：如果 UI 显示价值正确但结算价值不对，排查顺序是什么？**  
> 先查 `InventoryGrid.GetTotalScoreValue()`，再查 `GameSession.EndRun()` 是否拿到 `InventorySystem`，再查 `RunResult.BackpackValue`，最后查 `ResultView` 是否显示了快照字段。

**Q5：为什么本课不直接做商店或出售？**  
> 商店会引入价格、购买、刷新、货币消耗、局内经济平衡。第25课的高性价比目标是先让玩家看见“物品有价值、背包有收益”，出售和商店放到 Demo 后或经济专题更稳。
