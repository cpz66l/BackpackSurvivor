## 一、这节课实现了什么

### 任务 1 · 新增 RunResult 结算快照

- 新增 `RunResult` 普通数据类，不继承 `MonoBehaviour`。
- 结算时记录 `FinalState / Elapsed / Level / TotalXp / KillCount`。
- ResultView 后续只读这个快照，不回头找一堆运行时系统。

### 任务 2 · GameSession 统一终局入口

- `Victory / Defeat` 不再各自散落处理，而是统一进入 `EndRun(finalState)`。
- `EndRun()` 负责切状态、暂停时间、生成 `RunResult`、广播 `OnRunEnded`。
- `GameSession` 订阅 `EnemyAI.OnEnemyDied` 统计本局击杀数。

### 任务 3 · ResultView 结算面板

- 新增 `ResultView`，订阅 `GameSession.OnRunEnded`。
- 结算时显示 ResultPanel，填充胜负标题、存活时间、等级、总经验、击杀数。
- ResultView 挂在常驻 Canvas 对象上，ResultPanel 只是它控制的显示面板。

### 任务 4 · 重开与退出按钮

- `RestartButton` 点击后先恢复 `Time.timeScale = 1f`，再重载当前场景。
- 使用 `SceneManager.GetActiveScene().buildIndex` + `SceneManager.LoadScene(buildIndex)` 完成 Demo 阶段最稳的清场。
- 额外接入 `QuitButton`，Build 中可退出游戏。

### 任务 5 · 王者式环形经验 HUD

- 原本的 `XP 文本 + Lv 文本` 升级为“外围经验圆环 + 中间等级数”。
- `RunHudView` 使用 `Image.fillAmount` 表示 `currentXp / xpToNextLevel`。
- 等级数字直接显示在圆环中心，减少 HUD 文字噪音。

### 任务 6 · 修复 HUD Slider 被移动键控制

- 发现 `HpSlider` 被 EventSystem 选中后，A/D 会调整 Slider 值。
- 将血条 Slider 设置为不可交互，Navigation 设为 None。
- 结论：纯 HUD 控件必须是显示器，不是玩家可操作控件。

## 二、最终代码（关键片段）

### RunResult：一份结算快照

```csharp
public class RunResult
{
    public GameState FinalState { get; }
    public float Elapsed { get; }
    public int Level { get; }
    public int TotalXp { get; }
    public int KillCount { get; }

    public RunResult(GameState finalState, float elapsed, int level, int totalXp, int killCount)
    {
        FinalState = finalState;
        Elapsed = elapsed;
        Level = level;
        TotalXp = totalXp;
        KillCount = killCount;
    }
}
```

`RunResult` 是数据包，不需要挂场景，不需要 `Awake / Update`。

### GameSession：订阅所有敌人的死亡广播

```csharp
private void OnEnable()
{
    if (playerHealth != null)
        playerHealth.OnDeath += HandlePlayerDeath;

    XpOrb.OnCollected += HandleXpCollected;

    if (inputReader != null)
        inputReader.OnPause += TogglePause;

    EnemyAI.OnEnemyDied += HandleEnemyDied;
}

private void OnDisable()
{
    if (playerHealth != null)
        playerHealth.OnDeath -= HandlePlayerDeath;

    XpOrb.OnCollected -= HandleXpCollected;

    if (inputReader != null)
        inputReader.OnPause -= TogglePause;

    EnemyAI.OnEnemyDied -= HandleEnemyDied;
    Time.timeScale = 1f;
}
```

`EnemyAI.OnEnemyDied` 是静态事件，所以 GameSession 不需要遍历场景里的所有敌人。任何敌人死亡时广播，GameSession 都能收到。

### GameSession：统一 EndRun

```csharp
private void EndRun(GameState finalState)
{
    if (state != GameState.Running) return;

    SetState(finalState);
    Time.timeScale = 0f;

    RunResult result = new RunResult(finalState, Elapsed, Level, TotalXp, killCount);
    OnRunEnded?.Invoke(result);
}
```

终局流程统一后，胜利和失败只差一个 `finalState`，不会出现胜利有结算、失败漏结算这种分叉 bug。

### ResultView：显示结算面板

```csharp
private void HandleRunEnded(RunResult runResult)
{
    panel.SetActive(true);

    if (runResult.FinalState == GameState.Victory)
    {
        titleText.text = "游戏胜利";
        titleText.color = victoryTitleColor;
    }
    else if (runResult.FinalState == GameState.Defeat)
    {
        titleText.text = "游戏失败";
        titleText.color = defeatTitleColor;
    }

    statsText.text =
        $"存活时间：{FormatTime(runResult.Elapsed)}\r\n" +
        $"等级：{runResult.Level}\r\n" +
        $"总经验：{runResult.TotalXp}\r\n" +
        $"击杀数：{runResult.KillCount}";
}
```

ResultView 是“木偶 UI”：只消费 `RunResult`，不自己判断胜负规则。

### ResultView：重开当前场景

```csharp
private void HandleRestartClicked()
{
    Time.timeScale = 1f;

    int buildIndex = SceneManager.GetActiveScene().buildIndex;
    SceneManager.LoadScene(buildIndex);
}
```

重开前必须恢复时间流速，否则下一局可能继承暂停状态。

### RunHudView：环形经验条

```csharp
private void HandleXpChanged(int totalXp, int level, int currentXp, int xpToNextLevel)
{
    float ratio = 0f;

    if (xpToNextLevel > 0)
        ratio = Mathf.Clamp01((float)currentXp / xpToNextLevel);

    if (xpLoop != null)
        xpLoop.fillAmount = ratio;

    levelText.text = level.ToString();
}
```

圆环显示的是“当前等级内进度”，所以使用 `currentXp / xpToNextLevel`，不是累计经验 `totalXp`。

## 三、周期链路

### 失败结算链路

```text
玩家 Health 归零
  ↓
Health.OnDeath
  ↓
GameSession.HandlePlayerDeath()
  ↓
EndRun(GameState.Defeat)
  ↓
SetState(Defeat) + Time.timeScale = 0
  ↓
生成 RunResult
  ↓
OnRunEnded(result)
  ↓
ResultView 显示失败结算
```

### 胜利结算链路

```text
RunTimer.Tick(Time.deltaTime)
  ↓
timer.IsFinished == true
  ↓
EndRun(GameState.Victory)
  ↓
SetState(Victory) + Time.timeScale = 0
  ↓
生成 RunResult
  ↓
ResultView 显示胜利结算
```

### 击杀统计链路

```text
任意 EnemyAI.Die()
  ↓
EnemyAI.OnEnemyDied?.Invoke()
  ↓
GameSession.HandleEnemyDied()
  ↓
state == Running 时 killCount++
  ↓
EndRun 时写入 RunResult.KillCount
```

### 重开链路

```text
点击 RestartButton
  ↓
ResultView.HandleRestartClicked()
  ↓
Time.timeScale = 1
  ↓
SceneManager.LoadScene(currentBuildIndex)
  ↓
场景重新加载，所有本局运行态清空
```

### 经验圆环链路

```text
拾取经验球
  ↓
GameSession.HandleXpCollected()
  ↓
LevelProgress.AddXp()
  ↓
OnXpChanged(totalXp, level, currentXp, xpToNextLevel)
  ↓
RunHudView 更新 xpLoop.fillAmount 与等级数字
```

## 四、设计思考

### 1. 为什么需要 RunResult？

结算面板要显示的是“本局结束那一刻的结果”。如果 ResultView 结算时再去问 GameSession、LevelProgress、EnemyAI、HUD，各系统就会耦在一起。

`RunResult` 把终局瞬间固化成一份快照。表现层只读快照，不关心数据是怎么来的。

### 2. 为什么 Victory / Defeat 要统一 EndRun？

胜利和失败都是“本局结束”。如果两条分支各自写逻辑，很容易出现一边暂停时间、一边没暂停；一边广播结算、一边漏广播。

统一 `EndRun(finalState)` 后，终局流程只有一份，差异只剩结果类型。

### 3. 为什么用 EnemyAI 静态事件统计击杀？

敌人是池化对象，场上敌人会不断生成和回收。GameSession 如果逐个订阅敌人实例，会被对象生命周期和池化复用拖复杂。

`EnemyAI.OnEnemyDied` 是类级广播口。任意敌人死亡都通过同一个口通知外部，GameSession 只订阅一次就能统计全局击杀。

### 4. 为什么重开用场景重载？

现在项目已经有敌人池、子弹池、掉落物、背包、经验、升级暂停、静态事件、HUD 状态。手写 `ResetAll()` 很容易漏一个状态。

Demo 冲刺期，场景重载是最稳的清场方案。它不最优雅，但非常可靠。

### 5. 为什么 ResultView 不能挂在 ResultPanel 上？

如果 ResultView 挂在 ResultPanel 自己身上，`Start()` 里 `panel.SetActive(false)` 会把 ResultView 也关掉，进而触发 `OnDisable()` 退订 `OnRunEnded`。

正确做法是：ResultView 挂在常驻 UI 根节点，ResultPanel 只是被它控制显示/隐藏的子面板。

### 6. 为什么经验圆环用 Image.fillAmount？

圆形经验条本质是一个 0~1 的比例显示。UGUI `Image` 的 Filled / Radial 360 正好表达这个比例，不需要额外写几何或材质逻辑。

这比 Slider 更适合做圆环，也更不容易被输入系统误操作。

### 7. 为什么血条 Slider 要禁用交互？

HUD 血条是显示器，不是玩家输入控件。UGUI Slider 默认可选中、可导航，EventSystem 会把 A/D 或方向键解释为调整 Slider。

所以显示用 Slider 要关 `Interactable`，Navigation 设为 None，避免 UI 抢走玩家移动输入。

## 五、踩坑记录

### 1. ResultView 挂在被隐藏面板上会退订事件

- **现象风险**：Play 后面板隐藏，但结算时面板不再出现。
- **原因**：`panel.SetActive(false)` 会让挂在面板上的 ResultView 一起 `OnDisable()`，从而退订 `OnRunEnded`。
- **处理**：ResultView 挂到常驻 Canvas/HUDRoot，ResultPanel 只作为被控制对象。
- **沉淀**：控制显隐的脚本不能挂在会被自己隐藏的对象上。

### 2. 标题颜色 alpha 为 0

- **现象**：结算标题已经赋值，但看起来不显示。
- **原因**：Inspector 颜色 alpha 为 0，文字完全透明。
- **处理**：Victory / Defeat 标题颜色 alpha 改为 1。
- **沉淀**：UI 看不见，先查 active，再查引用，接着查颜色 alpha。

### 3. 血条 Slider 被 A/D 控制

- **现象**：左右移动时，血条像被移动键操控。
- **原因**：HpSlider 是可交互 Selectable，EventSystem 会用 UI Move 输入控制它。
- **处理**：HpSlider 设置 `Interactable = false`，Navigation 设为 None。
- **沉淀**：纯 HUD 控件不要参与 EventSystem 导航。

### 4. 重开前必须恢复 timeScale

- **现象风险**：结算时 `Time.timeScale = 0`，如果直接重载场景，下一局可能继承暂停状态。
- **处理**：重开按钮先 `Time.timeScale = 1f`，再 `LoadScene()`。
- **沉淀**：凡是改过全局状态，离开当前流程前必须恢复。

## 六、面试问答

**Q1：RunResult 的作用是什么？**  
> 它是本局结束瞬间的数据快照，把胜负、存活时间、等级、总经验、击杀数一次性传给表现层，避免 ResultView 反向依赖多个运行时系统。

**Q2：为什么 RunResult 不继承 MonoBehaviour？**  
> 因为它不需要挂场景，也不需要 Unity 生命周期。它只是普通数据包，用构造函数填入数据即可。

**Q3：为什么胜利和失败都走 EndRun？**  
> 因为它们都是终局流程。统一入口可以保证暂停时间、切状态、生成结果、广播结算这几步一致，减少分支遗漏。

**Q4：为什么统计击杀用 EnemyAI.OnEnemyDied 静态事件？**  
> 敌人是池化生成的，逐个订阅实例会复杂且容易漏。静态事件提供全局死亡广播，GameSession 订阅一次即可统计所有敌人死亡。

**Q5：为什么重开不用手动 Reset 所有系统？**  
> 当前系统多且有对象池、静态事件、背包、HUD、升级暂停等状态。Demo 阶段场景重载更稳，能一次性清理绝大部分运行态。

**Q6：ResultView 为什么要挂在常驻对象上？**  
> 因为它需要一直订阅 GameSession 的结算事件。如果挂在会被隐藏的 ResultPanel 上，隐藏面板时脚本也会被禁用并退订事件。

**Q7：为什么经验圆环不用 Slider？**  
> Slider 是可交互控件，适合玩家拖动；经验圆环只是显示比例。`Image.fillAmount` 更简单、更贴合圆形进度条，也不容易被输入系统控制。

**Q8：HUD Slider 被键盘控制的根因是什么？**  
> UGUI Slider 是 Selectable，EventSystem 会把键盘 Move 输入用于 UI 导航和数值调整。显示用 Slider 必须关闭 Interactable 和 Navigation。

## 七、习惯清单

1. 终局流程用统一入口，不让 Victory / Defeat 各写一套。
2. 结算页读结果快照，不反查一堆运行时系统。
3. 静态事件适合做全局广播，但订阅/退订必须镜像。
4. 控制面板显隐的脚本不要挂在被自己隐藏的面板上。
5. 重开前恢复 `Time.timeScale`。
6. Demo 冲刺期优先选择稳定的场景重载，不手搓全系统 Reset。
7. 圆形进度优先用 `Image.fillAmount`，不是 Slider。
8. 纯 HUD 控件关闭 Interactable / Navigation / Raycast Target。

## 八、思考题（附复习参考）

**Q1：如果后续要加“本局获得金币”，应该放在哪里？**  
> GameSession 或专门的 RunStatsCollector 统计本局金币，终局时写入 RunResult。ResultView 只显示 RunResult，不自己查金币系统。

**Q2：如果以后要做局外主菜单，还应该继续 Load 当前场景吗？**  
> 可以改成 ResultView 提供两个按钮：重新开始当前关卡、返回主菜单。重开仍可 Load 当前 Run 场景，主菜单则 Load Menu 场景。

**Q3：如果要做无场景重载的“再来一局”，难点在哪里？**  
> 需要 Reset 敌人池、子弹池、掉落物、背包、经验、HUD、GameSession、静态事件残留和 TimeScale，漏一个就可能出现前一局状态污染。当前 Demo 阶段不值得冒这个风险。

**Q4：如果经验圆环升级时想做动画，应该在哪里做？**  
> 放在 RunHudView 或独立 LevelBadgeView。GameSession 仍然只广播数值变化，动画属于表现层，不要把动画时序塞进 LevelProgress。

**Q5：如果 Slider 又被键盘控制，排查顺序是什么？**  
> 先查 Slider 的 Interactable，再查 Navigation，再查 EventSystem 的当前选中对象，最后查 RaycastTarget 是否让 HUD 控件被点选。
