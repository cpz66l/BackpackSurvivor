# 第22课 · 内容面铺开

> 课程周期：2026-08-01  
> 前置：第21课《构筑最小兑现》  
> 关键词：LootEntry 源头数据、长期物品池、三类自动武器、FireRateBoost、EffectValue、TMP 中文字体

---

## 一、这节课实现了什么

第22课完成了 Demo 冲刺期的“内容面铺开”：不再只验证系统能跑，而是让玩家真的能捡到不同物品、看到不同武器、感到背包构筑开始有数值收益。

### 任务 1 · LootEntry 升级为背包物品源头数据

- `LootEntry` 不再只存 `id / rarity / width / height / weight`。
- 新增 `itemTag / connectableSides / scoreValue / effectValue`。
- 掉落表现在直接决定物品标签、邻接方向、结算价值和战斗效果数值。
- `Item` 同步保存 `ScoreValue / EffectValue`，避免运行时再用 `id` 写映射分支。

### 任务 2 · Item 与 LootEntry 往返保真

- `InventorySystem.CreateItemFromLootEntry()` 从 `LootEntry` 创建完整 `Item`。
- `InventorySystem.DiscardToWorld()` 将 `Item` 还原成 `LootEntry` 时保留新增字段。
- 拾取、入包、丢弃回世界走同一份物品定义，减少“捡进来是 A，丢出去变 B”的风险。

### 任务 3 · 定下 Demo 长期物品池

- 新增/整理普通、优秀、稀有、史诗、传说奖励表。
- 普通物品包含收集品、标准弹匣、制式手枪、急救绷带。
- 优秀/稀有物品开始出现改装手枪、突击步枪、霰弹枪、扩容弹匣、高速供弹模块等。
- 史诗/传说物品用于撑起宝箱期待和结算价值。
- GDD 已同步第22课定稿掉落表与价值设定。

### 任务 4 · 自动武器扩展到三类基础体验

- 场景中接入手枪、步枪、霰弹枪三类自动武器。
- `BackpackWeaponActivator.weaponSlots` 支持 `Pistol / Rifle / Shotgun / Pistol`。
- 第二个 `Pistol` 槽位继续服务 `DualWield`，步枪和霰弹枪用于拉开武器体验面。

### 任务 5 · FireRateBoost 接入真实战斗收益

- `AdjacencyRuleBook` 新增步枪/霰弹枪向下连接弹匣的 `FireRateBoost` 规则。
- `AdjacencyEffectResolver` 新增可堆叠的 FireRateBoost 分支。
- `BackpackWeaponActivator` 建立 `Item -> AutoWeapon` 映射，把邻接效果应用到具体激活武器。
- `AutoWeapon` 新增背包攻速倍率，并参与最终攻击间隔计算。
- 多个弹匣效果按 `EffectValue` 累加，最终倍率上限暂定 `1.75x`。

### 任务 6 · 修复 TMP 中文字体显示方块

- 替换旧的 `字魂醒狮体` 字体为 `SourceHanSansCN-Normal`。
- 场景、伤害数字 prefab、ItemView prefab 的 TMP 字体和材质引用已指向新 SDF。
- `TMP Settings.asset` 默认字体和 fallback 改为新字体。
- 新 SDF 开启 Dynamic Atlas、Multi Atlas，并关闭 Build 时清空动态数据。

第22课完成后，背包构筑已经有两条可演示收益：

```text
手枪 + 手枪左右相邻 = DualWield，突破默认武器上限
步枪/霰弹枪 + 弹匣上下相邻 = FireRateBoost，提高激活武器射速
```

## 二、最终代码（关键片段）

### 1. LootEntry 成为源头数据

```csharp
[Serializable] public class LootEntry
{
    public DropCategory category = DropCategory.Equipment;
    public string id;
    public GameObject dropPrefab;
    public Rarity rarity;
    public int weight;
    public int amount = 1;
    public int width = 1;
    public int height = 1;

    public ItemTag itemTag = ItemTag.None;
    public ConnectableSides connectableSides = ConnectableSides.None;
    public int scoreValue;
    public float effectValue;
}
```

这一刀的意义很大：物品定义从“代码猜测”变成“配置资产给答案”。  
以后新增物品，优先改表，而不是在运行时代码里继续堆 `if id == xxx`。

### 2. Item 保存评分和效果数值

```csharp
public int ScoreValue { get; }
public float EffectValue { get; }

public Item(
    string id,
    Rarity rarity,
    int width,
    int height,
    ItemTag itemTag,
    ConnectableSides connectableSides,
    int scoreValue,
    float effectValue)
{
    Id = id;
    baseWidth = width;
    baseHeight = height;
    Rarity = rarity;
    Tag = itemTag;
    LocalConnectableSides = connectableSides;
    ScoreValue = scoreValue;
    EffectValue = effectValue;
}
```

`ScoreValue` 先为结算页和搜刮价值服务，`EffectValue` 先为芯片收益服务。  
这两个字段都属于“物品身份的一部分”，所以应该跟着 `Item` 走，而不是散落在 UI 或战斗脚本里。

### 3. LootEntry → Item

```csharp
private Item CreateItemFromLootEntry(LootEntry entry)
{
    if (entry == null) return null;

    return new Item(
        entry.id,
        entry.rarity,
        entry.width,
        entry.height,
        entry.itemTag,
        entry.connectableSides,
        entry.scoreValue,
        entry.effectValue);
}
```

这一段是“入包入口”。  
凡是从掉落物进入背包的物品，都从 `LootEntry` 读完整字段。

### 4. Item → LootEntry

```csharp
LootEntry entry = new LootEntry
{
    category = DropCategory.Equipment,
    id = item.Id,
    rarity = item.Rarity,
    width = item.Width,
    height = item.Height,
    amount = 1,
    itemTag = item.Tag,
    connectableSides = item.LocalConnectableSides,
    scoreValue = item.ScoreValue,
    effectValue = item.EffectValue,
};
```

这一段是“丢弃入口”。  
新增字段必须往返保真，否则玩家丢出去再捡回来，物品可能丢标签、丢邻接方向、丢价值或丢芯片数值。

### 5. 新增 FireRateBoost 规则

```csharp
new AdjacencyRule(
    ItemTag.Rifle,
    ConnectableSides.Down,
    ItemTag.Magazine,
    ConnectableSides.Up,
    AdjacencyEffectId.FireRateBoost),

new AdjacencyRule(
    ItemTag.Shotgun,
    ConnectableSides.Down,
    ItemTag.Magazine,
    ConnectableSides.Up,
    AdjacencyEffectId.FireRateBoost)
```

这里没有写成“所有武器都能吃所有芯片”，而是继续遵守第14课定下的方向限制。  
背包构筑的关键不是物品挨着就行，而是“正确物品 + 正确方向 + 规则匹配”。

### 6. Resolver 区分互斥效果和可堆叠效果

```csharp
public static List<AdjacencyEffect> ResolveValidEffects(List<AdjacencyEffect> candidateEffects)
{
    List<AdjacencyEffect> validEffects = new List<AdjacencyEffect>();

    if (candidateEffects == null) return validEffects;

    AddValidDualWieldEffects(candidateEffects, validEffects);
    AddValidFireRateBoostEffects(candidateEffects, validEffects);

    return validEffects;
}
```

第21课 `DualWield` 是互斥效果，需要防三持。  
第22课 `FireRateBoost` 是可堆叠效果，可以直接加入有效效果列表。  
这就是 resolver 的价值：不同效果类型可以有不同结算策略。

### 7. Item 映射到具体 AutoWeapon

```csharp
private readonly Dictionary<Item, AutoWeapon> activeWeaponsByItem =
    new Dictionary<Item, AutoWeapon>();

private bool TryActivateItem(Item item)
{
    // 找到匹配 Tag 的空闲 WeaponSlot 后：
    weapon.WeaponObject.SetActive(true);
    activeWeaponItems.Add(item);

    AutoWeapon autoWeapon = weapon.WeaponObject.GetComponent<AutoWeapon>();
    if (autoWeapon != null)
        activeWeaponsByItem[item] = autoWeapon;

    return true;
}
```

第15课只需要知道哪些 `Item` 被激活，所以 `HashSet<Item>` 足够。  
第22课要把芯片效果应用到具体武器对象，所以必须多一张 `Item -> AutoWeapon` 映射表。

### 8. FireRateBoost 聚合和封顶

```csharp
float fireRateMultiplier = 1f + effectValues;
fireRateMultiplier = Mathf.Min(fireRateMultiplier, 1.75f);
autoWeapon.SetBackpackFireRateMultiplier(fireRateMultiplier);
```

`EffectValue` 使用加法累积，最终转成倍率。  
封顶的原因不是数学需要，而是 Demo 体验需要：允许玩家感到变强，但不允许一两个高值芯片把射速打爆。

### 9. AutoWeapon 消费背包攻速倍率

```csharp
float finalAttackInterval =
    attackInterval / (stats.FireRateMultiplier * backpackFireRateMultiplier);

public void SetBackpackFireRateMultiplier(float multiplier)
{
    backpackFireRateMultiplier = Mathf.Max(1f, multiplier);
}
```

这里保持了两个来源的清晰边界：

```text
PlayerRunStats.FireRateMultiplier = 升级系统给的本局成长
backpackFireRateMultiplier = 背包邻接给的构筑收益
```

它们最终一起影响开火间隔，但来源不会混在一起。

## 四、设计思考

### 1. 为什么 LootEntry 要成为源头，而不是代码里按 id 映射？

如果代码里写：

```text
id == "制式手枪" → Pistol
id == "标准弹匣" → Magazine
```

短期能跑，长期会变成一堆散落分支。新增物品时，要同时改掉落表、背包、邻接、评分、战斗，任何一处漏了都会出现物品信息不一致。

第22课把 `itemTag / connectableSides / scoreValue / effectValue` 放进 `LootEntry`，相当于把物品定义集中到配置资产里。运行时代码只负责搬运和消费，不负责猜测。

### 2. 为什么 Demo 冲刺期要先“铺内容面”？

到第21课，系统已经能证明“摆法影响战斗”。  
但给试玩者看的时候，只有一把手枪和一条双持，很容易被理解成小功能，而不是一个可扩展玩法。

第22课补的是展示面：

```text
不同稀有度
不同武器类型
不同物品价值
不同邻接收益
```

这比继续深挖一个复杂词缀系统更适合 8月15 Demo，因为面试官和试玩者会先感受到“游戏已经有内容层次”。

### 3. 为什么 FireRateBoost 可以堆叠，而 DualWield 不行？

`DualWield` 改变的是武器数量上限，天然需要互斥，否则三把手枪可能变成连锁三持。

`FireRateBoost` 改变的是某把已激活武器的数值，多个弹匣叠到同一把武器上是可以解释的。它的问题不是互斥，而是上限和平衡。

所以 resolver 不能写成“一个 Item 参与过任何效果就禁止再参与”。  
正确方向是：

```text
DualWield：按效果类型互斥
FireRateBoost：按目标武器聚合，数值封顶
```

### 4. 为什么 FireRateBoost 只作用于已激活武器？

如果一个没有被激活的步枪也能吃弹匣加成，那玩家看不到收益，也不知道这条效果有没有用。

本课选择只给已激活 `AutoWeapon` 应用倍率，优先保证反馈清晰：

```text
当前正在射击的武器
  +
背包里正确连接的芯片
  =
玩家肉眼能看到射速变化
```

Demo 阶段，能看出来比“理论上更完整”更重要。

### 5. 为什么需要 activeWeaponsByItem？

`ItemTag` 能告诉我们“这是什么类型”，但不能告诉我们“背包里这一件物品对应场景里的哪一个武器对象”。

第15课只做激活标记，用 `HashSet<Item>` 足够。  
第22课要对具体自动武器改倍率，所以必须记录：

```text
背包里的这个 Item
  ↔
场景里正在工作的这个 AutoWeapon
```

这就是 `activeWeaponsByItem` 的职责。

### 6. 为什么不让 prefab 自己找场景武器？

预制体资产不能稳定引用场景对象。  
如果用特殊名字 `GameObject.Find()`，短期能跑，但会把接线契约藏进字符串里：改名、复制场景、多人协作都容易炸。

本课继续把场景接线放在 `BackpackWeaponActivator.weaponSlots`，由场景级管理者维护“标签 → 武器对象”的关系。  
这是更清楚的依赖方向：资产描述物品，场景管理场景对象。

### 7. 为什么 TMP 中文问题要从字体资产事实源解决？

中文方块不是 UI 文本写错，而是 TMP Font Asset 缺字或引用错。  
只在单个 Text 上换字体，会留下其他 prefab 或 TMP 默认设置继续用旧字体。

所以这次修复不是“某个 Text 改一下”，而是：

```text
换源字体
换 SDF
换默认 TMP Settings
换场景和 prefab 引用
开动态补字
```

字体也有事实源。Demo 要可复现，就不能只靠本机临时字体状态。

## 五、踩坑记录

### 1. LootEntry 扩字段后，丢弃回世界也必须同步

- **现象风险**：物品捡进背包时有 Tag 和 EffectValue，但拖出背包再捡回来后丢失这些数据。
- **原因**：入包创建 `Item` 和丢弃还原 `LootEntry` 是两条方向相反的链路，新增字段必须两边都补。
- **沉淀**：凡是“数据往返”的系统，字段升级要检查正向和反向两条路。

### 2. 芯片有标签还不够，还必须有数值

- **现象**：规则能识别弹匣邻接，但无法体现“标准弹匣”和“高速供弹模块”的差异。
- **原因**：`ItemTag.Magazine` 只能表达类型，不能表达强度。
- **修复**：新增 `effectValue`，由配置表给每个芯片具体数值。
- **沉淀**：Tag 负责分类，Value 负责强度；两者不要混用。

### 3. 可堆叠效果必须有上限

- **现象风险**：多个高值芯片叠加后，武器射速可能过快，破坏 Demo 平衡和视觉可读性。
- **处理**：FireRateBoost 使用加法叠层，但最终倍率封顶 `1.75x`。
- **沉淀**：允许玩家变强，但要给数值系统装护栏。

### 4. 普通敌人掉落仍有测试开关

- **现状**：敌人掉落为了快速测试背包内容和高品质物品，仍可能保留偏高的稀有掉落概率。
- **处理方向**：第23课精英/宝箱节奏强化时，把普通怪回调为经验为主，优质装备交给精英、宝箱、终局压力。
- **沉淀**：测试配置可以存在，但提交前必须知道它是测试配置，不要误当正式经济。

### 5. TMP 中文方块要查字体资产链

- **现象**：中文不显示，显示方块。
- **排查路径**：查 TMP 字体引用、材质引用、TMP Settings 默认字体、SDF 是否动态、是否绑定源 TTF。
- **修复**：替换为 `SourceHanSansCN-Normal SDF`，统一场景和 prefab 引用，并设置 TMP 默认字体和 fallback。
- **沉淀**：字体问题不是“字写错”，而是资产链和 glyph 覆盖问题。

## 六、面试问答

**Q1：第22课你是怎么让掉落物支持更多玩法字段的？**  
> 我把 `LootEntry` 升级成背包物品的源头数据，新增 `itemTag / connectableSides / scoreValue / effectValue`。拾取时由 `LootEntry` 创建 `Item`，丢弃时再从 `Item` 还原 `LootEntry`，保证物品在掉落、背包、丢弃之间字段保真。

**Q2：为什么不用物品 id 在代码里映射标签和数值？**  
> 因为 id 映射会让物品定义散落在代码分支里，新增物品容易漏改。把标签、邻接方向、价值、效果数值放进配置资产后，运行时代码只消费数据，不猜数据，扩展成本更低。

**Q3：FireRateBoost 是怎么从背包布局影响自动武器的？**  
> 背包变化后，`InventoryGrid` 扫描邻接候选，`AdjacencyEffectResolver` 解析出有效 `FireRateBoost`，`BackpackWeaponActivator` 根据 `Item -> AutoWeapon` 映射找到已激活武器，读取相邻芯片的 `EffectValue`，累加后调用 `AutoWeapon.SetBackpackFireRateMultiplier()` 改变开火间隔。

**Q4：为什么 FireRateBoost 和 DualWield 的解析方式不同？**  
> DualWield 改变武器数量，需要防止同一个物品参与多组双持；FireRateBoost 是数值加成，可以对同一目标武器堆叠，但需要倍率上限。不同效果类型应该有不同结算策略，而不是用一个全局互斥规则套所有效果。

**Q5：为什么背包芯片只加成已激活武器？**  
> 因为 Demo 阶段要优先保证玩家能感知收益。未激活武器吃加成，玩家看不到实际效果；已激活武器吃加成，射速变化能立刻反馈给玩家。

**Q6：activeWeaponsByItem 解决了什么问题？**  
> 它把背包里的运行时 `Item` 实例映射到场景里的 `AutoWeapon` 组件。没有这张表，只知道物品标签，无法确定具体应该修改哪一个武器对象。

**Q7：为什么不建议 prefab 用 GameObject.Find 找场景武器？**  
> 因为那会把依赖藏在对象名字字符串里，改名或复制场景就可能失效。场景对象关系应该由场景级管理脚本显式接线，例如 `BackpackWeaponActivator.weaponSlots`。

**Q8：TMP 中文显示方块你怎么排查？**  
> 先确认 Text 内容没问题，再查 TMP Font Asset 是否包含中文字形、Text 是否引用旧字体/旧材质、TMP Settings 默认字体和 fallback 是否正确，最后确认 SDF 是否支持动态补字。第22课通过替换思源黑体 SDF 并统一引用解决。

## 七、习惯清单

1. 配置资产能表达的物品属性，不要写进运行时代码分支。
2. 新增物品字段时，同时检查入包和丢弃两条链路。
3. `Tag` 表示类别，`EffectValue` 表示强度，职责分清。
4. 候选邻接效果先进 resolver，真实有效效果再给 UI 和战斗消费。
5. 互斥效果和可堆叠效果分开处理，不要用一套规则硬套。
6. 可堆叠数值必须有上限，Demo 期尤其要防爆表。
7. prefab 不要依赖场景对象名字，场景依赖交给场景级管理器显式接线。
8. 字体资产要随项目提交：`.ttf / .meta / SDF.asset / TMP Settings` 都是可复现的一部分。
9. commit 前继续扫 `UnityEditor` / `ShadowCascadeGUI`，using 闸不能松。

## 八、思考题（附复习参考）

**Q1：如果后续要做 CritBoost，应该加在哪里？**  
> 先加 `AdjacencyEffectId.CritBoost` 和对应 `AdjacencyRule`，再在 resolver 中加单独解析分支。战斗消费侧不要直接写在 UI 里，而是像 FireRateBoost 一样由激活武器系统或武器属性系统读取有效效果。

**Q2：如果一把步枪周围连了三个弹匣，应该怎么限制收益？**  
> 可以继续允许候选都进入 validEffects，但在消费侧按目标武器聚合时限制最大层数或最大倍率。当前用倍率封顶 `1.75x`，未来也可以加“每把武器最多吃 N 个 Magazine”的规则。

**Q3：如果结算页要显示背包总价值，应该从哪里读？**  
> 从 `InventoryGrid.GetUniqueItems()` 取本局结束时背包里的唯一物品，再累加 `Item.ScoreValue`。ResultView 不应该自己扫描背包，最好由 GameSession 或 RunResult 生成结算快照。

**Q4：为什么同一个 Item 可以既参与 DualWield，又参与 FireRateBoost？**  
> 因为这两个效果的互斥规则不同。DualWield 是同类互斥，防三持；FireRateBoost 是数值堆叠。不能用“Item 已参与任何效果”作为全局排除条件，否则会扼杀后续构筑深度。

**Q5：如果中文在编辑器正常、Build 里又变方块，优先查什么？**  
> 查字体资产是否随项目提交，TMP Settings 默认字体/fallback 是否指向项目内 SDF，`m_ClearDynamicDataOnBuild` 是否导致动态字形被清空，以及 SDF 是否支持动态 atlas。不要只查场景里的单个 Text。
