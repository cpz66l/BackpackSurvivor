# 第27课 · 数值调参台与首轮平衡

> 课程周期：2026-08-04  
> 前置：第26课《合并升级收益兑现》  
> 关键词：首轮平衡、波次血量、伤害显示统一、攻速上限、宝箱距离提示、15分钟可玩验证

---

## 一、这节课实现了什么

第27课没有继续堆新系统，而是把第22到第26课累积出来的战斗、掉落、构筑和价值反馈压进一轮可玩的 15 分钟循环里。  
重点不是“调几个数字”，而是建立 Demo 期最重要的平衡闭环：玩家成长能爽，敌人成长能追，地图目标能被看见。

### 任务 1 · FireRateBoost 从超模边缘拉回可控区

- 弹夹类芯片的基础 `effectValue` 回调到更克制的数值。
- 当前配置基准：普通弹夹 10%，优秀弹夹 15%，稀有弹夹 20%。
- `Item.EffectValue` 不再简单等于 `baseEffectValue * Level`，而是通过等级倍率表计算。
- 当前等级倍率：Lv.1 = 1.0x，Lv.2 = 1.5x，Lv.3 = 2.0x。
- `BackpackWeaponActivator.maxBackpackFireRateMultiplier` 回调到 2.0x。

这样保留了“合并升级有收益”，但不让 Lv.2 / Lv.3 弹夹把攻速直接推到离谱区间。

### 任务 2 · 伤害显示与真实伤害统一

- `WeaponBase.Fire()` 在伤害源头把 `damage * stats.DamageMultiplier` 取整。
- 池化子弹和无池兜底子弹两条路径都使用同一个 `finalDamage`。
- `DamageNumberView.Play()` 使用 `Mathf.RoundToInt(damage)` 显示。
- 现在显示 25，就意味着传入子弹的真实伤害也是 25。

这一步修掉了第26课发现的“显示 25 但 50 血敌人要 3 枪”的认知问题。

### 任务 3 · 怪物血量随波次成长

- `WaveDirector.WaveStage` 新增 `normalEnemyMaxHp` 和 `eliteEnemyMaxHp`。
- `WaveDirector` 在阶段切换时把血量配置下发给 `EnemySpawner`。
- `EnemySpawner` 在生成普通/精英敌人时，调用 `Health.SetMaxHpAndReset()` 注入本波血量。
- 场景中使用直接血量而不是倍率，便于肉眼调参。

当前首轮基准：

```text
Wave 1：普通 40，精英 150
Wave 2：普通 65，精英 150
Wave 3：普通 90，精英 200
Wave 4：普通 130，精英 300
Wave 5：普通 160，精英 400
```

这让敌人质量能跟上玩家的武器、升级、合并和邻接成长。

### 任务 4 · 宝箱距离提示

- `LootChest` 增加静态未开启宝箱列表 `unopenedChests`。
- 宝箱出池时加入列表，打开或回池时移出列表。
- `LootChest.TryGetNearestUnopened()` 提供最近未开启宝箱查询。
- 新增 `ChestDistanceView`，在 HUD 上显示最近宝箱距离。
- 纯 HUD 文本关闭 `Raycast Target`，避免挡背包拖拽或其他 UI 输入。

最终取舍是“显示距离，不显示箭头”。  
这会给玩家目标感，但仍保留自己判断方向、绕路、取舍战斗和搜刮的空间。

### 任务 5 · 首轮 15 分钟试玩验证

用户实测一局，在运气不好、没拿到高强度 AK 的情况下，剩 3 分钟左右失败。  
关键体验结论：

- 不是一边倒的道德局，终局压力成立。
- 背包整理会发生在战斗空隙，不是摆设系统。
- 宝箱距离提示能引导玩家主动找宝箱。
- 构筑强弱差已经能被感知。
- 玩家自己愿意继续玩，说明第一轮可玩性成立。

这节课最重要的成果不是某个参数，而是项目第一次明确跨过了“功能原型”到“像游戏”的线。

## 二、最终代码（关键片段）

### 1. Item 的等级效果倍率

```csharp
public float EffectValue => baseEffectValue * GetLevelEffectMultiplier();

private float GetLevelEffectMultiplier()
{
    if (Level == 1) return 1f;
    if (Level == 2) return 1.5f;
    if (Level == 3) return 2f;
    return 1f;
}
```

这里故意不让 Lv.2 = 2 倍、Lv.3 = 3 倍。  
因为攻速是强体感属性，线性翻倍很容易变成“无脑合并”。

### 2. 攻速上限集中在背包武器激活器

```csharp
[SerializeField] private float maxBackpackFireRateMultiplier = 2f;

float fireRateMultiplier = 1f + effectValues;
fireRateMultiplier = Mathf.Min(fireRateMultiplier, maxBackpackFireRateMultiplier);
autoWeapon.SetBackpackFireRateMultiplier(fireRateMultiplier);
```

这让弹夹强度有两个调节点：

```text
单个芯片强度：LootEntry.effectValue
最终封顶强度：maxBackpackFireRateMultiplier
```

Demo 期先用这两个旋钮就够了，不急着做完整数值表工具。

### 3. 武器源头取整真实伤害

```csharp
float rawDamage = damage * stats.DamageMultiplier;
float finalDamage = Mathf.RoundToInt(rawDamage);

bullet.Initialize(
    projectileSpeed,
    finalDamage,
    targetFaction,
    maxDistance,
    direction,
    0f,
    gameObject);
```

取整放在 `WeaponBase`，而不是只放在显示层。  
这样 `Projectile`、`Health`、伤害数字看到的是同一份语义。

### 4. 伤害数字显示同样取整

```csharp
public void Play(float damage)
{
    if (damageText != null)
        damageText.text = Mathf.RoundToInt(damage).ToString();

    if (playRoutine != null)
        StopCoroutine(playRoutine);

    playRoutine = StartCoroutine(PlayRoutine());
}
```

显示层不再向上承诺，也不再和真实扣血走两套规则。

### 5. WaveStage 增加血量字段

```csharp
[Serializable]
public class WaveStage
{
    public float startTimeSeconds;
    public float spawnInterval;
    public int maxAlive;
    public string stageName;
    public Color displayColor;
    [Range(0f, 1f)] public float eliteSpawnChance;
    public int chestKillsToSpawn;
    public int chestMaxFieldCount;
    public ChestSpawner.ChestTierWeight[] chestTierWeights;
    public float normalEnemyMaxHp = 1f;
    public float eliteEnemyMaxHp = 1f;
}
```

波次现在不只调“数量”，也能调“质量”。

### 6. WaveDirector 下发敌人血量

```csharp
enemySpawner.ApplyWaveSettings(
    waveStages[i].spawnInterval,
    waveStages[i].maxAlive,
    waveStages[i].eliteSpawnChance,
    waveStages[i].normalEnemyMaxHp,
    waveStages[i].eliteEnemyMaxHp);
```

`WaveDirector` 仍然是导演，`EnemySpawner` 只是执行器。  
这保持了第18课确立的职责边界。

### 7. EnemySpawner 生成时注入本波血量

```csharp
if (selectedPool == normalEnemyPool)
{
    GameObject obj = selectedPool.Get(spawnPos);
    obj.GetComponent<Health>()?.SetMaxHpAndReset(normalEnemyMaxHp);
}
else if (selectedPool == eliteEnemyPool)
{
    GameObject obj = selectedPool.Get(spawnPos);
    obj.GetComponent<Health>()?.SetMaxHpAndReset(eliteEnemyMaxHp);
}
```

血量必须在对象出池后立刻重置。  
池化敌人的上一次生命值不能带到下一次出生。

### 8. Health 支持直接设置最大血量并回满

```csharp
public void SetMaxHpAndReset(float newMaxHp)
{
    if (newMaxHp <= 1f) return;
    maxHp = newMaxHp;
    currentHp = maxHp;
    OnHealthChanged?.Invoke(currentHp, maxHp);
}
```

这里选择直接血量，而不是倍率。  
原因是 Demo 调参时，策划视角更关心“这一波普通怪到底多少血”。

### 9. LootChest 维护未开启宝箱集合

```csharp
private static readonly List<LootChest> unopenedChests = new List<LootChest>();

public void OnGetFromPool()
{
    survivalTimer = 0f;
    opened = false;
    chestCollider.enabled = true;
    modelRb.material.color = originalColor;
    ActiveCount++;

    if (!unopenedChests.Contains(this))
        unopenedChests.Add(this);
}

public void OnReturnPool()
{
    ActiveCount--;
    unopenedChests.Remove(this);
}
```

这个列表只记录“能被玩家打开的宝箱”。  
打开后的残骸不再参与距离提示。

### 10. 查询最近未开启宝箱

```csharp
public static bool TryGetNearestUnopened(Vector3 from, out LootChest nearest)
{
    nearest = null;
    float sqrNearestDistance = float.MaxValue;

    if (unopenedChests != null && unopenedChests.Count != 0)
        foreach (var chest in unopenedChests)
        {
            if (chest == null) continue;
            if (chest.gameObject.activeInHierarchy == false) continue;

            float sqrDistance = (chest.transform.position - from).sqrMagnitude;
            if (sqrDistance < sqrNearestDistance)
            {
                sqrNearestDistance = sqrDistance;
                nearest = chest;
            }
        }

    return nearest != null;
}
```

距离比较用 `sqrMagnitude`，避免每个宝箱都做开方。  
当前宝箱数量不大，但这是应该养成的习惯。

### 11. ChestDistanceView 显示宝箱距离

```csharp
private void Awake()
{
    if (player == null)
        player = FindAnyObjectByType<PlayerController>()?.transform;
}

private void Update()
{
    if (player == null || chestDistanceText == null) return;

    if (LootChest.TryGetNearestUnopened(player.position, out LootChest nearestChest))
    {
        float distance = Vector3.Distance(player.position, nearestChest.transform.position);
        if (distance < hideDistance)
        {
            chestDistanceText.text = $"宝箱附近";
            return;
        }

        chestDistanceText.text = $"宝箱:{distance:F1}m";
    }
    else
    {
        chestDistanceText.text = "";
    }
}
```

表现层只负责读数据和显示文案。  
宝箱生命周期仍然由 `LootChest` 自己维护。

## 三、周期链路

### 玩家成长链路

```text
拾取武器 / 芯片 / 经验
  ↓
背包放置与合并升级
  ↓
Item.Level / EffectValue / DualWield / FireRateBoost
  ↓
BackpackWeaponActivator 刷新武器和攻速
  ↓
玩家清怪效率提高
```

### 敌人成长链路

```text
GameSession.Elapsed 增长
  ↓
WaveDirector 匹配当前 WaveStage
  ↓
EnemySpawner 接收 spawnInterval / maxAlive / eliteChance / enemyMaxHp
  ↓
新生成敌人 SetMaxHpAndReset()
  ↓
TTK 随波次拉长，终局压力增加
```

### 伤害显示链路

```text
WeaponBase.damage × PlayerRunStats.DamageMultiplier
  ↓
WeaponBase 源头 RoundToInt
  ↓
Projectile.Initialize(finalDamage)
  ↓
Health.TakeDamage(info.damage)
  ↓
DamageNumberView.RoundToInt(damage)
  ↓
显示值与真实扣血一致
```

### 宝箱目标链路

```text
ChestSpawner 生成宝箱
  ↓
LootChest.OnGetFromPool()
  ↓
加入 unopenedChests
  ↓
ChestDistanceView 每帧查询最近未开宝箱
  ↓
HUD 显示距离或“宝箱附近”
  ↓
玩家在战斗空隙主动寻找宝箱
```

### 首轮平衡验证链路

```text
调玩家收益
  ↓
调敌人血量和波次压力
  ↓
调宝箱品质和可达性
  ↓
完整试玩
  ↓
记录死亡时间、危险时间点、超模来源
  ↓
回调高杠杆参数
```

## 四、设计思考

### 1. 为什么这节课不做复杂调参台？

Demo 冲刺期的目标不是搭一个漂亮工具，而是让关键参数能快速被调到可玩。  
当前真正高杠杆的旋钮只有几类：

```text
玩家侧：伤害倍率、攻速芯片、攻速上限、合并收益
敌人侧：血量、刷怪间隔、场上上限、精英率
奖励侧：经验、金币、宝箱品质、物品价值
引导侧：宝箱可见性、HUD 提示
```

这些已经分布在 `WaveDirector`、掉落 SO、`BackpackWeaponActivator` 和场景组件里。  
所以这节课选择“集中可调入口 + 首轮试玩记录”，而不是新建一套重工具。

### 2. 为什么敌人血量用直接值，而不是倍率？

倍率对程序很舒服，但对平衡调试不够直观。  
例如：

```text
基础血量 40 × 1.75 = 70
基础血量 50 × 1.75 = 87.5
```

如果基础 prefab 被改了，所有波次都会跟着漂。  
直接写血量则更像策划表：

```text
第 1 波普通怪 40 血
第 3 波普通怪 90 血
第 5 波精英怪 400 血
```

当前阶段要的是“能凭感觉快速调”，直接血量更适合。

### 3. 为什么 Lv.2 攻速不是 2 倍？

因为攻速收益会改变单位时间内的子弹数量，体感非常强。  
如果 Lv.2 = 2 倍，Lv.3 = 3 倍，玩家很容易得出唯一正确答案：

```text
看到弹夹就合并
不合并就是亏
```

而现在 Lv.2 = 1.5 倍、Lv.3 = 2 倍，会保留选择空间：

```text
合并：单格收益更高，节省背包空间
不合并：多个低级件可能更容易形成多个邻接
```

这才是背包游戏想要的决策感。

### 4. 为什么伤害要在源头取整？

如果只在 UI 层取整，规则层还是浮点，就会出现“显示和真实不一致”。  
战斗游戏里，玩家对伤害数字非常敏感。  
一旦显示 25 但 50 血敌人两枪不死，玩家不会认为“浮点数四舍五入了”，玩家会认为系统不可信。

所以第27课把取整提前到 `WeaponBase`。  
显示层只是复述规则层，不再自己解释规则。

### 5. 为什么宝箱只显示距离，不做箭头？

箭头会把探索变成执行路线。  
距离提示则只告诉玩家：

```text
附近有没有目标？
大概还有多远？
值不值得绕过去？
```

玩家还需要自己判断方向、绕怪、卡时间、决定是否冒险。  
这比“箭头导航”更符合搜刮和幸存者的混合体验。

### 6. 为什么这次试玩反馈很关键？

用户在没拿到高强度 AK 的情况下，剩 3 分钟失败。  
这说明几件事同时成立：

```text
随机性会影响局势
终局压力不是摆设
失败不是开局注定
背包整理有真实价值
宝箱目标能影响路线
```

更重要的是，用户作为深度玩家，已经觉得“自己愿意玩”。  
这比功能清单全勾更重要，因为游戏最终卖的是体验，不是类图。

## 五、踩坑记录

### 1. 伤害显示不能只改显示层

- **现象风险**：UI 显示伤害和真实扣血不一致。
- **根因**：显示层单独取整，规则层仍然使用浮点。
- **修复**：在 `WeaponBase` 源头取整，并让 `DamageNumberView` 显示同一语义。
- **沉淀**：规则层决定事实，表现层只复述事实。

### 2. 敌人血量成长不能只靠数量堆压

- **现象风险**：后期玩家成长起来后，怪物数量再多也只是被快速清屏。
- **根因**：玩家有升级、合并、邻接三条成长线，敌人只有生成密度成长。
- **修复**：每个波次配置普通/精英直接最大血量。
- **沉淀**：幸存者类压力通常来自数量、质量和空间压迫三者共同增长。

### 3. Player 血量为 0 会让敌人“看起来不动”

- **现象**：敌人能刷新、能被攻击、能掉落，但不追玩家。
- **根因**：Player 的 `Health.maxHp` 在场景序列化中变成 0，导致玩家开局 `IsDead == true`；敌人 AI 判断目标死亡后不进入正常追击。
- **修复**：把 Player 的最大血量恢复到正常值，并确认 Health 初始化。
- **沉淀**：AI 不动不一定是 AI 坏了，先查目标是否有效、是否死亡、是否被注册。

### 4. 纯 HUD 文本也会吃射线

- **现象风险**：新增宝箱距离文本后，如果 TMP `Raycast Target` 开着，可能挡住背包拖拽或 UI 点击。
- **根因**：UGUI 文本默认也能参与 GraphicRaycaster。
- **修复**：`ChestDistanceText` 关闭 `Raycast Target`。
- **沉淀**：纯显示 UI 一律不进输入系统。

### 5. 调参不要一次动太多旋钮

- **现象风险**：一局变好或变坏，但不知道是哪项改动导致。
- **根因**：同时改血量、刷怪、伤害、掉落和经验，反馈无法归因。
- **修复**：优先只调高杠杆参数，并用完整试玩记录死亡时间和压力点。
- **沉淀**：平衡不是猜数字，是控制变量后的体验验证。

## 六、面试问答

**Q1：你怎么处理玩家成长导致后期碾压的问题？**  
> 我在 `WaveDirector.WaveStage` 中加入普通和精英敌人的直接最大血量配置，并在阶段切换时下发给 `EnemySpawner`。敌人出池后调用 `Health.SetMaxHpAndReset()`，保证每一波新生成敌人都按当前波次血量刷新。这样敌人不只增加数量，也增加质量。

**Q2：为什么使用直接血量，而不是血量倍率？**  
> Demo 调参阶段直接血量更直观。倍率会依赖 prefab 基础血量，如果基础值改动，所有波次都会漂；直接写“第几波多少血”更接近策划表，也更方便试玩后快速修正。

**Q3：你怎么修复伤害数字和真实伤害不一致？**  
> 我把伤害取整提前到 `WeaponBase.Fire()`，也就是生成子弹前就得到 `finalDamage`。之后 `Projectile`、`Health`、`DamageNumberView` 都使用这份伤害语义。表现层不再单独向上或向下解释规则。

**Q4：为什么 FireRateBoost 的 Lv.2 只给 1.5 倍效果？**  
> 攻速是强体感收益，线性翻倍容易让合并变成唯一正确选择。Lv.2 1.5 倍、Lv.3 2 倍能让合并有价值，但仍保留“不合并以形成多个邻接”这种背包决策空间。

**Q5：宝箱距离提示为什么不做箭头？**  
> 箭头会直接替玩家做路线决策，距离提示只提供目标感。玩家仍然要判断方向、敌群压力和是否绕路，这更符合搜刮和幸存者结合的玩法。

**Q6：这次首轮试玩为什么可以说明玩法成立？**  
> 因为玩家在运气不佳时不是开局崩盘，而是在剩 3 分钟失败；过程中还会主动利用战斗空隙整理背包、查看宝箱距离并改变路线。这说明战斗、背包、掉落、宝箱和波次压力已经形成闭环。

**Q7：如果后续继续平衡，你会优先看哪些指标？**  
> 我会先记录升级时间点、普通怪 TTK、精英怪 TTK、第一次危险时间点、死亡或通关时间、宝箱获取数量，以及玩家是否被迫整理背包。它们比单个数值更能反映体验。

## 七、习惯清单

1. 调参先找高杠杆旋钮，不要急着做复杂工具。
2. 玩家成长和敌人成长要成对设计。
3. 攻速、暴击、范围这类强体感属性不要线性堆太猛。
4. 显示数字必须和真实规则语义一致。
5. 池化敌人出池后要重置本轮最大血量和当前血量。
6. 波次导演负责决策，刷怪器负责执行。
7. 纯 HUD 文本关闭 `Raycast Target`。
8. 目标提示优先给信息，不要替玩家做全部决策。
9. 平衡验证要记录死亡时间、危险点和超模来源。
10. 试玩时玩家“愿意继续玩”是非常重要的正反馈。

## 八、思考题（附复习参考）

**Q1：如果后期仍然太简单，你第一优先调什么？**  
> 先调终局波次的普通怪血量、精英血量、精英率和场上上限。不要第一时间削玩家，因为玩家成长是构筑爽点；先确认敌人成长是否追上了玩家成长。

**Q2：如果前期太难，应该先降怪物血量还是降刷怪数量？**  
> 看玩家的死亡方式。如果是单只怪太硬，降前两波血量；如果是被围住没空间，降刷怪频率或场上上限。平衡要根据压力来源下刀。

**Q3：为什么攻速上限不能太低？**  
> 上限太低会让不同等级弹夹、多个邻接芯片都撞到同一个天花板，玩家感觉“配了也没用”。上限要限制超模，但不能压扁构筑差异。

**Q4：如果以后要做真正的调参台，应该从哪里开始？**  
> 先把 `WaveStage`、经验曲线、金币掉落、芯片强度和宝箱权重集中成 ScriptableObject 配置，并给每类参数加说明。不要一开始做编辑器工具，先让数据结构稳定。

**Q5：宝箱距离提示如果太强，怎么削弱而不是删除？**  
> 可以只在一定范围内显示、只显示大致距离区间、提高刷新间隔，或在战斗中隐藏。这样保留目标感，但降低精确导航能力。

**Q6：为什么“剩 3 分钟失败”是一个好信号？**  
> 它说明玩家能进入终局，说明前中期没有崩；但最终仍然会因为构筑、运气或操作失败，说明终局有压力。对 Demo 来说，这比稳定无脑通关更有记忆点。

## 九、下一步

**第28课：新手目标提示与局内可读性。**

第27课已经证明 15 分钟循环初步可玩。下一课不急着加新战斗系统，而是让第一次打开游戏的人更容易理解当前目标和局内信息：

- 开局轻提示：移动、拾取、背包、宝箱、升级。
- 当前目标提示：活下去、找宝箱、整理背包、提升火力。
- 背包相关提示：背包满、可合并、可邻接、高价值物品。
- 升级选择文案再打磨，让选项更像游戏奖励而不是调试文本。
- 所有提示都要轻，不挡战斗，不吃射线，不破坏 Demo 节奏。
