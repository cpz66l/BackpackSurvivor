> 前置：第22课《内容面铺开》  
> 关键词：精英怪、宝箱品质曲线、终局压力、掉落经济、GLB 闪白修复、WaveDirector

## 一、这节课实现了什么

第23课完成了 15 分钟 Demo 节奏层的关键补强：不再只是“怪越来越多”，而是让普通怪、精英怪、宝箱和终局阶段各自承担明确职责。

### 任务 1 · 普通敌人与精英敌人分池生成

- `EnemySpawner` 从单一 `enemyPool` 改成 `normalEnemyPool / eliteEnemyPool`。
- 新增 `eliteSpawnChance`，由波次阶段动态控制精英出现概率。
- `PickEnemyPool()` 使用 `Random.value` 做 0~1 浮点掷骰。
- 修正了 `Random.Range(0, 1)` 整数重载上限排他的隐患：它只会返回 0，导致概率判断失真。

### 任务 2 · 精英敌人资源与掉落职责落地

- 新增 `NormalEnemy.prefab` 与 `EliteEnemy.prefab`，场景中分别接入普通/精英对象池。
- 精英敌人拥有更高血量、不同外观和独立掉落表。
- 普通敌人掉落从测试期高品质掉落回调为经验为主。
- 精英敌人承担优秀/稀有装备入口，宝箱承担更高期待的奖励入口。

### 任务 3 · GLB 新模型受击反馈修复

- 新模型导入后，旧的 `renderer.material.color` 闪白方式不再可靠。
- 事件链路确认正常：`Health.OnDamaged -> DamageFlashView.HandleDamaged` 能触发。
- 最终改为临时替换 `flashMaterial`，再恢复原始 `sharedMaterials`。
- `OnDisable()` 恢复材质，避免池化对象带着闪白材质回池。

### 任务 4 · 宝箱节奏接入 15 分钟波次

- `ChestSpawner` 新增 `ApplyWaveSettings()`。
- `WaveDirector.WaveStage` 新增：
  - `chestKillsToSpawn`
  - `chestMaxFieldCount`
  - `chestTierWeights`
- 宝箱仍由击杀触发，但每个阶段可以改变“多久出箱、场上最多几个箱、出什么品质箱”。

### 任务 5 · 终局高压精英潮

当前波次节奏采用“前期发育、后期考试”的曲线：

| 时间 | 阶段名 | 刷怪间隔 | 场上上限 | 精英率 | 宝箱击杀间隔 | 宝箱上限 |
|---:|---|---:|---:|---:|---:|---:|
| 0s | 洒洒水 | 2.0 | 8 | 0% | 10 | 2 |
| 180s | 简单 | 1.5 | 15 | 5% | 15 | 2 |
| 360s | 普通 | 0.6 | 20 | 10% | 25 | 3 |
| 600s | 上压力 | 0.3 | 25 | 20% | 30 | 4 |
| 780s | 终局 | 0.1 | 35 | 30% | 35 | 5 |

这套节奏的设计意图是：前期多给宝箱帮助构筑成型，中后期减少奖励频率，用敌人密度和精英比例检验玩家构筑。

### 任务 6 · 宝箱品质随波次提升

原本宝箱品质权重固定，即使终局也难刷到高品质宝箱。  
本课把宝箱品质权重交给 `WaveDirector`，让后期高品质宝箱概率自然提高。

当前品质曲线：

| 阶段 | 普通 | 不普通 | 稀有 | 史诗 |
|---|---:|---:|---:|---:|
| 洒洒水 | 80 | 20 | 0 | 0 |
| 简单 | 65 | 30 | 5 | 0 |
| 普通 | 45 | 40 | 15 | 0 |
| 上压力 | 25 | 45 | 25 | 5 |
| 终局 | 10 | 35 | 40 | 15 |

这样终局不只是更危险，也更有奖励期待。

## 二、最终代码（关键片段）

### 1. EnemySpawner 分池生成

```csharp
[SerializeField] private ObjectPool normalEnemyPool;
[SerializeField] private ObjectPool eliteEnemyPool;
[SerializeField, Range(0f, 1f)] private float eliteSpawnChance;

private ObjectPool PickEnemyPool()
{
    if (eliteEnemyPool == null) return normalEnemyPool;

    float randomValue = Random.value;
    if (randomValue < eliteSpawnChance)
        return eliteEnemyPool;

    return normalEnemyPool;
}
```

精英不是特殊分支硬刷，而是普通刷怪器的一种池选择结果。  
这样 `EnemySpawner` 仍然只负责“生成敌人”，不会变成波次导演。

### 2. WaveStage 承载敌人和宝箱节奏

```csharp
[Serializable]
public class WaveStage
{
    public float startTimeSeconds;
    public float spawnInterval;
    public int maxAlive;
    public string stageName;
    public Color displayColor;

    [Range(0f, 1f)] public float eliteSpawnChance;

    public int chestKillsToSpawn;
    public int chestMaxFieldCount;
    public ChestSpawner.ChestTierWeight[] chestTierWeights;
}
```

波次阶段现在不只调刷怪压力，也调奖励节奏。  
这是“导演层”的职责：在正确时间告诉执行器该变成什么状态。

### 3. WaveDirector 下发设置

```csharp
if (enemySpawner != null)
    enemySpawner.ApplyWaveSettings(
        waveStages[i].spawnInterval,
        waveStages[i].maxAlive,
        waveStages[i].eliteSpawnChance);

if (chestSpawner != null)
    chestSpawner.ApplyWaveSettings(
        waveStages[i].chestKillsToSpawn,
        waveStages[i].chestMaxFieldCount,
        waveStages[i].chestTierWeights);
```

`WaveDirector` 不直接生成敌人或宝箱，只在阶段切换时下发参数。  
这样执行器的逻辑保持简单，阶段配置也集中在 Inspector。

### 4. ChestSpawner 的阶段权重覆盖

```csharp
[Serializable]
public class ChestTierWeight
{
    public string chestName;
    public int weight;
}

private ChestTierWeight[] currentTierWeights;

public void ApplyWaveSettings(
    int killsToSpawn,
    int maxFieldCount,
    ChestTierWeight[] currentTierWeights)
{
    this.killsToSpawn = Mathf.Max(1, killsToSpawn);
    this.maxFieldCount = Mathf.Max(1, maxFieldCount);
    this.currentTierWeights = currentTierWeights;
}
```

`ChestTier.weight` 是默认权重，`currentTierWeights` 是当前波次覆盖权重。  
默认值保留，是为了防止某个阶段漏填配置时宝箱直接消失。

### 5. 宝箱权重单一规则源

```csharp
private int GetWeightForTier(ChestTier tier)
{
    if (tier == null) return 0;

    if (currentTierWeights != null)
    {
        foreach (var tierWeight in currentTierWeights)
        {
            if (tierWeight == null) continue;
            if (tierWeight.chestName == tier.chestName)
                return Mathf.Max(0, tierWeight.weight);
        }
    }

    return Mathf.Max(0, tier.weight);
}
```

这段是本课最后验收的关键。  
总权重计算和抽中返回都必须调用同一个函数，否则会出现“第一轮算进去了，第二轮找不到”的隐性 bug。

### 6. PickByWeight 两轮都走同一规则

```csharp
private ChestTier PickByWeight(ChestTier[] tiers)
{
    int total = 0;
    foreach (var t in tiers)
    {
        int weight = GetWeightForTier(t);
        if (weight <= 0) continue;
        total += weight;
    }

    if (total <= 0) return null;

    int roll = UnityEngine.Random.Range(0, total);
    int accum = 0;
    foreach (var t in tiers)
    {
        int weight = GetWeightForTier(t);
        if (weight <= 0) continue;

        accum += weight;
        if (roll < accum)
            return t;
    }

    return null;
}
```

随机表要特别怕“双规则”。  
一旦总权重和命中权重不是同一套逻辑，概率 bug 会很难靠肉眼发现。

### 7. DamageFlashView 改为材质替换

```csharp
private void ApplyFlashMaterial()
{
    if (flashMaterial == null) return;

    for (int i = 0; i < renderers.Length; i++)
    {
        Renderer renderer = renderers[i];
        if (renderer == null) continue;

        Material[] flashMaterials = new Material[renderer.sharedMaterials.Length];
        for (int j = 0; j < flashMaterials.Length; j++)
            flashMaterials[j] = flashMaterial;

        renderer.sharedMaterials = flashMaterials;
    }
}

private void RestoreMaterials()
{
    if (renderers == null || originalMaterials == null) return;

    for (int i = 0; i < renderers.Length; i++)
    {
        if (renderers[i] == null) continue;
        if (originalMaterials[i] == null) continue;
        renderers[i].sharedMaterials = originalMaterials[i];
    }
}
```

这个方案比改颜色更粗暴，但对 Demo 更稳：不同模型、不同材质、不同 Shader 都能看到明显闪白。

## 三、周期链路

### 精英生成链路

```text
GameSession.Running
  ↓
WaveDirector 读取 Elapsed
  ↓
进入新的 WaveStage
  ↓
EnemySpawner.ApplyWaveSettings(spawnInterval, maxAlive, eliteSpawnChance)
  ↓
EnemySpawner 到时间尝试生成
  ↓
PickEnemyPool()
  ↓
normalEnemyPool / eliteEnemyPool
  ↓
敌人出场并进入追击/攻击/死亡流程
```

### 宝箱节奏链路

```text
WaveDirector 阶段切换
  ↓
ChestSpawner.ApplyWaveSettings(killsToSpawn, maxFieldCount, chestTierWeights)
  ↓
EnemyAI.OnEnemyDied
  ↓
ChestSpawner.AddKillsCount()
  ↓
killsCount 达标
  ↓
TryFindSpawnPoint()
  ↓
PickByWeight()
  ↓
LootChest.Initialize(chestName, color, bundle)
```

### 宝箱品质曲线链路

```text
ChestSpawner.tiers 默认品质表
  ↓
WaveStage.chestTierWeights 当前阶段覆盖
  ↓
GetWeightForTier()
  ↓
优先阶段权重，缺失则回退默认权重
  ↓
PickByWeight 两轮统一使用
  ↓
阶段越靠后，高品质宝箱概率越高
```

### GLB 受击闪白链路

```text
Health.TakeDamage()
  ↓
OnDamaged
  ↓
DamageFlashView.HandleDamaged()
  ↓
停止旧协程，启动新 FlashRoutine
  ↓
ApplyFlashMaterial()
  ↓
等待 flashDuration
  ↓
RestoreMaterials()
  ↓
OnDisable 再兜底恢复，防池化残留
```

## 四、设计思考

### 1. 为什么普通怪不能高概率掉好东西？

普通怪是节奏底盘，主要职责是制造经验成长和基础战斗密度。  
如果普通怪频繁掉稀有装备，精英和宝箱就失去奖励职责，玩家也不会期待“打精英”和“开箱”。

第23课把奖励职责拆成：

```text
普通怪：经验为主，低概率小掉落
精英怪：优秀/稀有装备入口
宝箱：更高品质和惊喜入口
终局：高压力 + 高品质期待
```

这比单纯提高掉率更像游戏经济。

### 2. 为什么不急着做 Boss？

Boss 很诱人，但成本不只是一个模型和血条。  
Boss 要有技能、读招、攻击判定、演出、奖励和失败反馈，否则只是大号怪。

在 8月15 Demo 冲刺期，更高性价比的是终局精英潮：

```text
复用现有敌人池
复用现有波次系统
复用现有 HUD 波次提示
复用现有掉落系统
```

它能稳定制造最后两分钟的压力，而且风险可控。

### 3. 为什么宝箱品质要交给 WaveDirector？

`ChestSpawner` 只应该知道怎么生成宝箱，不应该知道“第几分钟该出什么品质”。  
时间节奏、压力曲线、奖励曲线都属于导演层。

所以正确方向是：

```text
WaveDirector：什么时候、什么强度、什么奖励倾向
ChestSpawner：按当前参数计数、选点、抽品质、生成宝箱
```

这能避免执行器里长出一堆时间判断。

### 4. 为什么阶段权重要有默认回退？

数据驱动系统最怕配置漏填。  
如果某个阶段忘写“史诗宝箱”，系统不应该直接炸，也不应该让抽表概率失真。

所以 `GetWeightForTier()` 的顺序是：

```text
当前阶段有同名权重 → 用阶段权重
当前阶段没写 → 回退 ChestTier 默认权重
权重为负 → 归零
宝箱项为空 → 归零
```

这就是配置系统的护栏。

### 5. 为什么 GLB 闪白用换材质，而不是继续改颜色？

改颜色依赖材质支持 `_Color` 或 `_BaseColor`，还要考虑 Shader、实例材质和渲染管线差异。  
新导入 GLB 后，事件链路是通的，但视觉不生效，说明问题在材质表现层。

Demo 阶段用临时白色材质替换更直接：

```text
不关心原 Shader 怎么写
不关心原材质颜色属性名
不关心模型有几个材质槽
```

代价是要认真缓存和恢复 `sharedMaterials`，尤其池化对象禁用时必须还原。

## 五、踩坑记录

### 1. Random.Range 整数重载上限排他

- **现象风险**：`Random.Range(0, 1)` 看起来像 0~1，实际整数重载只会返回 0。
- **根因**：Unity 的 `Random.Range(int, int)` 上限是 exclusive。
- **修复**：精英概率掷骰使用 `Random.value`。
- **沉淀**：概率判断优先用 `Random.value`；整数 Range 只适合离散索引。

### 2. 新模型受击事件正常，但视觉不闪

- **现象**：敌人受击仍扣血、伤害数字正常，但白光反馈消失。
- **排查**：先验证 `Health.OnDamaged` 和 `DamageFlashView.HandleDamaged` 是否触发，再查 Renderer/Material。
- **根因**：GLB 模型材质路径不吃旧的 `renderer.material.color` 闪色方案。
- **修复**：改为临时替换 `flashMaterial`，结束和禁用时恢复原材质。
- **沉淀**：视觉 bug 先分清“事件没来”还是“表现方式不生效”。

### 3. 只改宝箱生成频率，不改品质权重是不完整的

- **现象**：终局宝箱仍按固定 `普通/不普通/稀有` 权重抽，高品质箱难出现。
- **根因**：波次只控制 `killsToSpawn / maxFieldCount`，没有控制品质分布。
- **修复**：给 `WaveStage` 增加 `chestTierWeights`。
- **沉淀**：奖励节奏有两层：出现频率和品质分布；只调一层会偏。

### 4. 随机权重表必须避免双规则

- **现象风险**：总权重计算使用阶段权重+默认回退，但第二轮返回仍只查阶段权重，导致 roll 落到回退权重区间时返回 null。
- **根因**：两轮循环各写一套规则。
- **修复**：抽出 `GetWeightForTier()`，总权重和命中返回都调用同一函数。
- **沉淀**：权重随机表必须“算总数”和“找命中”共用同一个取权重函数。

### 5. using 闸继续有效

- **现象风险**：`using static` 很容易把不必要依赖带进运行时代码，之前已经有 UnityEditor using 事故。
- **处理**：本课最终清掉无意义的 `using static BS.GamePlay.Waves.WaveDirector`，并继续扫 `UnityEditor / ShadowCascadeGUI`。
- **沉淀**：commit 前扫 using 不是形式主义，是打包稳定性的闸门。

## 六、面试问答

**Q1：你这节课怎么实现精英怪按波次出现？**  
> 我把 `EnemySpawner` 从单一敌人池改成普通/精英两个对象池，并增加 `eliteSpawnChance`。`WaveDirector` 在阶段切换时下发精英概率，`EnemySpawner` 生成时用 `Random.value` 选择普通池或精英池。

**Q2：为什么不用 if 时间判断直接写在 EnemySpawner 里？**  
> 因为 `EnemySpawner` 是执行器，只负责生成敌人；时间阶段属于 `WaveDirector` 的职责。把节奏放在导演层，可以让刷怪、宝箱、HUD 都读同一份阶段配置。

**Q3：普通怪、精英怪、宝箱的奖励职责怎么划分？**  
> 普通怪负责经验和基础小掉落，精英怪负责更高质量装备入口，宝箱负责高期待奖励和后期品质提升。这样玩家才会形成“清怪成长、打精英期待、开箱惊喜”的节奏。

**Q4：为什么要让宝箱品质随波次变化？**  
> 只让宝箱变多或变少，不能解决后期奖励期待问题。终局阶段如果仍按固定品质权重抽，玩家很难刷到高级箱。按波次调整 `chestTierWeights`，能让后期风险和收益一起提高。

**Q5：你怎么保证宝箱权重配置漏填时不炸？**  
> `GetWeightForTier()` 会先查当前阶段是否有同名覆盖权重，找不到就回退到 `ChestTier.weight` 默认权重；空项和负数都归零。这样配置漏填不会直接破坏抽表。

**Q6：为什么权重表要抽出 GetWeightForTier？**  
> 权重随机有两轮：第一轮算总权重，第二轮根据 roll 找命中。如果两轮取权重逻辑不一致，就会出现概率错误或返回 null。抽成一个函数能保证单一规则源。

**Q7：GLB 模型受击白光为什么会失效？**  
> 事件链路没断，问题在材质表现。旧方案改 `material.color` 依赖材质和 Shader 支持对应颜色属性，新 GLB 材质不一定吃这套。改用临时替换闪白材质后，对不同模型更稳定。

**Q8：为什么终局阶段先做精英潮而不是 Boss？**  
> Demo 冲刺期优先完整和稳定。Boss 需要技能、读招、演出、奖励和失败反馈，成本较高；精英潮能复用已有敌人池、波次、掉落和 HUD，性价比更高。

## 七、习惯清单

1. 概率掷骰优先用 `Random.value`，整数 `Random.Range` 注意上限排他。
2. 导演层管节奏，执行器管执行；不要让 Spawner 自己判断第几分钟。
3. 奖励系统同时看“出现频率”和“品质分布”，不要只调一个。
4. 权重随机表的总权重和命中返回必须走同一个取权重函数。
5. 数据配置要有默认回退，漏填不能直接炸。
6. 池化对象做临时视觉覆盖时，`OnDisable()` 必须恢复状态。
7. 视觉反馈失效先拆成“事件没触发”还是“材质/渲染没表现”。
8. commit 前继续扫 `UnityEditor` / `ShadowCascadeGUI` / 无意义 `using static`。
9. Demo 冲刺期优先做可见体验闭环，不轻易开大系统。

## 八、思考题（附复习参考）

**Q1：如果后续想做“精英词缀”，应该放在哪一层？**  
> 词缀配置应该放在数据层或敌人配置层，生成时由 `EnemySpawner` 或专门的初始化器应用到敌人实例。`EnemyAI` 不应该硬写“如果是火焰精英就怎样”，否则敌人脚本会越来越胖。

**Q2：如果某个阶段想完全不刷宝箱，现在代码支持吗？**  
> 不完全支持。`ApplyWaveSettings()` 会把 `maxFieldCount` 和 `killsToSpawn` 钳到至少 1。若要阶段性禁用宝箱，建议新增 `chestEnabled`，而不是用 0 偷偷表达禁用。

**Q3：如果终局太难，优先调哪些值？**  
> 先调 `eliteSpawnChance` 和 `maxAlive`，再调 `spawnInterval`。`spawnInterval = 0.1` 会很快把场上敌人顶满，体感变化很猛。调参课可以用集中配置表观察这些值。

**Q4：如果玩家后期还是太强，是否应该直接削武器？**  
> 不急。先区分强在哪里：伤害过高、射速过高、回血太多、敌人血量太低、敌人追击压力不足，还是奖励太肥。第24课要做的是集中调参和首轮平衡，不是凭感觉乱削。

**Q5：为什么宝箱品质权重用 chestName 匹配，而不是数组下标？**  
> 下标匹配依赖两个数组顺序永远一致，Inspector 里很容易拖错或漏项。名字匹配更直观，也支持漏填后回退默认权重。
