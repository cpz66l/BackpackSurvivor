# V0.3 开发计划：内容深度与长期留存

> 项目：《背包幸存者》Backpack Survivor  
> 前置版本：V0.2 Windows Playable Demo  
> 阶段目标：在不推倒 V0.2 架构的前提下，补充内容深度、战斗变化、音频包装、敌人行为、Boss 压力和局外留存记录。  
> 核心原则：先扩可见内容，再扩底层规则；先服务可玩性，再考虑大规模数据化。

---

## 一、V0.3 版本定位

V0.2 已经完成“能玩、能打包、能展示”的目标。V0.3 不应该重新造底层，而应该围绕一个问题推进：

> 玩家多玩几局时，是否每局都有更多选择、更强反馈、更明确目标和更高追求？

因此 V0.3 的重心不是继续堆 UI，而是补四类深度：

```text
内容深度：更多升级选项、更多物品、更多邻接效果
战斗深度：敌人移动更稳、Boss 形成阶段压力
反馈深度：基础音效补齐、背景音乐和音量控制
留存深度：记录最高分、最高价值、摸出金色物品数量等长期成果
```

---

## 二、V0.3 Definition of Done

V0.3 建议验收标准：

- 三选一升级池从 3 个扩展到 **12 个以上**，覆盖攻击、生存、机动、搜刮、经济等方向。
- 新增 **3~5 个真实生效的邻接效果**，并能在 Tooltip 或 HUD 中解释收益。
- 新增一批 Demo 可见内容：至少 **2 类新芯片 / 1 类新武器或武器变体 / 若干高价值收集品**。
- 建立基础音频架构：SFX 不再只靠单个 `SfxPlayer` 堆字段，支持 BGM、音量分类和统一播放入口。
- 敌人移动从“全员直线追玩家”升级为更稳定的追击方案，减少挤成一团、卡住和抖动。
- 实现一个基础 Boss：出场、血条、阶段技能、死亡奖励、终局压力和音效反馈。
- 实现本地存档：最高分、最高金币、最高背包价值、最大存活时间、累计摸出金色物品数量。
- 完成 V0.3 Build 和 Release，README 更新版本说明。

## 三、总架构原则

### 1. 不重写 V0.2 主干

V0.2 已经验证的主链路继续保留：

```text
GameSession / RunTimer / RunResult
WaveDirector / EnemySpawner
InventoryGrid / AdjacencyRuleBook / AdjacencyEffectResolver
BackpackWeaponActivator / WeaponBase
RunHudView / ResultView / MainMenuController
```

V0.3 的正确做法是“加适配层和数据层”，不是把这些主干推倒。

### 2. 先扩枚举，再评估数据化

升级选项和邻接效果一开始可以继续用 enum 扩展，等数量超过可维护阈值后再完整 ScriptableObject 数据化。

推荐节奏：

```text
3~12 个选项：enum + 生成器表足够
12~20 个选项：开始抽 OptionDefinition / EffectDefinition
20+ 个选项：必须数据化，否则代码表会变成内容编辑器
```

### 3. 战斗数值统一从 Stat 层出口

V0.3 会增加暴击、吸血、护盾、范围、拾取半径、金币倍率等收益。不要让每个系统各自硬读升级和芯片。

推荐形成一条更清楚的消费链：

```text
升级选择 / 背包邻接 / 武器品质
  -> PlayerRunStats 或 BackpackCombatModifiers
  -> WeaponBase / PlayerController / PickUpMagnet / Loot 系统消费
```

### 4. 表现必须解释规则

新增内容如果玩家看不懂，就是负担。V0.3 每加一个升级或邻接效果，都要同时考虑：

```text
名字
图标或颜色
Tooltip 描述
数值表达
生效反馈
结算或 HUD 是否能回看
```

## 四、关键架构设计

### 1. 三选一升级系统

当前状态：`LevelUpOptionGenerator` 中硬编码 3 个选项，`PlayerRunStats` 承接伤害、射速、移速。

V0.3 目标：升级池扩容，但不要一开始过度工程化。

建议新增类别：

```text
攻击类：伤害、射速、暴击率、暴击伤害、子弹速度、投射物体积
生存类：最大生命、生命恢复、受伤减免、短暂无敌
机动类：移动速度、冲刺冷却、转向速度
搜刮类：拾取半径、宝箱品质权重、装备掉落概率、金币获取倍率
构筑类：背包武器上限、芯片效果倍率、合成价值倍率
```

推荐架构：

```text
LevelUpOptionId       继续作为稳定 ID
LevelUpOption         继续作为运行时展示数据
LevelUpOptionGenerator
  -> 先从硬编码 List 扩成分类候选池
  -> 再加权重、等级门槛、互斥和不重复规则
PlayerRunStats
  -> 扩展更多运行期属性
  -> 提供 ResetToDefault，保证重开干净
```

暂不建议立刻做完整 SO 数据化。原因：三选一还在找手感，先用代码快速试错更便宜。

### 2. 邻接效果系统

当前状态：`AdjacencyEffectResolver` 里分别处理 DualWield、FireRateBoost、DamageBoost。

V0.3 风险：新效果继续用一个方法一个分支，会让 Resolver 变胖。

建议先引入“效果策略”概念，即使不马上完全数据化，也要在设计上分清：

```text
Stackable：可叠加，例如攻速、伤害、暴击率
Exclusive：互斥，例如双持防三持
PerWeapon：只作用于参与邻接的武器
Global：作用于玩家全局，例如拾取半径、金币倍率
Capped：有上限，例如攻速最多 2.0x
```

建议新增邻接效果优先级：

```text
P0：CritBoost        暴击率/暴击伤害，最容易和伤害系统结合
P0：RangeBoost       射程或索敌范围，玩家能明显感知
P1：ReloadBoost      冷却/射击间隔进一步细分
P1：ShieldLink       防具或护盾芯片，提高生存
P2：GoldMagnet       金币/拾取/搜刮类邻接，连接经济系统
P2：BurningBullets   燃烧/持续伤害，需要 DoT 管线，稍后做
```

架构建议：

```text
InventoryGrid.ScanAdjacency：只产出候选效果，不懂战斗
AdjacencyEffectResolver：只筛有效效果，不直接改武器
BackpackEffectCollector：把 validEffects 汇总成 Combat/Economy/Loot Modifier
BackpackWeaponActivator：只负责武器激活和把战斗 Modifier 注入 WeaponBase
```

如果暂时不新增 `BackpackEffectCollector`，至少要防止 `BackpackWeaponActivator` 继续无限膨胀。

### 3. 音频系统

当前状态：`SfxPlayer` 单 AudioSource + 多个 AudioClip 字段，适合 V0.2，但不适合继续扩展。

V0.3 目标：补基础音效和背景音乐，同时建立可扩展入口。

推荐架构：

```text
AudioManager
  - SfxSource
  - MusicSource
  - PlaySfx(SfxId id)
  - PlayMusic(MusicId id, fadeTime)
  - SetMasterVolume / SetSfxVolume / SetMusicVolume

AudioCue / AudioCatalog
  - id
  - clips[]
  - volume
  - pitchRandomRange
  - cooldown

AudioMixer
  - Master
  - SFX
  - Music
```

基础音效优先级：

```text
P0：按钮点击、背包打开/关闭、拖拽放下、合并成功、邻接生效
P0：Boss 出场、Boss 受击、Boss 死亡
P0：背景音乐循环
P1：低血量提示、升级选择确认、金色物品出现
P2：不同武器单独开火音色
```

### 4. 敌人寻路与群体移动

当前状态：`EnemyAI` 使用 `CharacterController.SimpleMove` 直线追玩家，开放场景足够，但敌人多后容易挤成一团。

V0.3 不建议第一步就全量替换为 NavMeshAgent。当前竞技场是开放圆形地图，直接追击 + 群体分离更便宜，也更容易控制性能。

建议分层：

```text
EnemyAI：只管状态，决定追击/攻击/死亡
EnemyMovement：计算移动方向和速度
EnemySteering：分离、避让、卡住修正
EnemySpawner / WaveDirector：控制数量和强度
```

优化顺序：

1. 先把移动逻辑从 `EnemyAI.Update()` 拆出来。
2. 加分离力：敌人之间保持最小距离，避免完全重叠。
3. 加低频重算：目标方向和分离采样不必每帧全量重算。
4. 对 Boss 或复杂障碍再考虑 NavMeshAgent，不让普通怪全员背上高成本。
5. 用 Profiler 对比优化前后 PlayerLoop 和 GC，而不是凭感觉宣布优化成功。

### 5. Boss 系统

Boss 不应该只是“大血量精英怪”，要有阶段和招式。

推荐 Boss 架构：

```text
BossController
  - BossState：Intro / Chase / Skill / Enraged / Dead
  - Health 事件订阅
  - 技能冷却和阶段判断

BossSkill
  - Warning
  - Execute
  - Recover

BossSpawnDirector
  - 由 WaveDirector 或 GameSession 触发
  - 控制 Boss 出场时机、HUD、BGM、奖励

BossHudView
  - 血条
  - 名称
  - 阶段提示
```

第一只 Boss 推荐做“简单但完整”的 3 技能版本：

```text
技能 1：冲锋，地面预警后直线突进
技能 2：扇形弹幕，迫使玩家走位
技能 3：召唤小怪，制造清场压力
阶段变化：50% 血以下攻速/移速提高，BGM 或颜色变化
死亡奖励：高品质宝箱或必出稀有物品
```

### 6. 存档与战绩

V0.3 的存档目标不是复杂账号系统，而是本地留存记录。

推荐字段：

```text
bestScore
bestSurvivalTime
bestLevel
bestGold
bestBackpackValue
bestKillCount
totalRuns
totalKills
totalGoldCollected
legendaryItemFoundCount
goldenItemFoundCount
lastPlayedVersion
```

推荐架构：

```text
SaveData              纯数据结构
SaveService           Load / Save / UpdateAfterRun
SaveRepository        JSON 文件读写，路径 Application.persistentDataPath
MainMenuRecordView    主菜单展示最高纪录
ResultView            本局结算后展示是否刷新纪录
```

第一版可以用 JSON 文件，不建议只用零散 `PlayerPrefs`。原因是字段会越来越多，JSON 更适合版本迁移和调试。

## 五、版本模块安排建议

### v0.3.0.1：版本管理切换与内容基线

**目标**：确认 V0.2 已封版，把后续推进方式从“课时制”切换为“版本号 / 模块号”。

- 检查 V0.2 Build / README / Release / 视频链接是否一致。
- 新建 V0.3 内容清单：升级、邻接、物品、音效、Boss、存档。
- 明确哪些核心架构由用户亲写，哪些重复样板可由 AI 辅助。
- 更新 `plan.md`、`Docs/V0.3版本管理.md`、`Docs/V0.3开发日志.md`。

**验收**：V0.3 待办不是散点愿望，而是有优先级、有模块边界、有版本顺序。

### v0.3.1：三选一升级候选池

**目标**：把升级池从 3 个扩到 8~12 个，让每次升级更有变化。

- 扩展 `LevelUpOptionId`。
- 扩展 `PlayerRunStats`：生命、拾取、暴击、金币倍率等。
- `LevelUpOptionGenerator` 增加分类池、等级门槛、权重和同轮不重复。
- `LevelUpChoiceView` 保持展示，不负责规则。

**验收**：连续升级多次，不再频繁看到同样 3 个选项；选项能真实影响战斗或搜刮。

**可拆快照**：`v0.3.1.1` 扩枚举与文案；`v0.3.1.2` 扩 `PlayerRunStats`；`v0.3.1.3` 接入权重和门槛；`v0.3.1.4` UI 验收与调参。

### v0.3.2：邻接效果架构升级

**目标**：为更多邻接效果做承载，避免 Resolver 和 Activator 膨胀。

- 梳理 `AdjacencyEffectResolver` 的策略：Stackable / Exclusive / PerWeapon / Global / Capped。
- 设计或实现 `BackpackEffectCollector`。
- 明确战斗 Modifier、经济 Modifier、搜刮 Modifier 的出口。
- UI 继续只显示 validEffects，不显示假效果。

**验收**：新增效果前，系统已经知道“谁负责筛选、谁负责汇总、谁负责注入”。

### v0.3.3：新邻接效果实装

**目标**：新增 3 个可感知邻接效果。

推荐第一批：

```text
CritBoost：暴击率/暴击伤害
RangeBoost：自动武器索敌范围或子弹射程
ShieldLink：防具邻接提供护盾或减伤
```

**验收**：每个效果都有规则、UI 金边、Tooltip 描述、真实战斗收益和上限策略。

### v0.3.4：内容池扩展

**目标**：把新效果配套到真实物品和掉落表里。

- 新增 2~3 个芯片物品。
- 新增 1 个武器或武器变体。
- 新增若干高价值收集品。
- 更新宝箱和敌人掉落表。
- 补图标、稀有度、价值、Tooltip。

**验收**：玩家能在正常游玩中摸到新内容，而不是只在测试场景里硬塞。

### v0.3.5：基础音频系统与 BGM

**目标**：从 `SfxPlayer` 字段堆叠升级为基础音频服务。

- 新增 `AudioManager` 或升级 `SfxPlayer` 为统一入口。
- 区分 SFX / Music。
- 接入背景音乐循环。
- 补按钮、背包、合成、邻接、金色物品、Boss 相关音效。
- 预留音量设置接口。

**验收**：游戏不再只有零散音效，主菜单/战斗/Boss 至少有基础音乐和关键反馈音。

### v0.3.6：敌人寻路与群体移动优化

**目标**：普通敌人的追击更自然，数量上来后不再明显挤成一团。

- 从 `EnemyAI` 拆出移动模块。
- 增加分离力或简易避让。
- 控制目标方向和邻居采样频率。
- 处理卡住/贴边/过度重叠。
- Profiler 对比优化前后。

**验收**：敌群移动更稳定；无明显 GC；帧耗不因分离算法明显上升。

### v0.3.7：Boss 一期 - 出场、血条与基础 FSM

**目标**：让 Boss 作为终局节点出现，而不是普通怪放大版。

- 新增 Boss prefab 和 `BossController`。
- 接入 `Health`、受击反馈、死亡奖励。
- Boss 出场时暂停普通波次或降低普通怪压力。
- 新增 Boss 血条 UI。

**验收**：Boss 能按时间或波次出场，有血条，有死亡奖励，能回到结算链路。

### v0.3.8：Boss 二期 - 技能与阶段变化

**目标**：Boss 至少有 2~3 个可读技能。

- 冲锋预警。
- 扇形弹幕或范围攻击。
- 召唤小怪。
- 50% 血阶段变化。
- Boss BGM 或音效强化。

**验收**：Boss 战有躲避、输出、清怪和阶段变化，不只是磨血。

### v0.3.9：本地存档与最高纪录

**目标**：建立局外留存记录。

- 新增 `SaveData`。
- 新增 `SaveService`。
- 结算时更新最高分、最高金币、最高背包价值、金色物品数量等。
- 主菜单显示历史最高纪录。
- ResultView 显示“新纪录”。

**验收**：关闭游戏再打开，历史纪录仍然存在；版本字段可用于未来迁移。

### v0.3.10：V0.3 平衡、验收与发布

**目标**：对 V0.3 做一次完整版本闸门。

- 试玩至少 2~3 局。
- 检查升级池、邻接效果、Boss、存档、音频是否互相打架。
- Profiler 快扫。
- Build v0.3。
- 更新 README、Release、V0.3 复盘。

**验收**：V0.3 能作为新的 Release 发布，而不是一堆半成品功能。

## 六、推荐优先级

如果时间有限，优先级建议如下：

```text
P0：升级三选一扩容、新邻接效果、内容池扩展
P1：基础音频 + BGM、敌人群体移动优化
P2：Boss 一期 + 二期
P3：本地存档与最高纪录
P4：完整数据化、复杂经济、更多 Boss 和完整词缀系统
```

为什么 Boss 不是第一优先级：Boss 很显眼，但如果玩家前 10 分钟的升级和构筑仍然变化不够，Boss 只是结尾烟花。V0.3 应该先让每一局的中途选择变丰富，再让 Boss 成为终局检验。

## 七、v0.3.1 开发建议

`v0.3.0.1` 不建议写代码。它只负责完成版本管理切换和内容基线确认。

进入 `v0.3.1` 前，建议先做 5 个准备：

1. 把 V0.2 未提交内容提交干净。
2. 确认 V0.3 不回头改 V0.2 主线。
3. 列出第一批升级候选：攻击、生存、机动、搜刮、构筑五类。
4. 决定哪些升级先用代码表快速试错，哪些暂缓到数据化。
5. 建立 `v0.3.1` 验收清单：能否抽到、能否生效、能否解释、能否重开清零。

这样 `v0.3.1` 开始扩三选一时，就不是脑袋一热加选项，而是围绕版本目标加内容。

## 八、阶段判断

V0.3 的目标不是让《背包幸存者》立刻变成商业完整游戏，而是让它从“能展示完整闭环”升级到“能展示内容扩展能力和系统可持续迭代能力”。

如果 V0.2 证明的是：

> 我能把一个游戏原型做成可玩的 Demo。

那么 V0.3 要证明的是：

> 我能在不推倒重来的情况下，沿着已有架构继续扩内容、扩反馈、扩敌人行为和扩长期记录。
