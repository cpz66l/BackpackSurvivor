# 作品材料 · 录屏脚本

> 项目：《背包幸存者》v0.2 Windows Demo  
> 目标：录一段 1~2 分钟作品展示视频，让第一次看到项目的人快速理解玩法、完成度和技术亮点。  
> 建议分辨率：1600×900 Windowed。  
> 建议录制方式：直接录正式 Build，不录 Unity Editor。  

---

## 一、录屏目标

这段视频不追求把所有系统都讲完，而是让观看者在短时间内看到三件事：

1. 这是一个可以独立运行的完整 Demo，不只是工程原型。
2. 核心玩法是“战斗 + 搜刮 + 背包构筑”。
3. 背包里的摆放、合并、邻接和武器激活会真实影响战斗。

视频最好控制在 90 秒左右。如果用于投递简历，宁可短而清楚，不要录成完整试玩录像。

---

## 二、录制前准备

### 1. 启动方式

使用 GitHub Release 中的正式 Windows 包，或者本地 Build 目录：

```text
Builds/BackpackSurvivor_v0.2_Windows/BackpackSurvivor.exe
```

### 2. 推荐设置

- 窗口模式：1600×900。
- 录屏范围：只录游戏窗口。
- 声音：保留游戏音效，麦克风讲解可选。
- 鼠标：建议显示鼠标指针，因为背包拖拽和瞄准都依赖鼠标。
- 开始前：确认主菜单、玩法说明、开始游戏、背包 Tab、结算重开都能正常使用。

### 3. 推荐素材状态

如果想录得更稳，可以先准备一局中期存档效果是不现实的，所以建议直接录一段新开局，然后用剪辑跳切到背包构筑更丰富的片段。视频可以是“实机片段剪辑”，不必须一镜到底。

---

## 三、90 秒主线脚本

### 0~8 秒：主菜单与项目身份

**画面**：主菜单，展示标题、背景图、开始按钮、玩法说明按钮。  
**操作**：鼠标移动到玩法说明，短暂停留，再关闭。  
**旁白参考**：

```text
这是我独立开发的 Unity 俯视角生存射击 Demo《背包幸存者》，当前 v0.2 已经完成 Windows Build，可以从主菜单进入完整单局。
```

**要点**：第一眼告诉别人这是完整包，不是 Scene 里临时 Play。

### 8~22 秒：进入战斗与基础循环

**画面**：点击开始游戏，进入 01-Run，玩家移动、主动射击、自动武器开火、敌人追击。  
**操作**：走位、左键射击、让自动武器打几下，展示伤害数字和命中反馈。  
**旁白参考**：

```text
单局核心是 15 分钟生存循环。玩家可以主动射击，同时背包中激活的武器会在角色身边自动攻击敌人。
```

**要点**：一定要让伤害数字、子弹、敌人追击同时出现。

### 22~36 秒：掉落、金币、经验和宝箱

**画面**：击杀敌人，经验/金币飞出，靠近后磁吸；镜头扫到宝箱距离提示或宝箱模型。  
**操作**：拾取经验和金币，靠近宝箱按 `E` 打开。  
**旁白参考**：

```text
敌人会掉落经验、金币和装备，宝箱则是高价值装备的重要来源。波次越往后，精英敌人和高品质宝箱的期望越高。
```

**要点**：掉落物颜色、金币 HUD、宝箱模型最好都出现。

### 36~60 秒：背包构筑核心

**画面**：按 `Tab` 打开背包，展示网格、物品图标、稀有度底色、等级星星、价值和 Tooltip。  
**操作**：拖拽物品、旋转物品、把两个同名同级物品合并，摆出双持或芯片邻接。  
**旁白参考**：

```text
装备不是直接进属性栏，而是进入有限网格背包。物品会占用不同形状，支持拖拽、旋转、合并升级和邻接构筑。灰色接边表示可连接方向，金色接边表示真实生效的邻接效果。
```

**要点**：这是整段视频最重要的部分，要慢一点，让观众看清“背包不是装饰”。

### 60~75 秒：构筑影响战斗

**画面**：关闭背包，回到战斗，展示自动武器数量、射速或伤害变强。  
**操作**：让双持或芯片效果生效后打一波敌人。  
**旁白参考**：

```text
背包中的具体武器实例会决定自动武器激活，稀有度、等级和芯片邻接会进入真实伤害与攻速计算。
```

**要点**：让观看者理解“构筑会回流到战斗系统”。

### 75~88 秒：升级三选一与波次压力

**画面**：拾取经验触发升级三选一，或展示 HUD 上的波次名称和敌人压力。  
**操作**：选择一个升级项，回到战斗。  
**旁白参考**：

```text
局内还有经验升级三选一和波次导演。敌人血量、数量、精英概率和宝箱品质都会随时间推进。
```

**要点**：展示成长系统与时间压力，不用解释每个选项。

### 88~100 秒：结算与闭环

**画面**：切到结算页片段，展示存活时间、等级、经验、击杀数、背包价值，最好有 Restart / MainMenu 按钮。  
**操作**：停留 2~3 秒。  
**旁白参考**：

```text
目前 Demo 已经完成主菜单、单局、结算、重开和正式 Build 验收，后续会继续补充新手引导、更多芯片和经济系统。
```

**要点**：用结算页证明这是一条完整闭环。

## 五、镜头优先级

### 必须出现

- 主菜单或玩法说明入口。
- 玩家移动、主动射击、自动武器攻击。
- 敌人死亡后掉落经验、金币或装备。
- 宝箱或宝箱距离提示。
- 背包打开、拖拽、旋转、合并或邻接。
- 金色接边或武器激活标记。
- 升级三选一或结算页二选一，最好都出现。

### 加分出现

- 高价值背包总价值。
- 精英敌人或高稀有度宝箱。
- Tooltip 展示物品价值/效果。
- DamageBoost 或 FireRateBoost 生效前后对比。
- Profiler 证据截图可以放在 README 或作品集页面，不建议塞进短视频主线。

---

## 六、剪辑建议

1. 开头 3 秒必须有游戏名和主菜单，不要一上来就是混乱战斗。
2. 背包构筑段宁可放慢，也不要快速乱拖，观看者需要看懂规则。
3. 不要录太久的跑图，宝箱距离提示出现即可。
4. 如果一局运气不好没有核心物品，可以多录几段素材后剪成一条展示视频。
5. 结尾一定给 GitHub / Release / README 一个落点，让别人知道可以下载试玩。

## 八、录完后的自检清单

- 视频前 10 秒能看出这是一个游戏，而不是 Unity 工程录屏。
- 观众能理解背包会影响战斗。
- 至少出现一次拖拽或旋转。
- 至少出现一次邻接或芯片效果。
- 至少出现一次升级、宝箱或结算。
- 视频没有长时间停在空跑、发呆或菜单上。
- GitHub Release 下载入口在视频简介或 README 中可见。
