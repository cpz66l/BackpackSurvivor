# 第29课 · 武器稀有度与等级差异

> 课程周期：2026-08-05  
> 前置：第28课《旋转邻接方向修正》  
> 关键词：武器实例倍率、WeaponItemStatResolver、乘区、Tooltip 可读性、OnChanged 语义事件

---

## 一、这节课实现了什么

第29课解决了一个很影响掉落期待的问题：同类型武器不再只是同一个模板。  
现在背包中的武器会根据 `Item.Rarity` 和 `Item.Level` 给激活出来的自动武器注入专属伤害倍率。

这节课的核心不是“把伤害写大”，而是建立一条清晰链路：

```text
背包 Item 实例
  ↓
WeaponItemStatResolver 解析稀有度 / 等级
  ↓
BackpackWeaponActivator 激活武器时注入倍率
  ↓
WeaponBase.Fire() 统一计算最终伤害
  ↓
伤害数字和真实扣血一致
```

最终玩家已经能在测试中看到：不同类型、不同稀有度、不同等级的武器伤害都不一样；玩家升级带来的伤害加成也会和武器自身倍率形成不同乘区。

### 任务 1 · 新增 WeaponItemStatResolver

- 新增 `WeaponItemStatResolver`。
- 用场景序列化表配置不同稀有度的武器伤害倍率。
- 用 `levelDamageMultiplier` 表示每升一级额外获得的武器等级倍率。
- `GetDamageMultiplier(Item item)` 输入运行时 `Item`，输出这件武器的伤害倍率。
- `item == null` 或倍率表未接时返回 `1f`，保证缺配置时不炸。

这一步把“物品品质如何影响战斗”从 `BackpackWeaponActivator` 中拆出去，避免激活器变成数值公式垃圾桶。

### 任务 2 · WeaponBase 增加背包武器倍率乘区

- `WeaponBase` 新增 `backpackWeaponMultiplier`，默认 `1f`。
- 新增 `SetBackpackWeaponMultiplier(float multiplier)`。
- `Fire()` 统一按以下公式计算伤害：

```text
最终伤害 = 武器 prefab 基础伤害 × 玩家升级伤害倍率 × 背包武器实例倍率
```

- 池化子弹分支和无池兜底分支共用同一个 `rawDamage`，避免两条路线伤害不一致。

这一步建立了第一个清晰的“武器品质乘区”。

### 任务 3 · BackpackWeaponActivator 激活时注入武器倍率

- `BackpackWeaponActivator` 新增 `weaponItemStatResolver` 引用。
- `Awake()` 中允许 `FindAnyObjectByType<WeaponItemStatResolver>()` 兜底。
- `TryActivateItem(item)` 成功拿到 `AutoWeapon` 后，调用 Resolver 计算倍率并写入武器。
- `DeactivateAllWeapons()` 刷新背包武器时重置攻速倍率和武器伤害倍率。
- DualWield 额外激活仍然走 `TryActivateItem()`，所以第二把双持武器也吃自己的稀有度和等级。

这一步很关键：倍率不是挂在“武器类型”上，而是挂在“背包里的具体 Item 实例”上。

### 任务 4 · 修正合并升级后的即时刷新

测试时发现：武器合成升级后，Tooltip 能显示等级变化，但伤害倍率要等下一次背包重绘后才变化。

根因是拖拽合并时：

```text
BeginDrag() 已经 Remove(source) 并触发过 OnChanged
TryMerge() 里 target.IncreaseLevel()
Remove(source) 因为 source 已经不在背包里，不会再触发 OnChanged
```

于是 `BackpackWeaponActivator` 没收到“目标物品等级变了”的事件。

最终修正：`TryMerge()` 成功后，如果 `source` 已经不在背包中，就主动补一次 `OnChanged`。  
这样 UI、武器激活器、背包总价值和邻接计算都能收到同一个数据变化事件。

### 任务 5 · Tooltip 显示武器收益

- `ItemTooltipView` 引用同一个 `WeaponItemStatResolver`。
- 武器标签显示“伤害提升 +xx%”。
- 芯片标签继续显示 `EffectValue`。
- 收集品只显示稀有度、尺寸和价值。
- Resolver 为空时武器伤害提升显示为 `+0%`，不因漏接线报错。

这一步让玩家知道“为什么这把枪更强”。  
数值系统如果只有真实效果，没有可读反馈，玩家很难形成构筑判断。

### 任务 6 · 场景接线与实测

- `01-Run.unity` 中新增并保存 `WeaponItemStatResolver`。
- `BackpackWeaponActivator` 与 `ItemTooltipView` 指向同一个 Resolver。
- 当前场景倍率表已配置 Common / Uncommon / Rare / Epic 四档，`levelDamageMultiplier = 0.25`。
- 用户实测通过：不同等级、不同稀有度、不同类型武器伤害均有差异。
- 玩家升级伤害倍率会继续和武器自身倍率相乘，形成多乘区效果。

## 二、最终代码（关键片段）

### 1. WeaponItemStatResolver 负责解释武器品质

```csharp
public class WeaponItemStatResolver : MonoBehaviour
{
    [System.Serializable]
    private class WeaponStat
    {
        public Rarity rarity;
        public float damageMultiplier = 1f;
    }

    [SerializeField] private List<WeaponStat> weaponStats;
    [SerializeField] private float levelDamageMultiplier = 0.25f;

    public float GetDamageMultiplier(Item item)
    {
        if (item == null || weaponStats == null)
            return 1f;

        foreach (var stat in weaponStats)
        {
            if (stat.rarity == item.Rarity)
            {
                float damageMultiplier = stat.damageMultiplier *
                    (1 + (item.Level - 1) * levelDamageMultiplier);
                return damageMultiplier;
            }
        }

        return 1f;
    }
}
```

Resolver 是“战斗如何理解物品品质”的小翻译层。  
`Item` 不需要知道自己能加多少伤害，背包纯数据层也不被战斗公式污染。

### 2. WeaponBase 新增背包武器倍率

```csharp
protected float backpackWeaponMultiplier = 1f;

protected void Fire(Vector3 direction)
{
    sfx?.PlayShoot();

    float rawDamage = damage * stats.DamageMultiplier * backpackWeaponMultiplier;

    if (bulletPool != null)
    {
        Projectile bullet = bulletPool.Get(firePoint.position).GetComponent<Projectile>();
        float finalDamage = Mathf.RoundToInt(rawDamage);
        bullet.Initialize(projectileSpeed, finalDamage, targetFaction, maxDistance, direction, 0f, gameObject);
    }
    else
    {
        GameObject bulletObj = new GameObject("bullet");
        bulletObj.transform.position = firePoint.position;
        Projectile bullet = bulletObj.AddComponent<Projectile>();

        float finalDamage = Mathf.RoundToInt(rawDamage);
        bullet.Initialize(projectileSpeed, finalDamage, targetFaction, maxDistance, direction, 0f, gameObject);
    }
}
```

`rawDamage` 提前算一次，池化与非池化路线共用。  
这样不会出现“正常游戏里一个伤害，兜底路径里另一个伤害”的分叉。

### 3. WeaponBase 暴露倍率写入口

```csharp
public void SetBackpackWeaponMultiplier(float multiplier)
{
    backpackWeaponMultiplier = Mathf.Max(1f, multiplier);
}
```

当前 Demo 只允许武器品质增强，不做负面词条。  
所以最小值夹在 `1f`，避免配置错误让武器伤害低于基础值。

### 4. Activator 激活时写入具体 Item 的倍率

```csharp
if (autoWeapon != null)
{
    activeWeaponsByItem[item] = autoWeapon;

    if (weaponItemStatResolver == null)
        autoWeapon.SetBackpackWeaponMultiplier(1f);
    else
    {
        float weaponDamageMultiplier = weaponItemStatResolver.GetDamageMultiplier(item);
        autoWeapon.SetBackpackWeaponMultiplier(weaponDamageMultiplier);
    }
}
```

这里的重点是：同一种 `ItemTag.Pistol` 可以有不同稀有度、不同等级。  
所以倍率不能只按 Tag 配，而要按具体 `Item` 实例解析。

### 5. 刷新武器时重置旧倍率

```csharp
AutoWeapon autoWeapon = weapon.WeaponObject.GetComponent<AutoWeapon>();
autoWeapon.SetBackpackFireRateMultiplier(1f);
autoWeapon.SetBackpackWeaponMultiplier(1f);
weapon.WeaponObject.SetActive(false);
```

重算前先清空，是防止上一把高稀有武器的倍率残留到下一把普通武器身上。  

### 6. TryMerge 成功后补发语义事件

```csharp
public bool TryMerge(Item source, Item target)
{
    if (!CanMerge(source, target)) return false;
    target.IncreaseLevel();

    bool sourceInGrid = Contains(source);
    Remove(source);

    if (!sourceInGrid)
        OnChanged?.Invoke();

    return true;
}
```

合并升级不是单纯删除 source，它还改变了 target 的等级。  
所以 `TryMerge()` 成功本身就应该被视为背包数据变化。

### 7. Tooltip 区分武器、芯片和收集品

```csharp
if (item.Tag == ItemTag.Magazine || item.Tag == ItemTag.AttackDamageChip)
{
    int percent = Mathf.RoundToInt(item.EffectValue * 100f);
    bodyText.text = $"稀有度: {GetRarityChinese(item.Rarity)}\n" +
                    $"大小: {item.Width}x{item.Height}\n" +
                    $"价值: ￥{item.ScoreValue}\n" +
                    $"效果: +{percent}%";
}
else if (item.Tag == ItemTag.Rifle || item.Tag == ItemTag.Pistol || item.Tag == ItemTag.Shotgun)
{
    int percent;
    if (weaponItemStatResolver == null)
        percent = 0;
    else
        percent = Mathf.RoundToInt((weaponItemStatResolver.GetDamageMultiplier(item) - 1) * 100f);

    bodyText.text = $"稀有度: {GetRarityChinese(item.Rarity)}\n" +
                    $"大小: {item.Width}x{item.Height}\n" +
                    $"价值: ￥{item.ScoreValue}\n" +
                    $"伤害提升: +{percent}%";
}
```

Tooltip 复用 Resolver，不重新发明一套武器倍率。  
这保证 UI 显示和真实战斗数值来自同一个事实源。

## 三、周期链路

### 武器品质乘区链路

```text
LootEntry.rarity
  ↓
InventorySystem.CreateItemFromLootEntry()
  ↓
Item.Rarity / Item.Level
  ↓
WeaponItemStatResolver.GetDamageMultiplier(item)
  ↓
AutoWeapon.SetBackpackWeaponMultiplier(multiplier)
  ↓
WeaponBase.Fire()
  ↓
Projectile.Initialize(finalDamage)
```

### 最终伤害计算链路

```text
Weapon prefab 基础 damage
  ×
PlayerRunStats.DamageMultiplier（玩家升级乘区）
  ×
backpackWeaponMultiplier（武器稀有度 / 等级乘区）
  ↓
Mathf.RoundToInt
  ↓
子弹真实伤害与伤害数字
```

### 背包变化刷新链路

```text
放置 / 移除 / 合并升级
  ↓
InventoryGrid.OnChanged
  ↓
InventoryUIController.Redraw()
  ↓
BackpackWeaponActivator.RefreshActiveWeapons()
  ↓
关闭旧武器并清倍率
  ↓
按背包位置重新激活武器并注入新倍率
```

### 双持武器倍率链路

```text
基础激活位先激活一把武器
  ↓
ActivateDualWieldWeapons(validEffects)
  ↓
TryActivateItem(effect.ItemA / effect.ItemB)
  ↓
第二把武器同样走 Resolver
  ↓
第二把武器吃自己的 Rarity / Level
```

### Tooltip 可读性链路

```text
鼠标悬停 ItemView
  ↓
ItemTooltipView.Show(item, position)
  ↓
按 ItemTag 分流
  ↓
武器：Resolver 显示伤害提升
芯片：EffectValue 显示效果值
收集品：显示价值与基础信息
```

## 四、设计思考

### 1. 为什么不直接做多套武器 prefab？

Demo 冲刺期最重要的是性价比。  
如果每个稀有度、每个等级都做一套 prefab，会快速膨胀成大量重复资产，还会让平衡调整变得很麻烦。

当前方案让 prefab 继续负责“武器类型手感”：

```text
手枪 / 步枪 / 霰弹枪的基础 damage、间隔、射程、枪口等
```

让 `Item` 和 Resolver 负责“本局掉到的这把武器品质”：

```text
稀有度倍率 / 等级倍率
```

这样一把蓝色 Lv.2 手枪和白色 Lv.1 手枪可以共用同一个手枪实体，但打出不同伤害。

### 2. 为什么不用 Item.EffectValue 表示武器伤害？

`Item.EffectValue` 现在已经服务芯片，比如 FireRateBoost。  
如果把武器伤害也塞进去，Tooltip 会分不清“这个值是芯片效果，还是武器伤害倍率”。

所以本课单独建立武器倍率通道：

```text
芯片效果：Item.EffectValue
武器品质：WeaponItemStatResolver.GetDamageMultiplier(item)
```

这让字段语义保持干净，后续第30课做攻击芯片时也不会互相抢字段。

### 3. 为什么这是乘区而不是加法？

现在最终伤害是：

```text
基础伤害 × 玩家成长 × 武器品质
```

玩家升级强化的是“角色火力”，武器稀有度强化的是“装备质量”。  
它们来源不同，所以用不同乘区更合理。

这会带来一个很好的构筑效果：同样选择“伤害 +20%”，拿到高品质武器时收益更明显。  
玩家会自然理解“好武器值得围绕它构筑”。

### 4. 为什么 Resolver 放在 GamePlay.Combat？

`BS.Inventory` 是纯数据层，它不应该知道战斗平衡。  
`Rarity` 是通用概念，但“Rare 等于多少伤害倍率”是战斗玩法解释。

所以 Resolver 放在 `GamePlay.Combat`，职责是：

```text
把背包物品解释成战斗武器数值
```

这比把公式写进 `Item` 更符合分层。

### 5. 为什么 Tooltip 要复用 Resolver？

UI 的职责是解释真实规则，不是重新计算一套看起来类似的规则。  
如果 Tooltip 自己写一套稀有度倍率，未来数值表改了，战斗和 UI 很容易分叉。

本课让 Tooltip 和战斗都读同一个 Resolver，形成单一事实源：

```text
真实伤害用它
玩家看到的伤害提升也用它
```

### 6. 为什么合并升级必须触发 OnChanged？

`OnChanged` 不应该只代表格子数组发生变化，也应该代表背包中物品状态发生变化。  
合并升级改变的是 `target.Level`，它会影响价值、Tooltip、武器倍率和芯片效果。

所以即使格子引用没有新增或删除，只要物品等级变了，也应该广播数据变化。

## 五、踩坑记录

### 1. Resolver 没挂进场景，倍率一直是 1

- **现象**：代码看起来已经乘了武器倍率，但实际伤害和之前没有区别。
- **排查**：顺着 `TryActivateItem()` 看，发现 `weaponItemStatResolver == null` 时会兜底 `1f`；再查场景 YAML，场景里没有 `WeaponItemStatResolver` 组件。
- **根因**：代码通道写好了，但场景没有接线，`FindAnyObjectByType<WeaponItemStatResolver>()` 找不到对象。
- **修复**：在 `01-Run` 场景中添加 Resolver，配置倍率表，并拖给 `BackpackWeaponActivator` 和 `ItemTooltipView`。
- **沉淀**：Unity 问题要同时查代码链路和场景序列化；代码对不代表 Inspector 已经接上。

### 2. 合并升级后伤害不立刻变化

- **现象**：武器合成升级后，UI 能看到等级变化，但伤害倍率要等下一次重绘才生效。
- **排查**：`BeginDrag()` 已经把 `source` 移出背包并触发过一次 `OnChanged`；`TryMerge()` 里升级 target 后再 `Remove(source)`，因为 source 已不在背包里，所以不会触发新的 `OnChanged`。
- **根因**：`target.IncreaseLevel()` 改变了物品状态，但没有广播背包变化事件。
- **修复**：`TryMerge()` 成功后，如果 source 不在 grid 中，就主动 `OnChanged?.Invoke()`。
- **沉淀**：事件要表达语义变化，不只是数组结构变化；等级变化也是背包数据变化。

### 3. 无池兜底分支最初漏乘武器倍率

- **现象风险**：池化子弹和无池子弹可能打出不同伤害。
- **根因**：只在 `bulletPool != null` 分支里乘了 `backpackWeaponMultiplier`。
- **修复**：把 `rawDamage` 提前到分支外统一计算。
- **沉淀**：同一条规则不要在两个分支里各写一遍，先算事实，再决定生成路线。

### 4. Tooltip 容易重新发明数值公式

- **现象风险**：Tooltip 显示的伤害提升和真实战斗倍率不一致。
- **根因**：表现层为了方便可能自己写一套稀有度判断。
- **修复**：Tooltip 也引用 `WeaponItemStatResolver`。
- **沉淀**：表现层可以解释规则，但不能复制规则。

### 5. IDE 自动导入 Unity.VisualScripting

- **现象**：`ItemTooltipView` 混入了无用 `using Unity.VisualScripting;`。
- **根因**：IDE 自动补 using。
- **修复**：删除无用 using，并再次跑 using 闸。
- **沉淀**：运行时代码 using 要人工确认；无用包引用不是小洁癖，是长期打包风险控制。

## 六、面试问答

**Q1：你是怎么让同类型武器根据稀有度和等级变强的？**  
> 我没有为每个稀有度做新 prefab，而是让背包里的 `Item` 保存 `Rarity` 和 `Level`，再由 `WeaponItemStatResolver` 解析出伤害倍率。`BackpackWeaponActivator` 激活对应 `AutoWeapon` 时，把这个倍率注入到武器实例里，最终由 `WeaponBase.Fire()` 统一参与伤害计算。

**Q2：为什么不用 Item.EffectValue 存武器伤害倍率？**  
> 因为 `EffectValue` 已经服务芯片效果，例如攻速芯片。如果继续复用，会让字段语义混乱。武器品质是装备本体强度，芯片是邻接效果，两者应该分开通道。

**Q3：你这里的最终伤害有哪些乘区？**  
> 当前至少有三个乘区：武器 prefab 基础伤害、玩家升级的 `PlayerRunStats.DamageMultiplier`、背包武器的 `backpackWeaponMultiplier`。这样玩家升级和高品质武器会互相放大，形成更明显的构筑收益。

**Q4：为什么 WeaponItemStatResolver 不放在 Inventory 程序集？**  
> `BS.Inventory` 是纯数据层，不应该知道战斗平衡。`Rarity` 可以是通用概念，但“稀有度等于多少伤害倍率”属于玩法解释，所以放在 `GamePlay.Combat` 更合适。

**Q5：DualWield 的第二把武器为什么也能吃自己的稀有度和等级？**  
> 因为基础激活和 DualWield 额外激活都统一走 `TryActivateItem(item)`。倍率注入写在这个方法里，所以任何被激活的背包武器都会按自己的 `Item` 实例计算倍率。

**Q6：为什么合并升级后要触发 OnChanged？格子不是已经没变了吗？**  
> 背包数据变化不只包括格子占用变化，也包括物品状态变化。`target.Level` 变化会影响价值、Tooltip、武器伤害倍率和芯片数值，所以必须广播 `OnChanged` 让表现和战斗系统刷新。

**Q7：为什么 Tooltip 要复用 Resolver？**  
> UI 应该解释真实规则，而不是复制一套规则。Tooltip 和战斗使用同一个 Resolver，才能保证玩家看到的“伤害提升 +xx%”和真实伤害倍率一致。

**Q8：这套方案相比多 prefab 有什么优点？**  
> 它更轻、更好调，也更适合 Demo。prefab 只表达武器类型手感，Item + Resolver 表达本局掉落品质。以后要调稀有度收益，只改倍率表，不需要复制和维护大量武器 prefab。

## 七、习惯清单

1. 同类型装备差异优先从“运行时数值注入”做起，不急着复制 prefab。
2. 字段语义要干净，芯片效果和武器品质不要共用一个 `EffectValue`。
3. 公式层要单一事实源，战斗和 Tooltip 都读同一个 Resolver。
4. 分支前先算共同事实，避免池化和非池化路径逻辑分叉。
5. 刷新前先清旧倍率，防止高品质武器数值残留。
6. 数据层事件要表达语义变化，等级变化也要广播。
7. Unity 功能不生效时，同时查代码和 Inspector/YAML 接线。
8. using 每次提交前扫一遍，IDE 自动导入不能无脑信。
9. Demo 冲刺期优先做玩家能立刻感知的数值差异。

## 八、思考题（附复习参考）

**Q1：如果以后要让传说武器有特殊效果，应该继续塞进 WeaponItemStatResolver 吗？**  
> 如果只是数值倍率，可以继续放 Resolver；如果是特殊机制，比如子弹分裂、灼烧、穿透，就不应该只靠倍率表，应该进入词缀/效果系统，避免 Resolver 变成万能特判类。

**Q2：如果未来出现负面词条，`SetBackpackWeaponMultiplier()` 的下限还应该是 1f 吗？**  
> 不应该。当前 `1f` 表示武器品质只增强。若有诅咒或负面词条，需要把下限改成合理正数，例如 `0.01f`，并在 Tooltip 中明确显示负面效果。

**Q3：为什么这节课不同时做射程、弹速、暴击？**  
> Demo 冲刺期要优先做最明显、最好验证的收益。伤害数字能直接反馈稀有度和等级差异；射程、弹速、暴击都需要更多 UI 解释和平衡，适合后续扩展。

**Q4：如果 Tooltip 显示的是 +40%，玩家升级后为什么实际伤害提升不只 +40%？**  
> Tooltip 的 +40% 表示武器品质乘区，玩家升级是另一个乘区。最终伤害是多个乘区相乘，所以玩家升级后，高品质武器会获得更高的绝对伤害增长。

**Q5：为什么合并升级事件不应该只由 UI 手动 Redraw 解决？**  
> 因为不只有 UI 关心合并升级。武器激活器、背包价值、邻接效果都可能依赖 `OnChanged`。如果 UI 自己补画，战斗系统仍然会漏刷新。
