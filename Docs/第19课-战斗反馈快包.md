## 一、这节课实现了什么

### 任务 1 · 命中/受击闪色反馈

- 新增 `DamageFlashView`，订阅 `Health.OnDamaged`。
- 敌人受击时短暂闪白，玩家受击时可用红色闪烁。
- `OnDisable()` 停止协程并恢复原色，避免池化对象带着“前世颜色”复活。

### 任务 2 · 池化伤害数字

- 新增 `DamageNumberView`，负责显示伤害文本、上浮、渐隐和回池。
- 新增 `DamageNumberSpawner`，订阅敌人 `Health.OnDamaged`，在受击点附近生成伤害数字。
- 新增 `DamageNumberPoolProvider`，让场景对象池以 Provider 形式暴露给敌人预制体上的 Spawner。
- 伤害数字 Canvas 改为 World Space，并做 Billboard 面向主摄像机。

### 任务 3 · 基础音效入口

- 新增 `SfxPlayer`，集中管理开火、命中、拾取经验、升级、玩家受伤、开宝箱音效。
- 开火音效接入 `WeaponBase.Fire()`。
- 命中音效接入 `DamageNumberSpawner`。
- 经验拾取和升级音效接入 `GameSession.HandleXpCollected()`。
- 开宝箱音效接入 `LootChest.Interact()`。
- 玩家受伤音效接入玩家受击反馈脚本。

### 任务 4 · 玩家受击反馈合并

- 新增 `PlayerHitFeedbackView`，订阅玩家 `Health.OnDamaged`。
- 玩家受伤时同时触发受伤音效和相机震动。
- 音效和震屏互不阻塞，缺某一个表现组件时不影响另一个反馈执行。

### 任务 5 · Cinemachine 轻量震屏

- 确认项目使用 Cinemachine 3.1.7。
- `Main Camera` 挂 `CinemachineBrain`，`CM_PlayerCamera` 挂 `CinemachineCamera + CinemachineFollow`。
- 在 `CM_PlayerCamera` 上新增 `CinemachineBasicMultiChannelPerlin`。
- `CameraShakePlayer` 控制 `AmplitudeGain / FrequencyGain`，用协程让震动强度衰减到 0。

## 二、最终代码（关键片段）

### DamageFlashView：受伤事件驱动闪色

```csharp
private void OnEnable()
{
    if (health != null)
        health.OnDamaged += HandleDamaged;
}

private void OnDisable()
{
    if (health != null)
        health.OnDamaged -= HandleDamaged;

    if (flashRoutine != null)
        StopCoroutine(flashRoutine);

    RestoreColor();
}
```

闪色不是 `Update()` 轮询，而是伤害事件驱动。`OnDisable()` 恢复颜色，是池化对象必须遵守的状态归零。

### DamageNumberSpawner：伤害事件生成表现

```csharp
private void HandleDamaged(DamageInfo info)
{
    if (damageNumberPool == null) return;

    Vector3 spawnPos = info.hitPoint;
    if (spawnPos == Vector3.zero && health != null)
        spawnPos = health.Position;

    GameObject obj = damageNumberPool.Get(spawnPos + offset);
    DamageNumberView view = obj.GetComponent<DamageNumberView>();

    if (view == null) return;

    view.Play(info.damage);
    sfx?.PlayHit();
}
```

这里的重点不是“数字怎么飘”，而是表现层只消费 `DamageInfo`。伤害事实来自战斗层，数字只是投影。

### DamageNumberView：上浮、渐隐、回池

```csharp
private IEnumerator PlayRoutine()
{
    float t = 0f;
    startPosition = transform.position;

    while (t < lifetime)
    {
        t += Time.deltaTime;
        float ratio = Mathf.Clamp01(t / lifetime);

        transform.position = Vector3.Lerp(
            startPosition,
            startPosition + Vector3.up * riseDistance,
            ratio);

        FaceCamera();

        if (canvasGroup != null)
            canvasGroup.alpha = 1f - ratio;

        yield return null;
    }

    playRoutine = null;

    if (pool != null)
        pool.Return(gameObject);
    else
        gameObject.SetActive(false);
}
```

数字生命周期结束后自己回池，Spawner 不持有它的后续状态。

### DamageNumberPoolProvider：场景池 Provider

```csharp
public class DamageNumberPoolProvider : MonoBehaviour
{
    [SerializeField] private ObjectPool damageNumberPool;

    public ObjectPool DamageNumberPool => damageNumberPool;
}
```

敌人是预制体，不能直接拖场景中的对象池引用。Provider 把场景级服务显式暴露出来，比按名字 `GameObject.Find()` 更稳。

### SfxPlayer：集中播放短音效

```csharp
private void PlayOneShot(AudioClip clip)
{
    if (audioSource == null || clip == null) return;

    audioSource.PlayOneShot(clip);
}
```

调用方只表达“我要播放什么反馈”，具体 AudioSource 和 Clip 是否存在，由 `SfxPlayer` 内部兜底。

### CameraShakePlayer：Cinemachine 噪声震屏

```csharp
public void Shake(float duration, float amplitude, float frequency)
{
    if (noise == null)
        return;

    if (shakeRoutine != null)
        StopCoroutine(shakeRoutine);

    shakeRoutine = StartCoroutine(ShakeRoutine(duration, amplitude, frequency));
}
```

```csharp
private IEnumerator ShakeRoutine(float duration, float amplitude, float frequency)
{
    duration = Mathf.Max(0.01f, duration);

    float timer = 0f;
    noise.AmplitudeGain = amplitude;
    noise.FrequencyGain = frequency;

    while (timer < duration)
    {
        timer += Time.unscaledDeltaTime;
        float ratio = Mathf.Clamp01(timer / duration);

        noise.AmplitudeGain = Mathf.Lerp(amplitude, 0f, ratio);
        noise.FrequencyGain = frequency;

        yield return null;
    }

    ResetNoise();
    shakeRoutine = null;
}
```

只衰减 `AmplitudeGain`，不衰减 `FrequencyGain`。因为强度应该消失，频率不应该“软掉”。

## 三、周期链路

### 敌人受击反馈链路

```text
Projectile 命中敌人
  ↓
IDamageable.TakeDamage(DamageInfo)
  ↓
Health 扣血并触发 OnDamaged
  ↓
DamageFlashView 闪白
  ↓
DamageNumberSpawner 从对象池取数字
  ↓
DamageNumberView 显示伤害、上浮、渐隐、回池
  ↓
SfxPlayer 播放命中音效
```

### 玩家受击反馈链路

```text
EnemyAI 接触攻击玩家
  ↓
playerHealth.TakeDamage(DamageInfo)
  ↓
Health.OnDamaged
  ↓
PlayerHitFeedbackView
  ↓
SfxPlayer.PlayHurt()
  ↓
CameraShakePlayer.Shake()
  ↓
CinemachineBasicMultiChannelPerlin 产生短促震动
```

### 伤害数字池化链路

```text
DamageNumberSpawner
  ↓
DamageNumberPoolProvider.DamageNumberPool
  ↓
ObjectPool.Get(position)
  ↓
DamageNumberView.Play(damage)
  ↓
播放结束 pool.Return(gameObject)
```

### Cinemachine 震屏链路

```text
CM_PlayerCamera
  ↓
CinemachineCamera + CinemachineFollow 负责基础跟随
  ↓
CinemachineBasicMultiChannelPerlin 负责 Noise 阶段修正
  ↓
CameraShakePlayer 临时提高 AmplitudeGain / FrequencyGain
  ↓
CinemachineBrain 输出最终 Main Camera 画面
```

## 四、设计思考

### 1. 为什么第19课优先做反馈，而不是继续堆系统？

第18课结束后，游戏已经有移动、战斗、掉落、背包、成长、波次。但如果没有命中闪烁、伤害数字、音效和震屏，玩家会觉得“系统在算，但游戏不说话”。

反馈快包的目标是让同一套系统立刻更像游戏。它不改变核心规则，却显著提高可读性、爽感和演示观感，是 Demo 冲刺期性价比极高的一课。

### 2. 为什么伤害数字要池化？

伤害数字是高频短生命周期对象。幸存者类战斗里，同屏敌人多、子弹多、命中频繁，如果每次命中都 Instantiate/Destroy，一个看似很小的 UI 表现会变成 GC 和性能尖刺来源。

所以它和敌人、子弹、经验球一样，应该走对象池。表现层也要遵守池化纪律：出池归零、回池停止协程、不要保留前世状态。

### 3. 为什么不用预制体直接拖场景对象池？

Unity 的 Prefab 不能稳定引用某个场景实例。敌人预制体上的 `DamageNumberSpawner` 如果需要对象池，就不能在预制体里硬拖场景里的 `DamageNumberPool`。

这节课选择 `DamageNumberPoolProvider`，本质是建立一个场景服务入口：Spawner 启动时找 Provider，再从 Provider 拿池。它比 `GameObject.Find("DamageNumberPool")` 更好，因为依赖的是类型和字段，不是脆弱的字符串名字。

### 4. 为什么音效用 SfxPlayer 集中管理？

短音效不应该散落在各个系统里各自拿 `AudioSource`。集中到 `SfxPlayer` 后，调用方只表达意图：开火、命中、拾取、升级、受伤、开箱。

这样后续要调音量、分组、静音、替换 Clip、做对象池音源，都有统一入口。

### 5. 为什么玩家受伤音效和震屏放进同一个反馈脚本？

它们都来自同一个事实：玩家 `Health.OnDamaged`。如果分别写两个脚本订阅同一个事件，当然也能工作，但当前 Demo 阶段一个 `PlayerHitFeedbackView` 更直观。

它的职责不是“处理伤害”，而是“把玩家受伤这件事翻译成表现反馈”。这符合表现层只消费事件、不改规则的边界。

### 6. 为什么 Cinemachine 震屏不能直接摇 Main Camera？

现在的相机结构是 `Main Camera + CinemachineBrain` 输出真实画面，`CM_PlayerCamera` 负责虚拟相机跟随。`Main Camera` 每帧都会被 Brain 接管，直接改它的 Transform 容易被覆盖或和 Cinemachine 打架。

使用 `CinemachineBasicMultiChannelPerlin` 是在 Cinemachine 管线内部增加 Noise 修正，属于“顺着系统走”，不是和系统抢控制权。

## 五、踩坑记录

### 1. 伤害数字一直出现在屏幕中间

- **现象**：敌人受击后数字出现，但位置固定在屏幕中间。
- **原因**：Canvas 使用了 Screen Space 模式，世界坐标没有真正参与显示。
- **处理**：伤害数字预制体改为 World Space Canvas，并使用世界坐标生成。
- **沉淀**：世界空间表现必须确认 Canvas Render Mode；UI 能显示不代表坐标语义正确。

### 2. 伤害数字没有正对屏幕

- **现象**：数字出现在敌人附近，但看起来是斜着的。
- **原因**：World Space Canvas 会保留自身旋转，不会自动面向摄像机。
- **处理**：`DamageNumberView` 每帧执行 `FaceCamera()`，令数字跟随主摄像机旋转。
- **沉淀**：World Space UI 常见三件套：世界坐标、合适缩放、Billboard 面向相机。

### 3. Cinemachine 震屏效果太弱，一开始像没生效

- **现象**：玩家受击后其实有震动，但幅度太低，肉眼不明显。
- **原因**：俯视相机距离较远，`AmplitudeGain = 0.5` 的画面反馈偏轻。
- **处理**：先用更夸张参数验证链路，再回调到舒适值。
- **沉淀**：表现调参先用“大到一定能看见”的值验链路，再缩回最终手感。

### 4. 反馈分支不能互相阻塞

- **现象风险**：如果 `sfx == null` 时直接 `return`，震屏也会被跳过。
- **处理**：音效用 `sfx?.PlayHurt()`，震屏单独判断 `cameraShakePlayer != null`。
- **沉淀**：一个反馈缺失不应该拖死另一个反馈；表现系统要尽量降级可用。

## 六、面试问答

**Q1：第19课解决的核心问题是什么？**  
> 解决战斗反馈不足的问题。已有系统能运转，但玩家需要通过闪色、伤害数字、音效、震屏快速理解“我打中了、我受伤了、我升级了、我打开了宝箱”。

**Q2：为什么伤害数字要用对象池？**  
> 因为命中反馈是高频短生命周期对象。用对象池可以避免频繁 Instantiate/Destroy 带来的 GC 和性能尖刺，尤其适合幸存者类同屏大量命中的场景。

**Q3：Prefab 不能拖场景对象时，你怎么处理依赖？**  
> 我用场景 Provider 暴露对象池。预制体上的 Spawner 在运行时通过 Provider 获取池引用，避免字符串查找，也避免 Prefab 直接依赖场景实例。

**Q4：为什么不直接 `GameObject.Find("DamageNumberPool")`？**  
> 名字查找依赖字符串，重命名就会断，而且语义不清。Provider 用类型和字段表达依赖，Inspector 也能看见引用，后续维护更稳。

**Q5：Cinemachine 下为什么不直接摇 Main Camera？**  
> 因为 Main Camera 被 CinemachineBrain 接管，直接改 Transform 容易被覆盖。应该在虚拟相机管线内部做 Noise 或 Impulse，让 Cinemachine 自己输出最终画面。

**Q6：Basic Multi Channel Perlin 和 Impulse 怎么取舍？**  
> Perlin 更适合当前 Demo 的轻量短震屏，接线少、调参直观。Impulse 更适合多来源、距离衰减、爆炸冲击这类可扩展镜头反馈，可以后续升级。

**Q7：表现层脚本能不能直接改伤害或血量？**  
> 不应该。表现层只订阅 `Health.OnDamaged` 并播放反馈，不改变战斗事实。这样规则层和表现层边界清楚，后续替换表现不会影响数值。

## 七、习惯清单

1. 反馈系统先找事实事件，比如 `Health.OnDamaged`，不要自己猜状态。
2. 高频短生命周期表现对象优先池化。
3. 池化对象新增运行期字段，同一分钟检查 `OnGetFromPool()` 和 `OnReturnPool()`。
4. Prefab 不能硬拖场景实例时，优先考虑 Provider 或场景服务入口。
5. 调表现先用夸张参数验链路，再回调到舒服值。
6. 缺音效、缺特效、缺震屏都应该独立降级，不互相拖死。
7. Cinemachine 项目里，镜头反馈尽量走 Cinemachine 管线，不直接抢 Main Camera。
8. 世界空间 UI 先查 Render Mode、Scale、Billboard。

## 八、思考题（附复习参考）

**Q1：如果以后要做暴击数字，应该怎么扩展？**  
> 不要在 `DamageNumberView` 里硬判断“暴击”。更好的方式是让 `DamageInfo` 或后续战斗结果包携带是否暴击、伤害类型等信息，Spawner 根据结果选择样式，View 负责展示样式。

**Q2：如果后续音效越来越多，`SfxPlayer` 会不会变胖？**  
> 会。当前 Demo 阶段集中管理是高性价比方案。后续可以拆成 AudioEvent、AudioMixer 分组、音量设置、音源池，或者用事件总线把规则层和音频层进一步解耦。

**Q3：为什么受伤震屏不接在敌人攻击脚本里？**  
> 因为敌人攻击只是伤害来源之一。危险区、Boss、陷阱以后也可能伤害玩家。订阅玩家 `Health.OnDamaged`，能覆盖所有伤害来源。

**Q4：为什么敌人受击不做震屏？**  
> 自动武器命中频率很高，如果每次敌人受击都震屏，画面会脏且累。震屏应该服务重要事件，比如玩家受伤、开箱、升级确认、Boss 冲击。

**Q5：如果伤害数字偶尔不消失，第一时间查哪里？**  
> 查协程生命周期和对象池回收：`playRoutine` 是否停止并置空，`OnReturnPool()` 是否停止旧协程，`OnGetFromPool()` 是否重置 alpha、文本、位置/旋转相关状态。
