# 第30课 · 攻击芯片效果实装

> 课程周期：2026-08-05  
> 前置：第29课《武器稀有度与等级差异》  
> 关键词：DamageBoost、攻击芯片、邻接效果、真实激活武器、四乘区、封顶

---

## 一、这节课实现了什么

第30课把 `AttackDamageChip` 从 Tooltip 上的数值，推进成真正影响战斗的构筑件。  
现在攻击芯片只有在满足邻接规则、进入 `validEffects`、并且贴到真实激活武器上时，才会增加那把武器的单发伤害。

本课完成后，自动武器最终伤害已经形成四个乘区：

```text
武器 prefab 基础伤害
  × 玩家升级伤害倍率
  × 武器稀有度 / 等级倍率
  × 攻击芯片邻接倍率
```

这节课的核心不是“多加一个 if”，而是把 DamageBoost 接进现有的邻接体系：

```text
AdjacencyRuleBook
  ↓
InventoryGrid.ScanAdjacency()
  ↓
AdjacencyEffectResolver.ResolveValidEffects()
  ↓
BackpackWeaponActivator.Apply
  ↓
WeaponBase.Fire()
```

### 任务 1 · 新增 DamageBoost 效果 ID

- `AdjacencyEffectId` 新增 `DamageBoost`。
- DamageBoost 和 FireRateBoost 一样属于正向攻击类效果。
- 继续使用 enum，而不是字符串，避免拼写错误导致规则静默失效。

这一步让规则表可以明确表达“这条邻接不是双持，也不是攻速，而是攻击伤害加成”。

### 任务 2 · 在规则表中加入攻击芯片邻接规则

- `AdjacencyRuleBook` 新增武器与 `AttackDamageChip` 的邻接规则。
- 手枪、步枪、霰弹枪都能通过攻击芯片获得伤害加成。
- 规则仍然是标签 + 方向共同决定，不做“四边万能芯片”。
- 旋转后的接口方向继续由第28课的 `GetWorldSides()` 统一处理。

这一步保证攻击芯片仍然服务背包摆放决策，而不是变成随便贴哪里都生效的全局装备。

### 任务 3 · Resolver 放行 DamageBoost

- `AdjacencyEffectResolver.ResolveValidEffects()` 新增 `AddValidDamageBoostEffects()`。
- 第一版 DamageBoost 与 FireRateBoost 一样全部放行。
- DualWield 仍然有独立互斥规则，DamageBoost 不复用 DualWield 的“物品最多参与一组”逻辑。

为什么这样设计：攻击芯片天生适合叠加；如果以后要限制层数，应该在应用层用封顶或策略处理，而不是直接把候选效果删掉。

### 任务 4 · WeaponBase 增加攻击芯片乘区

- `WeaponBase` 新增 `backpackDamageBoostMultiplier`，默认 `1f`。
- 新增 `SetBackpackDamageBoostMultiplier(float multiplier)`。
- `Fire()` 中最终伤害公式接入攻击芯片乘区。

现在伤害来源清晰分层：

```text
PlayerRunStats.DamageMultiplier       = 玩家升级乘区
backpackWeaponMultiplier              = 武器稀有度 / 等级乘区
backpackDamageBoostMultiplier         = 邻接攻击芯片乘区
```

这比把所有伤害加成混在一个字段里更好调，也更适合面试讲系统分层。

### 任务 5 · BackpackWeaponActivator 应用 DamageBoost

- 新增 `maxBackpackDamageBoostMultiplier`，用于限制攻击芯片倍率上限。
- `RefreshActiveWeapons()` 在 DualWield 和 FireRateBoost 之后调用 `ActivateDamageBoost(validEffects)`。
- `ActivateDamageBoost()` 遍历真实有效效果，只处理 `EffectId == DamageBoost`。
- 通过 `TryGetActiveAutoWeapon(effect.ItemA / effect.ItemB)` 判断哪一侧是已激活武器。
- 另一侧视为芯片，读取它的 `EffectValue` 并按具体 `AutoWeapon` 累加。
- 最终写入 `autoWeapon.SetBackpackDamageBoostMultiplier(damageMultiplier)`。

这一步保证攻击芯片只作用于真实激活武器。  
背包里没被激活的武器，即使旁边有芯片，也不会偷偷给当前武器加成。

### 任务 6 · 重置旧芯片倍率，防止残留

- `DeactivateAllWeapons()` 重置三类倍率：

```text
SetBackpackFireRateMultiplier(1f)
SetBackpackWeaponMultiplier(1f)
SetBackpackDamageBoostMultiplier(1f)
```

- 同时给 `AutoWeapon` 获取结果加空判断，避免槽位接错对象时刷新 NRE。

这是本课一个重要习惯：凡是刷新前会“先关再开”的系统，旧状态必须清干净。  
否则拿走芯片后，武器可能继续吃旧伤害倍率。

### 任务 7 · Tooltip 区分攻速芯片和伤害芯片

- `Magazine` 显示“攻速 +xx%”。
- `AttackDamageChip` 显示“伤害 +xx%”。
- 武器仍然显示武器品质/等级带来的“伤害提升 +xx%”。
- 收集品继续只显示价值、尺寸和稀有度。

玩家现在能区分三类收益：

```text
武器本体为什么强
弹匣芯片加的是攻速
攻击芯片加的是伤害
```

### 任务 8 · 最终验收通过

本课已通过用户实测：

- 攻击芯片不邻接时，不增加伤害。
- 攻击芯片贴对方向后，金色接口生效，伤害数字变高。
- 拿走或换位后，伤害倍率回落，不残留旧加成。
- DamageBoost 与 FireRateBoost 分别影响伤害和攻速，不互相污染。
- 武器品质/等级乘区、玩家升级乘区、攻击芯片乘区可以同时工作。

## 二、最终代码（关键片段）

### 1. AdjacencyEffectId 新增 DamageBoost

```csharp
public enum AdjacencyEffectId
{
    None = 0,
    DualWield,
    FireRateBoost,
    CritBoost,
    HazardResistBoost,
    BurningBullets,
    DamageBoost
}
```

效果 ID 是规则系统的语言。  
新增 DamageBoost 后，规则、Resolver 和战斗应用层都能围绕同一个标识工作。

### 2. 规则表加入攻击芯片邻接

```csharp
new AdjacencyRule(
ItemTag.Pistol,
ConnectableSides.Left,
ItemTag.AttackDamageChip,
ConnectableSides.Up,
AdjacencyEffectId.DamageBoost),

new AdjacencyRule(
ItemTag.Rifle,
ConnectableSides.Up,
ItemTag.AttackDamageChip,
ConnectableSides.Down,
AdjacencyEffectId.DamageBoost),
```

实际规则表还覆盖了手枪、步枪和霰弹枪。  
重点是规则仍然由 `ItemTag + ConnectableSides + EffectId` 三件事共同定义。

### 3. Resolver 放行 DamageBoost

```csharp
public static List<AdjacencyEffect> ResolveValidEffects(List<AdjacencyEffect> candidateEffects)
{
    List<AdjacencyEffect> validEffects = new List<AdjacencyEffect>();

    if (candidateEffects == null) return validEffects;

    AddValidDualWieldEffects(candidateEffects, validEffects);
    AddValidFireRateBoostEffects(candidateEffects, validEffects);
    AddValidDamageBoostEffects(candidateEffects, validEffects);

    return validEffects;
}
```

DamageBoost 第一版不做互斥，只进入真实效果列表。  
后续如果需要层数上限，不要在这里简单删掉，而应该在应用层做封顶或策略控制。

### 4. AddValidDamageBoostEffects

```csharp
private static void AddValidDamageBoostEffects(
    List<AdjacencyEffect> candidateEffects,
    List<AdjacencyEffect> validEffects)
{
    foreach (AdjacencyEffect effect in candidateEffects)
    {
        if (effect == null) continue;
        if (effect.EffectId != AdjacencyEffectId.DamageBoost) continue;

        validEffects.Add(effect);
    }
}
```

这和 FireRateBoost 的放行方式一致。  
区别不在 Resolver，而在最终应用到武器时进入不同乘区。

### 5. WeaponBase 接入攻击芯片乘区

```csharp
protected float backpackWeaponMultiplier = 1f;
protected float backpackDamageBoostMultiplier = 1f;

protected void Fire(Vector3 direction)
{
    sfx?.PlayShoot();

    float rawDamage = damage
        * stats.DamageMultiplier
        * backpackWeaponMultiplier
        * backpackDamageBoostMultiplier;

    // 后续 Projectile.Initialize 使用 RoundToInt 后的 finalDamage
}
```

这一步让攻击芯片成为真实战斗数值，而不是 UI 文案。  
伤害数字会直接反映这个乘区。

### 6. WeaponBase 暴露 DamageBoost 写入口

```csharp
public void SetBackpackDamageBoostMultiplier(float multiplier)
{
    backpackDamageBoostMultiplier = Mathf.Max(1f, multiplier);
}
```

当前 Demo 中攻击芯片只增强，不做负面词条。  
所以倍率下限仍然是 `1f`。

### 7. DeactivateAllWeapons 重置三类背包倍率

```csharp
AutoWeapon autoWeapon = weapon.WeaponObject.GetComponent<AutoWeapon>();
if (autoWeapon != null)
{
    autoWeapon.SetBackpackFireRateMultiplier(1f);
    autoWeapon.SetBackpackWeaponMultiplier(1f);
    autoWeapon.SetBackpackDamageBoostMultiplier(1f);
}
weapon.WeaponObject.SetActive(false);
```

刷新背包武器时必须先清旧状态。  
否则旧布局的芯片倍率会残留到新布局。

### 8. ActivateDamageBoost 按激活武器累加芯片收益

```csharp
private void ActivateDamageBoost(List<AdjacencyEffect> validEffects)
{
    if (validEffects == null) return;

    Dictionary<AutoWeapon, float> damageBonusByWeapon = new Dictionary<AutoWeapon, float>();

    foreach (AdjacencyEffect effect in validEffects)
    {
        if (effect == null) continue;
        if (effect.EffectId != AdjacencyEffectId.DamageBoost) continue;

        if (TryGetActiveAutoWeapon(effect.ItemA, out AutoWeapon autoWeaponA))
        {
            float effectValue = effect.ItemB.EffectValue;
            if (damageBonusByWeapon.ContainsKey(autoWeaponA))
                damageBonusByWeapon[autoWeaponA] += effectValue;
            else
                damageBonusByWeapon[autoWeaponA] = effectValue;
        }
        else if (TryGetActiveAutoWeapon(effect.ItemB, out AutoWeapon autoWeaponB))
        {
            float effectValue = effect.ItemA.EffectValue;
            if (damageBonusByWeapon.ContainsKey(autoWeaponB))
                damageBonusByWeapon[autoWeaponB] += effectValue;
            else
                damageBonusByWeapon[autoWeaponB] = effectValue;
        }
    }

    foreach (var kvp in damageBonusByWeapon)
    {
        AutoWeapon autoWeapon = kvp.Key;
        float effectValues = kvp.Value;

        float damageMultiplier = 1f + effectValues;
        damageMultiplier = Mathf.Min(damageMultiplier, maxBackpackDamageBoostMultiplier);
        autoWeapon.SetBackpackDamageBoostMultiplier(damageMultiplier);
    }
}
```

这里沿用了 FireRateBoost 的模式：先按具体 `AutoWeapon` 累加，再统一写回倍率。  
这样同一把激活武器可以吃多个芯片，但会被上限控制。

### 9. Tooltip 区分芯片类型

```csharp
if (item.Tag == ItemTag.Magazine)
{
    bodyText.text = $"...\n攻速: +{percent}%";
}
else if (item.Tag == ItemTag.AttackDamageChip)
{
    bodyText.text = $"...\n伤害: +{percent}%";
}
```

这一步把“效果 +xx%”拆成了具体含义。  
玩家能更快理解芯片应该贴给哪类武器。

## 三、周期链路

### 规则发现链路

```text
武器与 AttackDamageChip 相邻
  ↓
InventoryGrid.ScanAdjacency(AdjacencyRuleBook.Rules)
  ↓
方向、标签、规则匹配成功
  ↓
生成候选 AdjacencyEffect(DamageBoost)
```

### 有效效果链路

```text
candidateEffects
  ↓
AdjacencyEffectResolver.ResolveValidEffects()
  ↓
DualWield 做互斥
FireRateBoost 放行
DamageBoost 放行
  ↓
validEffects
```

### 战斗应用链路

```text
BackpackWeaponActivator.RefreshActiveWeapons()
  ↓
DeactivateAllWeapons 清旧倍率
  ↓
TryActivateItem 激活真实武器并注入武器品质倍率
  ↓
ActivateFireRateBoost 应用攻速芯片
  ↓
ActivateDamageBoost 应用攻击芯片
```

### DamageBoost 作用对象链路

```text
AdjacencyEffect(ItemA, ItemB)
  ↓
TryGetActiveAutoWeapon(ItemA / ItemB)
  ↓
找到已激活武器一侧
  ↓
另一侧读取 EffectValue
  ↓
按 AutoWeapon 累加伤害芯片收益
```

### 最终伤害链路

```text
damage
  × PlayerRunStats.DamageMultiplier
  × backpackWeaponMultiplier
  × backpackDamageBoostMultiplier
  ↓
Mathf.RoundToInt
  ↓
Projectile.Initialize(finalDamage)
```

## 四、设计思考

### 1. 为什么 DamageBoost 不直接加到 PlayerRunStats？

`PlayerRunStats` 是玩家升级系统的事实源。  
攻击芯片来自背包邻接，应该随背包布局变化而变化。

如果把芯片加成写进 `PlayerRunStats`，拿走芯片、换位置、丢弃武器时就很难还原。  
现在芯片倍率挂在 `AutoWeapon` 上，背包每次刷新都会重新计算，状态边界更清楚。

### 2. 为什么 DamageBoost 只作用于真实激活武器？

背包里可能有很多武器，但当前能在玩家身边生成的只有被激活的那几把。  
如果未激活武器旁边的芯片也给当前武器加成，玩家就会觉得规则不透明。

现在逻辑是：

```text
只有 TryGetActiveAutoWeapon 成功的那侧，才是可被加成的武器
```

这让构筑判断和可见结果一致。

### 3. 为什么 DamageBoost 和 FireRateBoost 分开乘区？

攻速和伤害影响的是两个不同维度：

```text
DamageBoost 提高单发伤害
FireRateBoost 提高单位时间开火次数
```

它们最终都会影响 DPS，但玩家体感不同，平衡手段也不同。  
分开乘区以后，可以单独封顶、单独调值、单独写 Tooltip。

### 4. 为什么 DamageBoost 适合可叠加？

攻击芯片是构筑深度的来源之一。  
允许多个芯片叠加，可以让玩家为了极限输出牺牲背包空间。

但叠加必须有上限。  
本课通过 `maxBackpackDamageBoostMultiplier` 控制最大倍率，避免玩家堆满芯片后直接打穿 15 分钟平衡。

### 5. 为什么重置旧倍率这么重要？

背包武器激活器采用“先全关，再重新激活”的刷新策略。  
这种策略的好处是简单稳定，但前提是每次全关时必须清掉旧运行时状态。

本课新增 DamageBoost 后，如果不在 `DeactivateAllWeapons()` 里重置它，就会出现：

```text
旧布局有攻击芯片
  ↓
拿走芯片
  ↓
武器仍然保留旧伤害倍率
```

所以新增任何运行时倍率，都要同步进入重置流程。

### 6. 为什么 Tooltip 要写“攻速”和“伤害”，而不是统一“效果”？

泛泛的“效果 +20%”对玩家没有决策价值。  
背包构筑游戏里，玩家需要快速知道：

```text
这个东西提升什么？
应该贴给谁？
值不值得占格子？
```

所以 Tooltip 必须用具体词：攻速、伤害、价值、武器伤害提升。

## 五、踩坑记录

### 1. 新增倍率后必须加入重置流程

- **现象风险**：拿走攻击芯片后，武器仍然保留旧伤害倍率。
- **根因**：`DeactivateAllWeapons()` 最初只重置攻速倍率和武器品质倍率，没有重置新加的攻击芯片倍率。
- **修复**：关闭武器时同步调用 `SetBackpackDamageBoostMultiplier(1f)`。
- **沉淀**：新增运行时状态的同一分钟，必须找到所有重置入口。

### 2. 邻接方向必须是一对接触边

- **现象风险**：规则表看起来写了 DamageBoost，但默认摆放时金边不亮。
- **根因**：相邻接触边必须成对互补，例如 `Weapon.Up + Chip.Down`，不能把两边都写成 `Up`。
- **修复**：按实际摆法修正武器与攻击芯片的方向规则。
- **沉淀**：规则方向不是“物品想要的方向”，而是“两个物品实际贴住的那两条边”。

### 3. 芯片效果不能影响未激活武器

- **现象风险**：背包里未激活武器旁边的芯片也影响当前武器，玩家无法理解收益来源。
- **根因**：如果只看邻接效果，不看 `activeWeaponsByItem`，就会把所有背包效果都当成战斗效果。
- **修复**：应用 DamageBoost 时必须先 `TryGetActiveAutoWeapon()`，只给真实激活武器写倍率。
- **沉淀**：背包效果从“检测到”到“战斗生效”，中间必须经过激活状态过滤。

### 4. Tooltip 文案过泛会削弱构筑判断

- **现象风险**：玩家看到“效果 +20%”，但不知道是伤害、攻速还是其他属性。
- **根因**：早期 Tooltip 为了快，把芯片效果统一写成“效果”。
- **修复**：`Magazine` 显示攻速，`AttackDamageChip` 显示伤害。
- **沉淀**：数值反馈要告诉玩家“加了什么”，不只是“加了多少”。

## 六、面试问答

**Q1：你是怎么实现攻击芯片的？**  
> 我没有在武器逻辑里写物品特判，而是把攻击芯片接进邻接系统。规则表产出 `DamageBoost` 候选效果，Resolver 放行真实有效效果，`BackpackWeaponActivator` 再判断哪一侧是已激活武器，把另一侧芯片的 `EffectValue` 累加成伤害倍率，最后写入 `WeaponBase`。

**Q2：为什么 DamageBoost 不直接写到 PlayerRunStats？**  
> 因为它不是玩家升级效果，而是背包布局效果。它应该随着物品摆放、拿起、丢弃、合并即时变化。写到 `AutoWeapon` 的背包倍率里，可以每次背包刷新重新计算，避免状态残留。

**Q3：你现在的伤害公式是什么？**  
> 当前是 `damage × PlayerRunStats.DamageMultiplier × backpackWeaponMultiplier × backpackDamageBoostMultiplier`。分别代表武器基础值、玩家升级乘区、武器品质/等级乘区和攻击芯片乘区。

**Q4：DamageBoost 和 FireRateBoost 为什么分开处理？**  
> 它们都来自邻接系统，但影响的战斗维度不同。FireRateBoost 改攻击间隔，DamageBoost 改单发伤害。分开处理可以独立封顶、独立调参，也能让 Tooltip 讲清楚。

**Q5：为什么只给已激活武器应用芯片？**  
> 因为自动武器有激活上限，背包里未激活武器不应该参与当前战斗输出。芯片收益必须绑定到真实生成出来的武器，否则玩家很难理解收益来源，也会绕过激活上限设计。

**Q6：为什么需要 maxBackpackDamageBoostMultiplier？**  
> 因为现在已经有武器品质、武器等级、玩家升级和芯片多个乘区。没有封顶时，多个 DamageBoost 很容易把后期怪物血量打穿。封顶是 Demo 阶段最直接的平衡保险。

**Q7：这套结构以后怎么扩展 CritBoost？**  
> 可以继续沿用同一条链：规则表新增 CritBoost 规则，Resolver 放行或做层数策略，Activator 按激活武器累计暴击属性，WeaponBase 或子弹伤害管线再消费暴击参数。关键是不把 CritBoost 写成散落在各处的 if-else。

## 七、习惯清单

1. 新增邻接效果时，按 EffectId → RuleBook → Resolver → Activator → 消费端顺序接线。
2. 新增运行时倍率时，同步加入刷新/关闭/回池重置流程。
3. 背包效果必须经过“真实激活武器”过滤，不能全局偷加。
4. 攻速、伤害、品质、玩家升级要分乘区，不要混成一个字段。
5. 可叠加效果必须设计上限，先有保险再调数值。
6. Tooltip 要解释具体属性，不写泛泛的“效果”。
7. 邻接方向按实际接触边写，接触边通常成对互补。
8. 复制已有模式时，要复制结构，不复制错误注释。
9. Demo 冲刺期优先做能被伤害数字、金边、手感立刻验证的功能。

## 八、思考题（附复习参考）

**Q1：如果攻击芯片可以同时贴多把武器，要怎么避免同一个芯片被重复计入？**  
> 需要在 Resolver 或 Activator 中设计“芯片实例使用规则”。如果一个芯片只能服务一把武器，就用 `HashSet<Item>` 标记已使用芯片；如果允许多服务，就要明确写进设计，并通过更高价值/更大占格来平衡。

**Q2：如果以后要显示当前武器总 DPS，应该在哪里算？**  
> 不建议在 Tooltip 临时拼。更合适的是让武器或一个 CombatStatPreview 读取相同事实源：基础伤害、玩家倍率、武器倍率、芯片倍率和攻速倍率，统一生成预览，避免 UI 和战斗公式分叉。

**Q3：为什么 DamageBoost 第一版可以全部放行？**  
> 因为它的上限目前由 `maxBackpackDamageBoostMultiplier` 控制，且 Demo 阶段需要先验证“能叠、能封顶、能生效”。复杂互斥策略可以等芯片种类变多后再数据化。

**Q4：如果拿走芯片后伤害不回落，第一时间查哪里？**  
> 先查 `DeactivateAllWeapons()` 是否重置了 `backpackDamageBoostMultiplier`，再查 `InventoryGrid.OnChanged` 是否触发，最后查 `ActivateDamageBoost()` 是否仍然从 validEffects 中读到了旧效果。

**Q5：为什么说这节课让构筑深度更明显？**  
> 因为玩家现在可以围绕一把高品质武器继续贴攻击芯片，芯片收益会和武器品质、武器等级、玩家升级互相放大。背包位置不再只是收纳，而是输出策略的一部分。
