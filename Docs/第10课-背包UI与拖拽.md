## 一、这节课实现了什么

背包第一次"活了"：捡起的掉落物自动入包并显示在 6×8 网格 UI 上，支持鼠标拖拽整理、红绿合法性预览、非法位置回弹。

| 产物 | 说明 |
|------|------|
| Canvas 三层结构 | BagPanel（底框）→ CellLayer（48 格背景，Grid Layout Group）→ ItemLayer（物品层，pivot 左上角） |
| `InventoryUIController` | 投影渲染器：订阅 OnChanged 全量重绘；拖拽三部曲（BeginDrag/Dragging/EndDrag） |
| `ItemView` | 物品色块：Bind(Item) 设尺寸/文字/稀有度色；三个指针接口当传声筒；SetValidColor 红绿预览 |
| `InventorySystem` | 背包唯一主人：持有 Grid，订阅 DropItem.OnCollected，TryFindFreeArea 自动入包 |
| `Rarity` 枚举搬迁 | 从 BS.Data 下沉到 BS.Inventory（程序集方向规则所迫），Item 长出 Rarity 属性 |
| `LootEntry` 扩容 | +id/width/height 字段，掉落物从此有完整的入包身份信息 |
| `InventoryGrid` 补强 | +索引器（只读窗口）、+TryGetAnchor（拖拽定位） |
| PickupLogger | 正式退役删除 |

## 二、最终代码

### InventoryUIController.cs（投影渲染器 + 拖拽）

```csharp
using UnityEngine;
using BS.Inventory;
using BS.GamePlay;

namespace BS.Presentation
{
    public class InventoryUIController : MonoBehaviour
    {
        [SerializeField] private RectTransform itemLayer;    // 拖 ItemLayer
        [SerializeField] private ItemView itemViewPrefab;    // 拖预制体
        [SerializeField] private float step = 66f;           // 64格 + 2缝
        [SerializeField] private InventorySystem inventorySystem;

        private InventoryGrid grid;
        private bool isDragging = false;

        //拖拽相关
        private Item dragItem;
        private ItemView ghost;// 被拖的那个视图
        private int oldX, oldY;// 旧锚点（回滚用）
        private int targetX, targetY;// 当前鼠标悬停的目标格子

        private void Start()
        {
            grid = inventorySystem.Grid;   // 不 new！向唯一主人要引用
            grid.OnChanged += Redraw;
            Redraw();
        }

        private void Redraw()
        {
            if (isDragging) return;// 拖拽期间，数据变化攒着不画（门闸）

            DestroyAllChilden(itemLayer);//清场：销毁 itemLayer 所有子物体

            //全量重绘：按照数据重新生成一遍
            for (int y = 0; y < grid.Height; y++)
            {
                for (int x = 0; x < grid.Width; x++)
                {
                    Item item = grid[x, y];
                    if (item == null) continue;

                    // 锚点探测：左边或上边有同物品的格子都不是锚点
                    if (x > 0 && grid[x - 1, y] == item) continue;
                    if (y > 0 && grid[x, y - 1] == item) continue;

                    ItemView itemView = Instantiate(itemViewPrefab, itemLayer);
                    RectTransform rect = itemView.GetComponent<RectTransform>();
                    rect.anchoredPosition = new Vector2(x * step, -y * step);// y 翻转只此一处
                    itemView.Bind(item, step);
                }
            }
        }

        public void BeginDrag(Item item, ItemView view)
        {
            if (!grid.TryGetAnchor(item, out oldX, out oldY)) return;
            targetX = oldX; targetY = oldY;   // 关键：未拖动 = 放回原地
            dragItem = item;
            ghost = view;
            isDragging = true;                 // 先关门闸
            grid.Remove(item);                 // 再拿起（Redraw 被拦住，ghost 不死）
            ghost.transform.SetAsLastSibling();
        }

        public void Dragging(Vector2 pointerPos)
        {
            if (!isDragging || ghost == null) return;

            ghost.transform.position = pointerPos;

            RectTransformUtility.ScreenPointToLocalPointInRectangle(
                itemLayer, pointerPos, null, out Vector2 localPos);
            targetX = Mathf.FloorToInt(localPos.x / step);
            targetY = Mathf.FloorToInt(-localPos.y / step);// y 翻转

            ghost.SetValidColor(grid.CanPlaceAt(targetX, targetY, dragItem));
        }

        public void EndDrag()
        {
            if (!isDragging) return;
            isDragging = false;

            if (grid.CanPlaceAt(targetX, targetY, dragItem))
                grid.Place(targetX, targetY, dragItem);   // 合法落位
            else
                grid.Place(oldX, oldY, dragItem);          // 回滚（必成功：格子被自己腾空）

            dragItem = null;
            ghost = null;   // ghost 在 Place 触发的 Redraw 中销毁重建
        }

        private void DestroyAllChilden(RectTransform parent)
        {
            for (int i = parent.childCount - 1; i >= 0; i--)
                Destroy(parent.GetChild(i).gameObject);
        }
    }
}
```

### ItemView.cs（木偶 + 传声筒）

```csharp
using BS.Inventory;
using TMPro;
using UnityEngine;
using UnityEngine.EventSystems;
using UnityEngine.UI;

namespace BS.Presentation
{
    public class ItemView : MonoBehaviour, IPointerDownHandler, IDragHandler, IPointerUpHandler
    {
        [SerializeField] private Image bg;
        [SerializeField] private TextMeshProUGUI label;

        private Item item;
        public Item Item => item;

        private InventoryUIController controller;

        private void Start()
        {
            // 预制体不能引用场景物体，运行时查找是正道
            controller = FindAnyObjectByType<InventoryUIController>();
        }

        public void Bind(Item item, float step)
        {
            this.item = item;
            label.text = item.Id;
            GetComponent<RectTransform>().sizeDelta =
                new Vector2(item.Width * step, item.Height * step);
            switch (item.Rarity)   // 白绿蓝紫金，同 GDD 色表
            {
                case Rarity.Common:    bg.color = Color.white; break;
                case Rarity.Uncommon:  bg.color = Color.green; break;
                case Rarity.Rare:      bg.color = Color.blue; break;
                case Rarity.Epic:      bg.color = new Color(0.6f, 0.2f, 0.9f); break;
                case Rarity.Legendary: bg.color = new Color(1f, 0.84f, 0f); break;
            }
        }

        public void OnPointerDown(PointerEventData e) => controller.BeginDrag(item, this);
        public void OnDrag(PointerEventData e)       => controller.Dragging(e.position);
        public void OnPointerUp(PointerEventData e)  => controller.EndDrag();

        public void SetValidColor(bool canPlace)
        {
            bg.color = canPlace
                ? new Color(0.1f, 0.55f, 0.15f, 0.8f)   // 暗绿
                : new Color(0.6f, 0.12f, 0.12f, 0.8f);  // 暗红
        }
    }
}
```

### InventorySystem.cs（背包唯一主人）

```csharp
using BS.GamePlay.Loot;
using BS.Inventory;
using UnityEngine;
using static BS.Data.LootTableData;

namespace BS.GamePlay
{
    public class InventorySystem : MonoBehaviour
    {
        public InventoryGrid Grid { get; private set; }

        private void Awake()
        {
            Grid = new InventoryGrid(6, 8);   // 全项目唯一的 new
        }

        private void OnEnable()  => DropItem.OnCollected += HandleCollected;
        private void OnDisable() => DropItem.OnCollected -= HandleCollected;

        private void HandleCollected(LootEntry entry)
        {
            if (entry == null) return;
            Item item = new Item(entry.id, entry.rarity, entry.width, entry.height);
            if (Grid.TryFindFreeArea(item, out int x, out int y))
                Grid.Place(x, y, item);
            else
                Debug.Log("背包已满");   // 吐回地上（LootManager.SpawnEntry）为可选增强
        }
    }
}
```

// InventoryGrid：拖拽定位锚点（第一个扫到的必然是左上角）
public bool TryGetAnchor(Item item, out int x, out int y)
{
    for (int j = 0; j < Height; j++)
        for (int i = 0; i < Width; i++)
            if (cells[i, j] == item) { x = i; y = j; return true; }
    x = -1; y = -1; return false;
}

## 三、周期链路

### 拾取入包链路（全自动化）

```
怪物死 → Die() → TrySpawnDrop → 掉落物磁吸 → Collect()
 → OnCollected(LootEntry) 广播
 → InventorySystem.HandleCollected：new Item → TryFindFreeArea → Place
 → OnChanged → InventoryUIController.Redraw（全量重画）
 → 色块出现在网格里（尺寸=宽高×step，颜色=稀有度）
```

### 拖拽链路（三态 + 回滚）

```
PointerDown：TryGetAnchor 记旧锚点 → target 初始化为旧锚点 → 门闸关闭 → Remove（数据离包）
Drag：ghost 跟手 → pointerPos 换算格坐标（y翻转）→ CanPlaceAt 实时问 → 绿/红
PointerUp：门闸打开 → 合法 Place(新) / 非法 Place(旧锚点回滚)
 → OnChanged → Redraw 重画（ghost 寿终正寝，视图重生）
```

## 四、设计思考（这节课真正学的东西）

### 1. UI 只是投影 = 单一事实源

InventoryUIController 不记任何"背包里有什么"，它只在 OnChanged 时把数据重画一遍。UI 可销毁、可重建、可整个删掉换 UI Toolkit——数据层毫发无损。**状态只有一个家，视图都是租客。**

### 2. 拿起即 Remove 的连环妙处

拖拽第一步把物品从数据层 Remove：① 原格腾空，回滚永远合法；② 预览时不会"自己挡自己"；③ 若拖拽中数据变化（捡新物品），门闸挂起重绘，松手时一次统一刷新——三种麻烦一面墙全挡了。

### 3. 程序集引用是有方向的（Rarity 搬迁记）

Assembly-CSharp 能引用 BS.Inventory（Auto Referenced），**反之永不可能**。Item 想认识 Rarity，唯一出路是 Rarity 下沉到 BS.Inventory。通用法则：**共享概念住最底层，依赖箭头永远朝下**。这是大型项目防架构腐化的结构性武器。

### 4. 索引器：给封装开一扇只读窗

`public Item this[int x, int y] => GetItemAt(x, y);`——外界读起来像数组 `grid[x,y]`，但写不进去（编译错），写入仍走 Place/Remove 且必发事件。比"公开 cells 字段"高明在一个**只读**。

### 5. 输入 API 要跟着项目配置走

项目用新 Input System 且禁用了旧 API，`Input.mousePosition` 一调就炸。而 `PointerEventData.position` 自带光标坐标——**UI 事件流里泡着的数据，伸手就有，别去别处查**。

## 五、踩坑记录

| 坑 | 根因 | 教训 |
|----|------|------|
| ItemLayer 被当成第 49 个格子 | Grid Layout Group 接管**所有直属子物体** | 排版组件和免排版的层必须分开当父子，分层结构：BagPanel → CellLayer + ItemLayer |
| 拖哪都回弹（第一次） | ItemLayer pivot 在中心，ScreenPointToLocalPoint 原点在面板正中，换算偏半屏 | **localPos 原点在 pivot**。UI 数学前先确认 pivot；ItemLayer 改 (0,1) |
| 拖哪都回弹（第二次） | `Input.mousePosition` 在新输入系统下抛异常，方法中断，target 永不更新 | **异常中断行之后的代码不执行**；修复查全所有调用点，改一半等于没改 |
| 红色预览不出现 | SetValidColor 被 `if(canPlace)` 包裹，三元红分支被杀死 | 条件别套条件；写完问自己"else 路径跑过吗" |
| controller 序列化字段恒 null | **预制体资产不能引用场景物体** | 运行时查找（FindAnyObjectByType / 事件注册）才是预制体的找对象方式 |
| 新旧输入系统冲突 | 项目 Active Input Handling 只开了新系统 | 用 API 前先想项目配置；UI 拖拽用 PointerEventData.position 零依赖 |
| Inspector 报 m_Targets MissingReference | Inspector 选中着被 Destroy 的视图 | 编辑器怨念，无害；点别处即消 |

## 六、面试问答

**Q：背包 UI 怎么和数据同步？**
A：数据层发 OnChanged 事件，UI 订阅后全量重绘。48 格规模全量重画无压力；量级上去再考虑脏标记+局部刷新。核心是让 UI 成为可随时重建的投影，绝不持有玩法状态。

**Q：拖拽放到非法位置怎么保证物品不丢？**
A："拿起即 Remove + 旧锚点记忆 + 松手校验"：按下时记录锚点并从数据层移除（原格腾空保证回滚必成功），松手时 CanPlaceAt 校验，失败则 Place 回旧锚点。回滚路径必须数学上不可能失败。

**Q：uGUI 的渲染顺序由什么决定？**
A：Hierarchy 兄弟顺序，越靠下越晚绘制、越在上层。没有 z 深度概念。拖拽中的 ghost 用 SetAsLastSibling 置顶。

**Q：ScreenPointToLocalPointInRectangle 的原点在哪？**
A：目标 RectTransform 的 **pivot**。pivot 在中心，返回的 localPoint 就是中心原点——做格子换算前必须确认 pivot，或自行加半尺寸偏移。

**Q：新旧 Input System 混用会怎样？**
A：Active Input Handling 只开新系统时，旧 `UnityEngine.Input` 全部 API 抛 InvalidOperationException。要么统一新 API，要么 UI 事件用 PointerEventData 自带数据，绕开输入栈。

**Q：asmdef 之间的引用规则？**
A：自定义程序集之间靠 References 显式声明；Assembly-CSharp 自动引用所有 Auto Referenced 的 asmdef，**反向永不可能**。共享类型必须下沉到最底层程序集。

## 七、习惯清单

- [x] UI 不存玩法状态，一切问数据层（预览都用 CanPlaceAt 实时查）
- [x] 排版组件（Grid Layout）与自由层分父子，渲染顺序靠兄弟排序
- [x] 做 UI 数学前先看 pivot；y 翻转全项目只许出现一次
- [x] 异常中断排查法：报错行之后的代码都没跑，症状从"最后执行到哪"推
- [x] 预制体不引用场景物体，运行时再找
- [x] 控制别人的组件要走语义化方法（SetValidColor），不越权摸内部
- [x] 拖拽必须有"数学上必成功"的回滚路径
- [x] 三元表达式别被 if 裹住杀分支

## 八、思考题（附复习参考）

**Q1：拖拽途中游戏暂停或背包面板被关闭，被拿起的物品会怎样？怎么保命？**

> 参考：物品已 Remove，数据层没有它——如果此时 EndDrag 永远不触发（面板禁用后事件停发），物品就"蒸发"了。保命设计：① 面板关闭/禁用时强制走一次取消流程（Place 回旧锚点），OnDisable 里兜底；② 或拖拽数据不放控制器内存，而是"拿起"本身是一种数据状态（如 grid 的 holdingItem 字段），重开面板能续上。大厂做法偏向①：任何打断拖拽的出口（失焦、暂停、关闭）都汇聚到同一个 CancelDrag()。

**Q2：为什么预览红绿框必须实时问 CanPlaceAt，而不是 UI 自己记一份占用状态？**

> 参考：两份状态必然漂移——拖拽中怪物死亡掉落入包、别的系统动了格子，UI 的记忆就过期了，预览绿实际冲突。单一事实源：占用状态只有 cells 一份，CanPlaceAt 是它的官方问答窗口。UI 记状态 = 自己造一个需要同步的冗余，回到第 9 课 HashSet 那笔账。

**Q3：将来做"背包 ↔ 仓库"双面板互拖，现在哪些设计已经铺好了路？**

> 参考：① BeginDrag/EndDrag 都是"物品 + 坐标"语义，不绑定具体面板——拖起来自 A 面板、落到 B 面板只是换成 B 的换算和 B 的 grid；② Item 不持有"我在哪个背包"的状态，天然可迁移；③ Place/Remove/CanPlaceAt 是通用原子操作。要补的：拖拽中记录"来源 grid"，EndDrag 时判断目标面板是哪一个，跨面板 = 源 Remove + 目标 Place。事件驱动的收货口同理：仓库也只是另一个订阅者。
