# 第18课 · 波次导演与15分钟节奏

> 课程周期：2026-07-30  
> 前置：第17课《经验成长与三选一》  
> 关键词：WaveDirector、EnemySpawner、时间轴压力曲线、波次 HUD、阶段颜色、15 分钟节奏

---

## 一、这节课实现了什么

### 任务 1 · 刷怪器从固定参数升级为可调度执行器

- `EnemySpawner` 保留原有环带刷怪逻辑，不关心当前是第几分钟。
- 新增 `ApplyWaveSettings(spawnInterval, maxAlive)`，允许外部系统调整刷怪间隔和场上敌人上限。
- 刷怪器仍然只负责执行：计时、随机环带点、向对象池要敌人。

### 任务 2 · 新增波次导演 WaveDirector

- 新增 `WaveDirector`，作为 15 分钟压力曲线的主人。
- `WaveDirector` 读取 `GameSession.Elapsed`，不自己维护第二套计时器。
- 使用 `WaveStage` 阶段表配置每一段的开始时间、刷怪间隔、最大存活数、阶段名和显示颜色。
- 倒序匹配阶段，确保越靠后的阶段优先命中。

### 任务 3 · 波次只在阶段变化时生效

- `currentStageIndex` 记录当前阶段。
- 只有阶段 index 变化时，才调用 `EnemySpawner.ApplyWaveSettings()`。
- 避免每帧重复写参数，波次切换日志和行为都更干净。

### 任务 4 · 暂停与升级选择期间冻结波次推进

- `WaveDirector.Update()` 只在 `GameState.Running` 下工作。
- 普通暂停、升级三选一、胜利、失败状态下都不会切波次。
- 这保证了“暂停不偷跑难度”，玩家不会因为选升级而被时间轴惩罚。

### 任务 5 · 波次 HUD 命名与颜色反馈

- `WaveDirector` 新增 `OnWaveStageChanged(stageIndex, stageName, displayColor)`。
- `RunHudView` 订阅波次事件，显示 `WAVE n · 阶段名`。
- 每个阶段可以在 Inspector 配置显示颜色，后期波次用更危险的颜色表达压迫感。

### 任务 6 · 清理调试噪音

- `TargetRegistry` 清掉注册/注销时的临时 `Debug.Log`。
- 这避免后续高密度刷怪时 Console 被无意义日志刷屏。

## 二、最终代码（关键片段）

### EnemySpawner：只暴露可调参数入口

```csharp
public void ApplyWaveSettings(float spawnInterval, float maxAlive)
{
    if (spawnInterval < 0.1f || maxAlive <= 0) return;

    this.spawnInterval = spawnInterval;
    this.maxAlive = maxAlive;
}
```

`EnemySpawner` 不判断“第几波”，只接受最终参数。这样它是执行器，不是导演。

### WaveStage：一段压力配置

```csharp
[Serializable]
public class WaveStage
{
    public float startTimeSeconds;
    public float spawnInterval;
    public int maxAlive;
    public string stageName;
    public Color displayColor;
}
```

`startTimeSeconds` 是阶段锚点，`spawnInterval / maxAlive` 是实际压力参数，`stageName / displayColor` 是表现层要用的可读反馈。

### WaveDirector：按本局时间切阶段

```csharp
private void Update()
{
    if (gameSession == null || enemySpawner == null) return;
    if (gameSession.State != GameState.Running) return;
    if (waveStages == null || waveStages.Count == 0) return;

    for (int i = waveStages.Count - 1; i >= 0; i--)
    {
        if (gameSession.Elapsed >= waveStages[i].startTimeSeconds)
        {
            int stageIndex = currentStageIndex;
            currentStageIndex = i;

            if (stageIndex != currentStageIndex)
            {
                enemySpawner.ApplyWaveSettings(
                    waveStages[i].spawnInterval,
                    waveStages[i].maxAlive);

                OnWaveStageChanged?.Invoke(
                    currentStageIndex,
                    waveStages[i].stageName,
                    waveStages[i].displayColor);
            }

            break;
        }
    }
}
```

倒序查找的好处是：比如第 9 分钟同时满足 0、2、5、8 分钟的条件，但真正应该命中第 8 分钟开始的阶段。

### RunHudView：只显示导演给出的结果

```csharp
private void HandleWaveStageChanged(int stageIndex, string stageName, Color displayColor)
{
    if (waveText == null) return;

    waveText.text = $"WAVE {stageIndex + 1} · {stageName}";
    waveText.color = displayColor;
}
```

HUD 不写 `if 第5波就变红`。颜色是波次配置的一部分，HUD 只是把导演给的名字和颜色显示出来。

## 三、周期链路

### 开局进入第 1 波

```text
Scene Start
  ↓
GameSession.StartRun()
  ↓
State = Running
  ↓
WaveDirector.Update()
  ↓
Elapsed >= waveStages[0].startTimeSeconds
  ↓
currentStageIndex: -1 -> 0
  ↓
EnemySpawner.ApplyWaveSettings()
  ↓
OnWaveStageChanged(0, name, color)
  ↓
RunHudView 显示 WAVE 1
```

### 阶段切换链路

```text
RunTimer.Tick(Time.deltaTime)
  ↓
GameSession.Elapsed 增长
  ↓
WaveDirector 倒序匹配当前阶段
  ↓
阶段 index 发生变化
  ↓
ApplyWaveSettings(spawnInterval, maxAlive)
  ↓
广播阶段名和颜色
  ↓
刷怪压力提高，HUD 文案变色
```

### 暂停 / 升级选择冻结链路

```text
Esc 暂停 或 升级三选一
  ↓
GameSession.State != Running
  ↓
WaveDirector.Update() return
  ↓
不切阶段，不改刷怪参数
  ↓
玩家恢复 Running 后继续跟随本局时间判断
```

## 四、设计思考

### 1. 为什么要做 WaveDirector？

第 17 课已经让玩家能“打怪 → 吃经验 → 升级 → 变强”。但如果敌人压力不随时间提高，成长系统就没有对手戏。

`WaveDirector` 的价值是给 15 分钟 Demo 一条清晰压力曲线：开局适应，中期上压，末段冲刺。玩家升级后不是只看数字变大，而是用变强后的战斗力对抗越来越密的敌人。

### 2. 为什么不把波次逻辑写进 EnemySpawner？

`EnemySpawner` 已经有一个明确职责：按当前参数刷敌人。它不应该知道“第几分钟该多难”。

如果把时间轴、阶段名、颜色、刷怪参数都塞进刷怪器，它会变成又管规则又管执行的混合类。拆出 `WaveDirector` 后，后续想加精英潮、宝箱节奏、Boss 前压迫，都可以继续由导演调度。

### 3. 为什么 WaveDirector 读 GameSession.Elapsed？

因为 `GameSession` 已经是一局时间和状态的主人。再让 `WaveDirector` 自己计时，会出现第二套时间事实：暂停时谁停？胜利后谁停？升级选择时谁停？

读取 `GameSession.Elapsed`，就能天然跟随第 16 课建立的单局状态机。

### 4. 为什么只在阶段变化时 Apply？

波次阶段是状态，不是每帧动画。

每帧都写 `spawnInterval / maxAlive` 虽然结果一样，但会让调试变脏，也容易在后续加日志、音效、特效时重复触发。用 `currentStageIndex` 做门闸，保证一次阶段变化只生效一次。

### 5. 为什么波次颜色放在配置里？

颜色是阶段表达的一部分，不是 HUD 的判断逻辑。

HUD 如果根据 index 自己决定颜色，后续调换阶段顺序或改阶段含义时就要改 UI 代码。现在 `WaveDirector` 告诉 HUD “当前阶段叫什么、显示什么颜色”，表现层只负责展示。

## 五、踩坑记录

### 1. 初始化波次 HUD 不能只等下一阶段

- **现象**：如果只在后续阶段变化时广播，开局 `waveText` 可能为空。
- **原因**：第 0 阶段也需要被当作一次正式阶段切换。
- **处理**：`currentStageIndex` 初始为 `-1`，第一帧 Running 时命中第 0 阶段并广播。
- **沉淀**：事件驱动 UI 也要考虑初始快照。

### 2. 颜色 alpha 不能是 0

- **现象**：阶段名更新了，但看起来像没显示。
- **原因**：Inspector 里 `displayColor.a = 0`，文字完全透明。
- **处理**：所有阶段颜色 alpha 调为 1。
- **沉淀**：UI 颜色问题先查 alpha，再查脚本。

### 3. 波次切换要避开非 Running 状态

- **现象风险**：升级三选一时如果继续推进波次，玩家会在暂停选择中被难度时间轴追赶。
- **处理**：`WaveDirector` 只在 `GameState.Running` 下工作。
- **沉淀**：任何局内时间驱动系统，都要尊重 GameSession 状态机。

### 4. 日志在高频系统里会放大噪音

- **现象风险**：刷怪密度提高后，注册/注销日志会疯狂刷 Console。
- **处理**：清理 `TargetRegistry` 的临时注册/注销日志。
- **沉淀**：高频路径不要留测试日志；要么删掉，要么做成可开关调试模式。

## 六、面试问答

**Q1：WaveDirector 解决了什么问题？**  
> 它把 15 分钟 Demo 的压力曲线从固定刷怪参数升级为按时间推进的阶段系统，让玩家能感知从开局到终局的难度递增。

**Q2：为什么 EnemySpawner 不直接根据时间调整自己？**  
> 因为刷怪器是执行器，波次导演是规则层。拆开之后，刷怪器可以复用，导演可以继续扩展精英、宝箱、Boss 或特殊事件。

**Q3：为什么 WaveDirector 使用 GameSession.Elapsed？**  
> 因为 GameSession 是单局时间事实源。这样暂停、升级选择、胜负状态都能统一影响波次系统，不会出现多套计时不同步。

**Q4：为什么阶段查找要倒序？**  
> 因为后面的阶段也满足前面阶段的开始时间条件。倒序能优先命中最新阶段，例如 9 分钟应该进入 8 分钟阶段，而不是 0 分钟阶段。

**Q5：为什么只在阶段变化时调用 ApplyWaveSettings？**  
> 因为阶段切换是离散事件。只调用一次能避免重复日志、重复表现和无意义参数写入，后续接音效/提示也更安全。

**Q6：为什么 HUD 不自己决定波次颜色？**  
> 因为颜色属于波次配置的一部分。HUD 只展示导演给出的阶段名和颜色，不承担规则判断，这样改配置不用改 UI 代码。

## 七、习惯清单

1. 时间驱动系统先问“谁是时间事实源”，不要各自维护计时器。
2. 执行器只执行，导演只调度，别把波次规则塞进刷怪器。
3. 阶段变化用 index 门闸，只在变化时广播和应用。
4. 非 Running 状态下，局内压力系统要暂停。
5. HUD 只消费事件和快照，不自己猜规则。
6. UI 颜色异常先查 alpha。
7. 高频系统不要留无意义 `Debug.Log`。

## 八、思考题（附复习参考）

**Q1：如果以后要加精英潮，应该放在哪个系统？**  
> 放在 `WaveDirector` 或它调度的子系统里。`EnemySpawner` 可以继续做执行器，未来扩展为普通敌人池、精英敌人池或多个刷怪通道，但“什么时候出精英”应由导演决定。

**Q2：如果暂停时波次继续切换，会造成什么体验问题？**  
> 玩家在升级选择或暂停菜单里没有操作世界，但难度时间轴继续推进，恢复后可能突然进入更高压阶段。这会让暂停和升级选择变成隐形惩罚。

**Q3：为什么不急着做复杂 Boss？**  
> 当前 Demo 目标是 15 分钟完整循环。时间压力曲线比复杂 Boss 更早提供全局节奏，风险更低、可玩性提升更直接。Boss 可以在第 23 课用简化版本或高压精英潮替代。

**Q4：如果波次名显示不出来，排查顺序是什么？**  
> 先看 `waveText` 是否接线，再看 `WaveDirector` 是否广播，再看颜色 alpha 是否为 0，最后看 `GameSession.State` 是否进入 Running。
