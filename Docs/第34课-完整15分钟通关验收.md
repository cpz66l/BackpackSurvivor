## 一、这节课实现了什么

第34课不是开新系统，而是把《背包幸存者》当前版本当作真正要交给别人试玩的 V0.2 Demo 来验收。重点从“我能不能实现某个功能”，切换成“别人能不能理解、能不能玩下去、能不能在失败后想再来一局”。

本课的主线是完整游戏链路巡检：

```text
MainMenu
  ↓
玩法说明 / 制作者声明
  ↓
Start → 01-Run
  ↓
移动、瞄准、主动射击、自动武器
  ↓
敌人波次、精英敌人、宝箱压力
  ↓
掉落、拾取、背包整理、合并、邻接、武器激活
  ↓
升级三选一、金币、背包价值
  ↓
胜利 / 失败结算
  ↓
Restart / 返回 MainMenu / 再开始
```

本课完成后，项目已经从“功能都在”推进到“可被外部玩家试玩并暴露真实体验问题”的状态。

### 任务 1 · 外部试玩发现理解门槛

让其他人试玩后，最明显的问题不是战斗不能玩，而是：

- 不知道武器放进背包后才会在角色身边生成自动武器。
- 不知道背包左上位置决定武器激活优先级。
- 不知道灰色接边 / 金色接边分别代表可连接 / 已生效。
- 不知道双持和芯片邻接是当前 Demo 的构筑深度来源。

这个反馈非常重要。它说明系统深度已经存在，但玩家缺一个进入深度的入口。

### 任务 2 · 主菜单新增玩法说明入口

本课在 MainMenu 上新增类似制作者声明的玩法说明面板，用来承载“背包作战手册”。

教程文案的核心不是把所有规则讲完，而是先把影响前 3 分钟体验的规则讲清楚：

```text
武器放进背包才会自动攻击。
背包左上位置优先激活。
灰边能连接，金边已生效。
双手枪左右相邻可以触发双持。
弹匣 / 攻击芯片接到武器旁边能提升战斗能力。
```

这一步解决的是“玩家没有意识到自己正在错过深度”的问题。

### 任务 3 · 精英敌人经验奖励上调

本课把精英敌人的经验掉落提高，让玩家在高风险目标上获得更明确回报。

这和当前试玩反馈一致：如果精英敌人更危险，就应该让玩家感受到“打掉它是值得的”。否则精英只会变成压力源，而不是路线和战斗决策的一部分。

### 任务 4 · 修正主动射击瞄准高度错层

试玩中发现主动射击存在视觉不一致：鼠标位置代表地面点，但子弹从枪口高度沿水平面发射。等距相机下，同一屏幕射线打到 `y=0` 地面和打到枪口高度平面，得到的 XZ 交点不同。

本课新增按高度取鼠标平面交点的方法：

```text
地面交点 worldPoint：继续用于地面语义
枪口高度交点：用于主动武器弹道
身体高度交点：用于角色模型转向
```

修完后，主动射击方向、鼠标屏幕位置和角色视觉朝向更一致。

### 任务 5 · 出现“有故事的失败局”

本课试玩里首次出现了很有价值的一局：玩家打出约 `4000￥`，但最后几秒为了整理背包被敌人偷袭，遗憾失败。

这不是坏消息，反而说明核心循环开始成立：

- 背包整理有足够收益，所以玩家愿意冒险整理。
- 终局压力存在，不是一路碾压。
- 失败来自玩家决策，而不是系统不可理解。
- 玩家能形成一句话复盘：“我刚才贪整理背包被偷了。”

这种失败比无脑通关更有 Demo 价值。

### 任务 6 · 全游戏链路巡检

本课收官前重新扫了一遍主链路：

- **入口链路**：`MainMenuController` 支持开始游戏、制作者声明、玩法说明、退出。
- **状态链路**：`GameSession` 负责 Running / Paused / LevelUpSelecting / Victory / Defeat。
- **输入链路**：`InputReader` 统一发出移动、攻击、交互、旋转、暂停、开关背包意图。
- **战斗链路**：`WeaponBase` 统一伤害乘区，主动武器修正鼠标平面，自动武器继续索敌射击。
- **波次链路**：`WaveDirector` 按时间调度敌人强度、精英概率、宝箱节奏。
- **掉落链路**：`LootManager` 按品类生成装备/经验/金币，并统一散落表现。
- **背包链路**：`InventorySystem` 负责拾取入包、满包吐回、丢弃保真。
- **构筑链路**：`InventoryGrid` 扫邻接，`BackpackWeaponActivator` 应用双持、攻速、伤害芯片效果。
- **HUD 链路**：`RunHudView` 显示时间、血量、等级、经验环、金币、波次。
- **结算链路**：`ResultView` 显示胜负和背包价值，支持重开或返回主菜单。

巡检结论：当前没有看到阻断级断点，适合进入第35课 Profiler 快扫。

### 任务 7 · 最终验收通过

本课已通过代码巡检和基础构建验证：

- `dotnet build` 通过，0 错误。
- 危险 using 扫描干净。
- MainMenu → Run → Result → Restart / MainMenu 链路逻辑完整。
- 主动射击瞄准高度修正完成。
- 背包武器激活、邻接效果、背包价值、金币和经验链路仍然闭合。
- 第34课可以收官。

### 2. 玩法说明按钮订阅

```csharp
if (gameplayGuideButton != null)
    gameplayGuideButton.onClick.AddListener(GameplayGuideButton);
if (closeGuideButton != null)
    closeGuideButton.onClick.AddListener(CloseGuideButton);
```

和制作者声明一样，按钮订阅写在 `OnEnable()`，退订写在 `OnDisable()`，保持镜像。

### 3. 鼠标指定高度平面交点

```csharp
public bool TryGetMousePointOnPlane(float y, out Vector3 point)
{
    point = default;

    if (mainCam == null)
        return false;

    Ray ray = mainCam.ScreenPointToRay(mouseVector2);
    Plane plane = new Plane(Vector3.up, new Vector3(0f, y, 0f));

    if (!plane.Raycast(ray, out float enter))
        return false;

    point = ray.GetPoint(enter);
    return true;
}
```

这个方法让鼠标不再只有“地面点”一种解释。不同系统可以按自己的高度语义取点。

### 4. 主动武器按枪口高度瞄准

```csharp
if (!ir.TryGetMousePointOnPlane(firePoint.position.y, out Vector3 aimPoint))
    return;

Vector3 direction = aimPoint - firePoint.position;
direction.y = 0f;

if (direction.sqrMagnitude < 0.0001f)
    return;

Fire(direction.normalized);
```

子弹从枪口高度发射，就用枪口高度平面上的鼠标交点来算方向。这样屏幕鼠标位置和弹道视觉更一致。

### 5. 玩家模型按身体高度转向

```csharp
if (ir.TryGetMousePointOnPlane(bodyPivot.position.y, out Vector3 aimPoint))
{
    lookDirection = aimPoint - bodyPivot.position;
    lookDirection.y = 0f;

    if (lookDirection.sqrMagnitude > 0.001f)
    {
        Quaternion targetRotation = Quaternion.LookRotation(lookDirection);
        bodyPivot.rotation = Quaternion.RotateTowards(
            bodyPivot.rotation,
            targetRotation,
            rotateSpeed * Time.deltaTime
        );
    }
}
```

角色视觉朝向和主动射击方向用同一类高度平面逻辑，减少“身体看这边，子弹像往那边飞”的违和感。

### 6. ResultView 重开链路

```csharp
private void HandleRestartClicked()
{
    Time.timeScale = 1f;
    SceneManager.LoadScene("01-Run");
}

private void HandleQuitClicked()
{
    Time.timeScale = 1f;
    SceneManager.LoadScene("MainMenu");
}
```

结算页不直接退出程序，Demo 试玩更需要“再来一局”和“回菜单看说明”。

## 四、设计思考

### 1. 为什么第34课要做外部试玩？

开发者自己知道系统怎么运作，会天然跳过许多理解成本。外部试玩暴露的不是“代码会不会跑”，而是“玩家能不能发现它好玩在哪里”。

这次别人不理解邻接和武器激活，说明系统不是没深度，而是缺少导入口。教程面板就是对这个问题的低成本修复。

### 2. 为什么教程放 MainMenu，而不是局内强制弹窗？

当前 Demo 的战斗节奏已经成立，局内强制教程会打断第一次体验。主菜单说明更适合给玩家一个主动学习入口：想快速玩可以直接开始，想理解深度可以先看作战手册。

对简历 Demo 来说，这也更像一个完整作品，而不是开发者临时弹窗。

### 3. 为什么“4000￥但最后几秒被偷袭”是好信号？

因为失败不是来自系统崩坏，而是来自玩家决策：想在终局压力下继续整理背包，结果被敌人抓到。这说明背包管理的收益足够高，战斗压力也足够真实。

好的 Demo 不一定要让玩家第一次就通关；它要让玩家失败后能说出“我刚才差一点，下把我换个策略”。

### 4. 为什么精英敌人要提高经验？

精英敌人如果只更难打，却不给更高回报，玩家会倾向于把它理解成纯惩罚。提高经验后，它变成一个风险收益点：打掉它更危险，但也能更快升级。

这让精英从“压力单位”升级成“路线和构筑节奏的一部分”。

### 5. 为什么鼠标瞄准要区分高度平面？

屏幕上的鼠标位置是一条从摄像机发出的射线，不是天然的世界点。只有指定一个平面，它才会变成世界坐标。

地面交点适合移动和地面交互；枪口高度交点适合子弹弹道；身体高度交点适合模型朝向。把它们混用，就会出现视觉错层。

### 6. 为什么现在可以进入 Profiler，而不是继续加内容？

当前项目已经具备：入口、教程、战斗、波次、成长、掉落、背包构筑、价值、结算、重开。继续加内容会稀释 Demo 冲刺焦点。

接下来更重要的是确认：有没有 GC 尖刺、对象池残留、掉帧、Build 运行异常。这些问题比“再加一个芯片”更影响交付。

## 五、踩坑记录

### 1. 玩家看不懂系统，不等于系统没价值

- **现象**：外部玩家不知道邻接搭配和武器激活方式。
- **根因**：系统反馈存在，但缺少开局前的概念入口。
- **修复**：MainMenu 新增玩法说明面板，用短文案解释武器激活、优先级、邻接接边和第一局推荐玩法。
- **沉淀**：Demo 要让玩家看见深度入口，不能假设玩家会像开发者一样理解系统。

### 2. 鼠标世界点不是唯一答案

- **现象**：鼠标指向地面点，子弹却从枪口高度水平飞，视觉不一致。
- **根因**：同一屏幕射线与不同高度平面的交点不同。
- **修复**：`InputReader.TryGetMousePointOnPlane()` 按指定高度取交点；主动武器和角色转向分别使用合适高度。
- **沉淀**：输入层可以保留原始屏幕坐标和通用查询方法，不要把所有系统都绑死在地面点。

### 3. 高价值失败局要被记录

- **现象**：打到约 4000￥，最后几秒整理背包时被偷袭失败。
- **分析**：这是核心玩法成立的证据，不是单纯失败。
- **沉淀**：验收时不只记录 bug，也要记录“玩家愿意冒险做什么”，那往往就是核心乐趣。

### 4. 面板按钮要防空引用

- **现状**：MainMenu 的按钮订阅有判空，但 `AboutButton()` / `GameplayGuideButton()` 内部直接 `SetActive()`。
- **影响**：场景接线正确时没问题；如果以后某个 Panel 漏拖，点击会 NRE。
- **建议**：Build 前可给这些面板开关方法补一层 `if (panel != null)`。
- **沉淀**：按钮和面板是两个序列化引用，判空要判马上使用的对象。

### 5. Inspector 序列化警告不是当前阻断项

- **现象**：`dotnet build` 有 5 个 CS0649 警告。
- **原因**：这些字段由 Unity Inspector 序列化赋值，C# 编译器不知道场景里会填。
- **处理**：当前不是阻断项；第35课或 Build 前可以考虑用注释、默认值或代码防御降低噪音。

## 六、面试问答

**Q1：你是怎么做完整 Demo 验收的？**  
> 我按玩家实际链路验收：主菜单、玩法说明、开始游戏、战斗、掉落、背包构筑、升级、波次压力、结算、重开和返回主菜单。不是只看某个功能点，而是看完整体验能不能闭环。

**Q2：外部试玩发现玩家不懂邻接，你怎么解决？**  
> 我没有马上加复杂新手引导，而是在主菜单做玩法说明面板，用最短路径解释武器放背包才激活、左上优先级、灰边/金边含义、双持和芯片搭配。这样低成本解决理解入口，不打断局内节奏。

**Q3：为什么背包左上优先级要告诉玩家？**  
> 因为它已经是战斗规则的一部分。玩家如果不知道优先级，会误以为武器激活是随机的。告诉玩家后，背包摆放就从收纳变成战斗决策。

**Q4：你怎么解释主动射击瞄准修正？**  
> 鼠标屏幕位置本质是一条射线，必须和某个平面相交才得到世界点。旧逻辑用地面点算枪口高度弹道，导致视觉错层。我新增了按高度平面取交点的方法，让枪口用枪口高度、角色转向用身体高度。

**Q5：为什么提高精英敌人经验？**  
> 因为精英敌人承担更高风险，如果奖励不明显，玩家只会觉得它烦。提高经验后，精英变成高风险高回报目标，能推动升级节奏和路线选择。

**Q6：这次 4000￥失败局说明了什么？**  
> 它说明游戏已经有风险决策张力。玩家为了更高背包收益愿意在终局压力下整理背包，失败来自贪心和操作选择，而不是系统不可理解。

**Q7：你为什么现在进入 Profiler，而不是继续加功能？**  
> 当前 V0.2 的核心闭环已经具备，继续加功能会增加不稳定性。Demo 冲刺期下一步应该验证性能、对象池、GC 和 Build，而不是扩系统。

## 七、习惯清单

1. 完整验收按玩家链路走，不按脚本文件列表走。
2. 外部玩家看不懂时，先补“理解入口”，不要急着重构系统。
3. 教程文案优先解释能立刻改变战斗结果的规则。
4. 鼠标屏幕点要先定义平面，再谈世界坐标。
5. 高价值失败局要记录，因为它能证明风险收益成立。
6. 精英敌人要同时有压力和奖励，否则只会变成负反馈。
7. 结算、重开、返回主菜单都要恢复 `Time.timeScale = 1f`。
8. static 本局状态继续保持新局显式 Reset。
9. Demo 冲刺期只修影响演示的问题，不被新系统吸走。
10. 进入 Build 前继续扫危险 using 和 Unity `.meta` 完整性。

## 八、思考题（附复习参考）

**Q1：如果玩法说明太长，玩家不看怎么办？**  
> 可以把最关键的三句话放在面板顶部：武器放进背包才自动攻击；左上优先激活；灰边可连接、金边已生效。长文案留给愿意深入的人。

**Q2：为什么不把邻接教程做成强制关卡？**  
> 强制教程成本高，还会打断幸存者游戏的开局节奏。当前 Demo 更适合主菜单说明 + 明确 UI 反馈；等以后做正式版本，再考虑分步教学。

**Q3：主动射击能不能直接瞄地面点，不拍平 y？**  
> 不建议。那会让子弹从枪口向地面俯冲，容易引入打地面、命中高度不稳定等问题。俯视幸存者项目里，水平弹道更稳定。

**Q4：为什么失败局也能作为正向验收材料？**  
> 因为好的失败说明系统有压力、有收益、有玩家选择。只要玩家知道自己为什么输，并愿意下把调整策略，这就是玩法成立的表现。

**Q5：第35课 Profiler 应该重点看什么？**  
> 优先看 GC Alloc、敌人/子弹/掉落对象池是否稳定、背包 Redraw 是否造成明显尖刺、伤害数字和掉落散落是否过量实例化，以及 15 分钟后半段帧率是否稳定。
