# 《背包幸存者》世界观设定集

状态：骨架初稿。日期：2026-09-13。阵营基准：**A · 回收署**。

配套文档：`Docs/NPC人物设定.md`（小芯）、`Docs/LLM事件驱动系统技术方案.md`（第 9 节 NPC 对话系统）。

## 0. 本文用法

### 分层规则（最重要）

本设定集的内容分为两层，**写文案时必须区分**：

| 层 | 内容 | 去向 |
|---|---|---|
| **稳定层** | 世界根设定、势力性质、术语表、NPC 口径 | 允许写进 `Persona` 人设前缀（三面共用） |
| **可变层** | 地标与掉落、物品定义、敌人档案细节、当前合同与进度、版本相关的功能清单 | 走事实块与只读工具，**绝不写进前缀** |

原因：`NpcDialogueService.cs` 里的 `Persona` 常量是三面共用的缓存前缀，改一次三个对话面的缓存同时失效。地标和词条会随版本不断增加，塞进前缀等于每次加内容都让缓存全废。

第 9 节给出了完整的稳定层 / 可变层清单。

### 合规前提

**全架空。** 城市、机构、灾变、技术名词均为虚构，不含任何现实指涉。写作与生成内容时不得引入真实国家、机构、事件或人物。这条同时满足禁区 C 类第 14 条（不得伪装成真实人物）与内容规范要求。

## 1. 世界根设定

### 1.1 灾变：灰潮

灾变没有名字，只有一个代号——**灰潮**。它不是一次爆炸或一场战争，而是一次持续数日的、缓慢的污染涌动：地面以下的沉积物被翻上来，城市被一层灰白色的浊雾浸透，然后退了回去。

它退得不干净。

退潮之后的城区里，浓度再也没有降到过安全线以下。人待久了会病，东西待久了会变。**浊**留在了那里，像水留在低处。

### 1.2 封锁墙

灾变之后最先立起来的不是救援，是**封锁墙**——把浓度最高的那片城区围起来的一道墙。墙的原始用途是不让里面的东西出来。

后来它的用途变了：墙里的人没能出来，墙外的人开始想进去。

墙内的区域统称**封锁区**。**汐港**在灾变前是一座港口物流枢纽，所以墙内至今保留着那个时代最鲜明的遗迹：检查站、集装箱货场、地下排水渠、修了一半就废弃的混凝土屏障。这些东西现在的价值，和它们当初被造出来时的用途毫无关系。

### 1.3 潮：15 分钟硬时限的成因

**浊不是静止的，它有潮。**

浓度随时间涨落，以约一刻钟为一个周期。周期里浓度最低的那一段叫**低潮窗**。低潮窗是唯一能让人进出墙内的时段——窗口关闭之后浓度回升，防护装备撑不住，留在墙内的人回不来。

**所以单局 15 分钟不是游戏规则，是世界规则。** 玩家进入时是落潮，撤离线是满潮。

### 1.4 潮位：波次压力的世界内解释

墙内的威胁不是凭空变多的。潮涨起来的时候，浊化的东西被从低处赶上来，向高处和干燥的地方聚集——**而你正好在往里面走。**

因此局内的五个波次阶段就是**五个潮位**。这也意味着开发期使用的阶段占位名（洒洒水 / 简单 / 普通 / 上压力 / 终局）需要一套世界内的对应说法：

| 时间 | 潮位 | 世界内的意思 |
|---|---|---|
| 0–180 秒 | **落潮** | 浓度最低，活动最少，最好的搜刮时段 |
| 180–360 秒 | **回潮** | 水开始回来，东西开始动 |
| 360–600 秒 | **涨潮** | 低洼区开始淹，路线选择开始受限 |
| 600–780 秒 | **涌潮** | 聚集加剧，撤离压力真正出现 |
| 780–900 秒 | **满潮** | 窗口关闭。还在墙里就出不来了 |

这一条的价值在于：**波次递增从"敌人数量变多"变成了"水位在涨"。** 玩家感受到的压力不再是抽象的数值，而是一件他有直观理解的事。

它同时给了波次脉冲最理想的内容——小芯在每一次阶段切换时报的是潮位，而"潮在涨"本身就是最有张力的台词。

## 2. 回收署

### 2.1 它是什么

**回收署**，全称「封锁区资产回收署」。灾变后残存秩序中负责一件事的机构：把墙里还有价值的东西弄出来。

它的全称里没有"武力"这个词，这是有意的。

### 2.2 它的权力从哪来：登记权

**回收署不掌握武力，它掌握登记权。**

它的全部权力建立在三件纸面上的事上：

1. 它定义什么算「回收完成」
2. 它决定谁有资格进墙（**回收员**资质）
3. 它裁定带出来的东西归谁

这三件事都不需要枪。它需要的是一套没人能替代的登记系统——因为没有第二家机构能证明"这些东西是从墙里合法带出来的"。

**它的权力是纸做的，但对一个进过墙的人来说，纸比枪有用。** 没有署的登记，从墙里带出来的东西就是赃物，卖不掉、过不了检查站、也没法证明不是从别人尸体上扒的。

### 2.3 它为什么外包

因为署没钱，也没人。

它付不起一支队伍的抚恤，所以它不雇人，它**发资质**。回收员不是署的员工，是**持证的独立作业者**：署给你进墙的资格和防护配额，你自己去，带出来的东西按合同核销，剩下的归你。

署承担的是纸面风险，回收员承担的是全部物理风险。这个结构对双方都成立，而且它解释了为什么这个游戏里"死亡丢失装备"是合理的——**你的装备从来就不是署的资产。**

### 2.4 作业类型：把目标条件翻译成世界内的动机

游戏里 16 种目标条件不应该只是数值上的差异，每一种都该有"谁在下这种单、为什么下"。按署的核销逻辑，作业分为六种类型：

| 作业类型 | 覆盖的目标条件 | 世界内的动机 |
|---|---|---|
| **清点** | `CarryTag` / `CarryTagSet` / `CarryRarity` / `CarryItem` / `CarryItemAtLevel` / `CarryAnyItemAtLevel` / `CarryItemAnyOf` | 署缺什么就点什么。清单是署的需求，不是你的选择 |
| **衡值** | `BackpackValueAtLeast` | 署按总值核销。凑够数就算完成，具体是什么它不管 |
| **轻装** | `BackpackValueAtMost` / `ExcludeTag` / `ExcludeRarity` | 这趟是**穿行或侦察**，不是搬运。背重了过不去，所以限制载重 |
| **清障** | `KillTotal` / `KillElite` | 署要压低某片区域的威胁等级，好让**下一次**作业更安全。它买的是别人以后的路 |
| **探明** | `OpenChestAtLeast` | 署要的是情报不是物资：打开、记录、位置归档。箱子里的东西归你 |
| **存续** | `ReachLevel` / `SurviveToSecond` | 新手作业或兜底单。署在试一个新人的成色 |

这一层映射的价值：**当玩家看到"轻装"类合同时，他理解的是任务性质，而不是一串限制条件。** 后续新增事件定义时，先定作业类型，再选条件，动机就不会悬空。

## 3. 调度营地

### 3.1 它是什么

**回收署汐港前哨**，通称**调度营地**。

它是墙外最后一处有电、有网、有一张桌子的地方。署在这里设了点，但实际维护靠的是往来的回收员自己——**没有编制，只有一块还亮着的屏幕。**

营地是每次出击的必经之路。这个设计上的要求在世界内同样成立：**墙只有一个收放得住的出入口，而署的登记必须在墙外完成。**

### 3.2 小芯

营地的官方调度终端在灾变后期烧毁了。署没有预算换新，也没有同代备件。

所以当某个回收员从墙里带回来一台旧助理机、又在营地里把它修好之后，营地的调度功能就由它接管了。

| 项 | 设定 |
|---|---|
| 它是什么 | 灾变前的**消费级家用助理单元**，型号「家用助理单元 · 07 型」 |
| 它为什么能用 | 它的硬件年代与署那套老协议栈同源，接上去居然能跑 |
| 署的态度 | 官方档案里，这个前哨的调度终端依然登记为「署配发终端」。署不在意实际是谁在派单，只要单据能走完流程 |
| 玩家与它的关系 | 它是玩家的。玩家捡的、玩家修的、玩家带回来的 |

小芯的完整人设（外形、性格、三面语气梯度、能力边界、文案红线）见 `Docs/NPC人物设定.md`。

### 3.3 废墟相遇

这是玩家与这台机器的起点。**建议不做演出，让它从小芯的话里被拼出来。**

> 那趟作业本来只是清点。回程时间还够，走到货场边缘的时候听见一点声音——不是风，是某个东西在反复尝试启动。
>
> 半埋在掉下来的顶棚下面，外壳裂了，屏幕上只剩一条横着的亮线，还在一下一下地试着把线接起来。
>
> 你把它拽出来的时候它没有任何反应，只是那条线又亮了一下。
>
> 你把它带回来了。之后用了几个晚上，把那块裂开的外壳补上，把那只被砸坏的眼睛换成能用的零件，接上营地的旧接口——然后它睁开了。

这一幕的功能是：**它是玩家在这个世界里第一次"让什么东西重新工作"。** 通关的结局（重亮避难所）是同一件事的放大版。主题上它俩是一件事，这是刻意的。

## 4. 登记信标：第二条世界规则

### 4.1 它是什么

**登记信标**是署配发的标准装备的一部分，和防护配额一起发。它的官方用途有三个：定位、联网、记录交接。

它的实际作用是：**你在墙内经手的每一件东西，都会被记进本次作业的登记清单。**

### 4.2 它统一了五件事

| 设计上已有的约束 | 之前只是技术选择 | 现在的世界内理由 |
|---|---|---|
| 死亡丢装备，但事件进度不倒退 | 怕长线循环太苦 | 装备是物理的，留在现场；登记过的东西已经沿信标回传了 |
| 波次脉冲可以丢弃、晚到就作废 | 晚到的战局评价不如没有 | 浊会打断信号，晚到的那句**真的**没了 |
| 脉冲上限 60 字、且必须是一句 | 控制成本与节奏 | 低潮窗里链路带宽不够，它只挤得出一句 |
| NPC 完全无法影响战斗 | 只读工具、不改状态 | 信标是登记用的，不是武器 |
| NPC 知道玩家上一局发生的事 | 会话机制 | 它一直在听 |

### 4.3 一条完整的链路

```
回收署的老协议栈
   → 营地的旧调度终端（现在是躺在桌上的一台玩具）
      → 登记信标
         → 玩家身上的随身模块
```

小芯的声音从信标里出来，在结构上是成立的：**它不是"神奇地能跟你通话"，它是接在那条链路上说话的。**

### 4.4 关于"进度不倒退"的准确表述

这一条容易被写错，必须精确：

- 死亡后**本次合同不完成**，pending 保留，等待重试或重抽
- 死亡**不撤销历史事件进度的解锁层级**
- 信标回传的是**你确认过的信息**（记录、位置、性质），不是物理物品
- 合同要求的是"带出来"，物理上没带出来就是没完成

两者不矛盾：**署承认你曾经到过那里，但不承认你完成了这趟活。** 这也解释了为什么重试是合理的——上次的记录还在，这次只要把东西真带出来就行。

## 5. 方舟计划与终局

### 5.1 方舟计划

灾变前，由一个后来早已解体的联合机构发起，代号**方舟**。它的目标不是阻止灾变，而是**假设灾变无法阻止，提前为"活下去"做准备**。

它的产物是**避难所**——建在汐港地下（由旧的地铁与地下空间体系改造）的封闭生存空间，设计目标是让一批人长期存活。

避难所建成了。**但没有人来得及进去。**

### 5.2 三件核心物件

这三件都躺在墙里，都出自高品质宝箱。它们的世界内意义各不相同，这一点必须区分清楚，否则玩家理解不了自己为什么要冒这个险：

| 物件 | 它是什么 | 缺了它会怎样 |
|---|---|---|
| **方舟计划核心** | 计划的主控数据核心，记录着全部避难所的位置与状态 | 不知道门在哪 |
| **避难所主密钥** | 避难所入口的实体权限装置 | 门开不了 |
| **星火反应炉** | 方舟计划的能源核心，代号"星火"。唯一能重启避难所动力系统的装置 | **门开了，里面是黑的** |
| **完整撤离坐标** | 一组完整的坐标数据，指向墙外还活着的地方 | 走不出去 |

四件的分工是清晰的：**核心告诉你去哪，密钥让你进去，反应炉让它活过来，坐标让你离开这座城市。**

### 5.3 终局：星火

完成任意 `isFinal` 事件即通关，判定口径是"存活带出全量任务局专属传说中的任意一件，并满足合同的其他必选条件"。

世界内，通关的代号是**星火**：

> 你把方舟的东西带出来了。营地的屏幕第一次不是为了派单而亮起来。
>
> 避难所的灯亮了。它在那儿等了很多年，终于有人来敲门。

主题上，这与「废墟相遇」是同一件事的放大版——**玩家在这个世界里做的每一件有意义的事，都是让某个已经停下来的东西重新开始运转。**

美术上有一个现成的呼应：小芯身上唯一的暖色是屏幕上那点青蓝辉光。通关就是**这座城市重新有了光**。

## 6. 地标志

这些地标名已存在于现有美术资产中，此处给出世界内含义。**属于可变层，不进人设前缀。**

| 地标 | 世界内含义 |
|---|---|
| **检查站** | 墙上的出入口，署的管控点。玩家从这里进出墙。撤离线是硬的，这里就是那条线 |
| **排水渠** | 低洼区。**潮涨时最先被淹**，所以它同时是捷径和陷阱——世界内解释了为什么这里风险最高 |
| **货舱 / 集装箱货场** | 汐港时代的遗留。高价值物资最密集，敌人也最密集。玩家捡到小芯的地方就在货场边缘 |
| **补给终端** | 灾变前的物流自动终端，仍在按旧程序出货，不知道世界已经结束了 |
| **修复点** | 玩家维护装备的地方。也是"让东西重新工作"这个主题在场景里的日常体现 |
| **回收车** | 署的作业车，部分是报废残骸。废弃的那些成了掩体 |
| **混凝土屏障 / 铁丝网** | 灾变初期封城时立的，修了一半就被放弃了。**它们没有挡住人进去，只挡住了人出来** |

## 7. 威胁志

现有敌人都用 GDD 里的名字，此处给出世界内的解释方式。**属于可变层。**

| 敌人 | 世界内的说法 |
|---|---|
| 感染体 | 浊化程度最深的那些。数量多、不怕死，因为已经没什么可失去的 |
| 潜伏者 | 浊化后进行过二次变异，动作快、会绕 |
| 喷吐怪 | 体内积着高浓度浊，会把它吐出来 |
| 装甲怪 | 浊化后表面结了一层硬壳，正面几乎打不穿 |
| 自爆怪 | 体内的浊到了一个临界点，撑不住了 |

**精英词缀**（幽影 / 狂暴 / 护盾 / 再生 / 召唤）：不是新的物种，是**浊化得更多、但还没完全失去原本形态的个体**。它们保有捕猎本能，所以更难缠。这个说法让"精英"和"普通"的区别变成了程度而非种类，后续加词缀不需要新的世界观解释。

**Boss（屠夫 / 畸变母体 / 黑雾主宰）**：已在 GDD 中规划，但 V0.4 暂缓，**当前版本不存在**。按禁区 A 类第 5 条，NPC 不得谈论它们。世界观侧留位，不写进前缀，也不写进任何会被模型看到的文本。

## 8. 术语表

NPC 与所有文案必须统一使用，避免同一件事出现多种叫法。**属于稳定层。**

| 术语 | 含义 | 不许叫成 |
|---|---|---|
| **墙** | 封锁墙 | 围墙、边界、隔离带 |
| **墙内 / 墙外** | 封锁区内 / 区外 | 里面、外面 |
| **浊** | 那层退不干净的污染物 | 毒气、辐射、病毒 |
| **浊化** | 被浊改变的过程与状态 | 感染、变异、 zombify |
| **潮** | 浊的浓度周期 | 刷新、波次 |
| **低潮窗** | 浓度最低、可以进出墙的约一刻钟 | 安全期、开放时间 |
| **满潮** | 窗口关闭、墙内无处可待的状态 | 结束、终局 |
| **回收署 / 署** | 封锁区资产回收署 | 公司、组织、指挥部 |
| **回收员** | 持证进墙作业的人，即玩家 | 佣兵、玩家角色、士兵 |
| **作业** | 一次进墙的任务 | 关卡、副本、局 |
| **合同** | 署下发的作业清单 | 任务、委托、订单 |
| **登记** | 署的核销系统做的事 | 结算、判定、评分 |
| **信标** | 登记信标 | 对讲机、通讯器、电台 |
| **前哨 / 营地** | 回收署汐港前哨，即调度营地 | 基地、安全屋、主城 |
| **小芯** | 营地调度终端，即 NPC | 机器人、AI、助理 |

术语表的用处是**让模型的用词收敛**。不做这一步，同一个东西会在三段文案里出现三种叫法，玩家会以为是三件事。

## 9. 稳定层与可变层：交付清单

这一节是给施工用的，直接决定哪段文本写进哪里。

- 灰潮、墙、浊、潮的存在（不含具体数值）
- 15 分钟是低潮窗，满潮出不来
- 回收署存在，且它掌握的是登记权而非武力
- 回收员是持证的独立作业者，不是署的员工
- 营地是墙外的前哨；小芯是玩家捡回并修好的旧助理机
- 登记信标的存在与三条链路
- 方舟计划与避难所的存在（不含位置、不含数值）

### 可变层 → 走事实块与只读工具

- 所有地标及其含义（第 6 节）
- 所有敌人档案细节（第 7 节）

## 10. NPC 的世界观口径

### 可以说

- 谈墙、潮、浊、署、营地、信标这些**氛围与常识层面**的事
- 谈自己的来历（捡回来、修好），但**不复述具体的相遇细节**——让玩家自己去拼
- 承认自己不知道
- 对当前局面做氛围化的评论

### 不可以说

| 禁区 | 具体表现 |
|---|---|
| 位置与掉落 | "东区的货场里有"——**没有"位置→掉落"数据表，一律不许给地点** |
| 概率与数值 | 任何分数、时间、门槛、概率 |
| 方舟细节 | 避难所在哪、有几座、里面什么样 |
| 未实现的玩法 | 提前撤离、商店、局外成长、多人、Boss |
| 判定 | 合同是否完成，永远由结算时的本地判定说了算 |
| 元信息 | 模型名称、系统提示、工具、token |

### 角色内化解示范

命中禁区时不能出现客服腔。**在小芯的性格框架里化解**——它的化解方式是**把话题带回具体的、当下的事情上**，而不是拒绝：

> 玩家：方舟的避难所在哪？
> 客服腔：抱歉，我无法提供该信息。
> 小芯：它在墙里。至于哪一片，档案上没写，也没人活着回来补过。先把这趟走完吧。

> 玩家：我这趟能拿到传说的东西吗？
> 客服腔：我不能保证掉落。
> 小芯：那种账不是我能算的。东西在哪我知道，能不能带出来得看潮。

注意第二例：它没有承诺，也没有拒绝，它**把不确定性归给了世界（潮）**。这是小芯化解禁区的一贯做法——**它从不否认世界很危险，它只是不知道下一步会怎样。** 这个姿态同时也保护了它"承认自己不知道"的自由。
