## 一、这节课实现了什么

第32课把项目从“直接进入测试场景”的开发状态，推进成了更接近可交付 Demo 的启动闭环。现在游戏有了主菜单入口，玩家可以从菜单开始一局，在结算页重开或返回主菜单，也可以在主菜单查看制作者声明。

本课完成后的场景流是：

```text
MainMenu
  ↓ 开始游戏
01-Run
  ↓ 胜利 / 失败
ResultView
  ├─ 重开：重新加载 01-Run
  └─ 返回主菜单：加载 MainMenu
```

这节课的重点不是“多做一个 UI 页面”，而是让 Build 版本有清楚的入口和退出路径。对外展示时，玩家不应该一启动就掉进测试场。

### 任务 1 · 重新确认课程优先级

本来第32课计划做新手目标提示，但试玩反馈说明：当前游戏已经通过宝箱距离、波次压力、掉落反馈和背包整理自然形成目标感。继续堆提示会增加 UI 噪音。

因此本课重新排期：

```text
新手目标提示 → Demo 后 P2 可选项
主菜单与场景流 → Demo 主线当前课
```

这个取舍很重要：Demo 冲刺期不是把所有能做的功能都塞进去，而是优先补交付链路。

### 任务 2 · 新增 MainMenu 场景

- 新增 `Assets/BackpackSurvivor/Scenes/MainMenu/MainMenu.unity`。
- 主菜单加入背景图和配套 UI。
- 提供开始游戏、退出游戏、制作者声明按钮。
- `AboutPanel` 默认隐藏，由按钮打开和关闭。

主菜单现在承担三个职责：开始游戏、退出程序、解释 Demo 身份。

### 任务 3 · 新增 MainMenuController

- 新增 `MainMenuController`，命名空间为 `BS.Presentation`。
- 通过 `[SerializeField] private Button` 接入按钮。
- `OnEnable()` 订阅按钮事件。
- `OnDisable()` 取消订阅按钮事件。
- `StartButton()` 加载 `01-Run`。
- `QuitButton()` 调用 `Application.Quit()`。
- `AboutButton()` / `CloseAboutButton()` 控制声明面板显隐。

本课继续沿用之前的事件习惯：订阅和退订必须镜像，按钮不写 Inspector OnClick 常驻绑定，逻辑集中在脚本中。

### 任务 4 · 修改 ResultView 返回主菜单

- `ResultView` 保留 Restart 逻辑：重开当前 Run 场景。
- 原 Quit 逻辑从 `Application.Quit()` 改成 `SceneManager.LoadScene("MainMenu")`。
- 返回主菜单前恢复 `Time.timeScale = 1f`。

这个改动让结算页变成真正的场景流节点，而不是程序终点。

### 任务 5 · 修正 Build Settings 场景顺序

本课发现并修复了一个隐藏风险：Build Settings 里曾残留旧路径 `Run1.unity`。

最终 Build Settings 顺序改为：

```text
0: Assets/BackpackSurvivor/Scenes/MainMenu/MainMenu.unity
1: Assets/BackpackSurvivor/Scenes/Run/01-Run.unity
```

这样 Build 启动时会先进入主菜单，Run 场景作为被加载的游戏场景。

### 任务 6 · 加入制作者声明面板

- 主菜单新增“制作者声明 / 关于 Demo”入口。
- 声明内容说明项目性质、当前版本内容、开发目标和素材使用边界。
- 声明面板使用 `Scroll View` 承载长文本。
- 只做手动滚动，不做自动滚动，避免打扰玩家阅读。

这一步对求职展示很有价值：试玩者能快速知道这是个人 Demo、主要展示什么能力、哪些内容还在开发中。

### 任务 7 · 修复主菜单 UI 分辨率适配

- CanvasScaler 从 `Constant Pixel Size` 改为 `Scale With Screen Size`。
- Reference Resolution 改为 `1920x1080`。
- Match Width Or Height 设置为 `0.5`。
- 主菜单面板、声明面板按全屏拉伸组织。
- Scroll View 的 Viewport、Scrollbar、Content 重新按 UGUI 规则整理。

这一步解决了屏幕尺寸变化时 UI 位置偏移的问题。

### 任务 8 · 最终验收通过

本课已通过用户实测与代码验收：

- MainMenu 可以打开制作者声明并关闭。
- MainMenu 点击开始游戏能进入 `01-Run`。
- Run 结算页点击重开能重新开始一局。
- Run 结算页点击返回主菜单能回到 MainMenu。
- 回到主菜单后可以再次开始游戏。
- CanvasScaler 在多分辨率下保持 UI 相对位置稳定。
- `dotnet build` 通过，危险 using 扫描干净。

## 二、最终代码（关键片段）

### 1. MainMenuController

```csharp
using UnityEngine;
using UnityEngine.SceneManagement;
using UnityEngine.UI;

namespace BS.Presentation
{
    public class MainMenuController : MonoBehaviour
    {
        [SerializeField] private Button startButton;
        [SerializeField] private Button quitButton;
        [SerializeField] private GameObject aboutPanel;
        [SerializeField] private Button aboutButton;
        [SerializeField] private Button closeAboutButton;

        private void Awake()
        {
            if (aboutPanel != null)
                aboutPanel.SetActive(false);
        }

        private void OnEnable()
        {
            if (startButton != null)
                startButton.onClick.AddListener(StartButton);
            if (quitButton != null)
                quitButton.onClick.AddListener(QuitButton);
            if (aboutButton != null)
                aboutButton.onClick.AddListener(AboutButton);
            if (closeAboutButton != null)
                closeAboutButton.onClick.AddListener(CloseAboutButton);
        }

        private void OnDisable()
        {
            if (startButton != null)
                startButton.onClick.RemoveListener(StartButton);
            if (quitButton != null)
                quitButton.onClick.RemoveListener(QuitButton);
            if (aboutButton != null)
                aboutButton.onClick.RemoveListener(AboutButton);
            if (closeAboutButton != null)
                closeAboutButton.onClick.RemoveListener(CloseAboutButton);
        }

        private void StartButton()
        {
            Time.timeScale = 1f;
            SceneManager.LoadScene("01-Run");
        }

        private void QuitButton() => Application.Quit();

        private void AboutButton() => aboutPanel.SetActive(true);

        private void CloseAboutButton() => aboutPanel.SetActive(false);
    }
}
```

这个类是主菜单的最小控制器。它不管理游戏状态，只负责按钮到场景行为的映射。

### 2. ResultView 返回主菜单

```csharp
private void HandleRestartClicked()
{
    Time.timeScale = 1f;
    int buildIndex = SceneManager.GetActiveScene().buildIndex;
    SceneManager.LoadScene(buildIndex);
}

private void HandleQuitClicked()
{

    SceneManager.LoadScene("MainMenu");
}
```

重开继续加载当前 Run 场景，返回主菜单则加载 `MainMenu`。两个分支都先恢复 `Time.timeScale`。

### 3. Build Settings 场景顺序

```text
0: Assets/BackpackSurvivor/Scenes/MainMenu/MainMenu.unity
1: Assets/BackpackSurvivor/Scenes/Run/01-Run.unity
```

这不是代码，但它是 Build 可复现的关键配置。场景流课必须把它当成正式交付内容。

### 4. CanvasScaler 设置

```text
UI Scale Mode: Scale With Screen Size
Reference Resolution: 1920 x 1080
Screen Match Mode: Match Width Or Height
Match: 0.5
```

这一步让主菜单 UI 从固定像素布局，升级为按参考分辨率缩放的适配布局。

### 5. 制作者声明 Scroll View

```text
AboutPanel
  TitleText
  Scroll View
    Viewport
      Content
        BodyText
    Scrollbar Vertical
  CloseButton
```

Scroll View 负责裁剪和手动滚动，脚本只负责打开/关闭面板，不干预滚动逻辑。

### 6. Scroll View 核心配置

```text
ScrollRect
  Horizontal: Off
  Vertical: On
  Movement Type: Clamped
  Viewport: Viewport
  Content: Content
  Vertical Scrollbar: Scrollbar Vertical
```

```text
Viewport
  Anchor: stretch full parent
  Mask / RectMask2D: enabled
```

```text
Content
  Anchor: top stretch
  Content Size Fitter: Vertical Fit = Preferred Size
  Vertical Layout Group: allows child preferred height
```

Scrollbar 问题不是写代码解决的，而是 RectTransform、Viewport 和 Content 三者要形成正确的 UGUI 结构。

## 四、设计思考

### 1. 为什么这节课比新手提示更优先？

当前局内目标已经比较自然：玩家会看到宝箱距离、掉落物、背包空间、波次压力和结算目标。再增加提示层，容易变成噪音。

主菜单不同，它是 Build 交付的第一眼。没有主菜单，项目仍然像测试工程；有了主菜单，才像一个可以交给别人打开的 Demo。

### 2. 为什么 Start 用场景名而不是 Build Index？

`SceneManager.LoadScene("01-Run")` 对 Build Settings 顺序变化更稳。Build Index 适合重载当前场景，但主菜单跳 Run 用名字更清楚。

这也是一种可读性：看到代码就知道要去哪个场景。

### 3. 为什么切场景前必须恢复 Time.timeScale？

Run 结束时 `GameSession.EndRun()` 会把 `Time.timeScale` 设为 0。如果此时直接切主菜单或重开，不恢复时间，下一场景可能出现 UI 动画、计时、输入反馈异常。

所以凡是从暂停/结算状态切场景，都先写：

```text
Time.timeScale = 1f
```

### 4. 为什么制作者声明放主菜单？

它不应该打断战斗，也不应该塞进 HUD。主菜单是低压力阅读区，玩家和面试官都可以在开始前了解项目边界。

这也能主动说明素材来源和 Demo 状态，避免别人误以为这是商业发布版本。

### 5. 为什么 Scrollbar 不需要代码控制？

这里只是普通说明文本，玩家自己滚动即可。自动滚动反而会让阅读失去控制感。

本课采用 ScrollRect 的标准能力：裁剪、手动滚动、滚动条显示。脚本只控制面板开关，职责更干净。

### 6. 为什么 CanvasScaler 是主菜单适配的根？

按钮位置看起来偏移时，很容易先去调单个 RectTransform。但如果 CanvasScaler 还是 `Constant Pixel Size`，所有位置都在用固定像素，换分辨率必然漂。

主菜单这种全屏 UI，第一步应该是定参考分辨率和缩放策略。

## 五、踩坑记录

### 1. Build Settings 残留旧场景路径

- **现象**：项目实际场景是 `01-Run.unity`，Build Settings 却还指向旧 `Run1.unity`。
- **根因**：场景改名或迁移后，Build Settings 不会自动同步。
- **修复**：重排 Build Settings，MainMenu 放 0，01-Run 放 1。
- **沉淀**：做场景流和 Build 前，必须检查 Build Settings，而不是只看 Project 目录。

### 2. MainMenuController 再次混入 Unity.VisualScripting using

- **现象**：代码能编译，但危险 using 扫描命中 `Unity.VisualScripting`。
- **根因**：IDE 自动导入无用 using。
- **修复**：删除该 using，并在收尾时继续跑 using 闸。
- **沉淀**：运行时代码里的无用 using 不靠编译器提醒，要靠提交前扫描。

### 3. Button 判空对象写错

- **现象风险**：`aboutPanel` 不为空但 `aboutButton` 漏拖时，订阅按钮事件会空引用。
- **根因**：判空写成了 `if (aboutPanel != null)`，但下一行实际使用的是 `aboutButton`。
- **修复**：改成 `if (aboutButton != null)`，退订同理。
- **沉淀**：判空要判马上要用的对象，不判旁边相关对象。

### 4. Scrollbar 不动不是脚本问题

- **现象**：Scrollbar Vertical 看起来接了，但拖不动或没有滚动效果。
- **根因**：早期 Viewport 高度为 0、Scrollbar 高度为 0，Content 没被 BodyText 撑高。
- **修复**：Viewport 全屏拉伸，Scrollbar 右侧上下拉伸，Content 用 Preferred Size 撑高。
- **沉淀**：ScrollRect 三件套是 Viewport 面积、Content 高度、Scrollbar 尺寸；少一个都不滚。

### 5. 分辨率变化后 UI 漂移

- **现象**：屏幕尺寸变化后，主菜单按钮和面板位置发生偏移。
- **根因**：CanvasScaler 仍是 `Constant Pixel Size`。
- **修复**：改为 `Scale With Screen Size`，参考分辨率 1920x1080，Match 0.5。
- **沉淀**：全屏 UI 适配先查 CanvasScaler，再查单个锚点。

## 六、面试问答

**Q1：你是怎么做主菜单场景流的？**  
> 我新增了 `MainMenu` 场景和 `MainMenuController`，通过按钮事件加载 `01-Run` 或退出程序。Build Settings 中 MainMenu 是第 0 个场景，Run 是第 1 个场景。结算页保留重开当前 Run 场景，同时把原退出按钮改为返回 MainMenu。

**Q2：为什么 Result 页返回主菜单前要恢复 Time.timeScale？**  
> 因为结算时游戏会暂停，`Time.timeScale` 为 0。如果直接切场景，新的场景可能继承暂停状态，导致计时、动画或 UI 表现异常。所以所有从暂停/结算状态切场景的入口都先恢复到 1。

**Q3：为什么主菜单开始游戏用场景名加载？**  
> 场景名表达更明确，也不依赖 Build Settings 的具体顺序。Build Index 更适合“重载当前场景”，所以 Restart 用当前 buildIndex，Start 用 `"01-Run"`。

**Q4：你怎么处理制作者声明？**  
> 我把声明做成主菜单中的弹窗面板，使用 Scroll View 显示长文本。这样不打断战斗，也能在试玩前说明 Demo 的开发目标、当前内容和素材使用边界。

**Q5：Scrollbar 不工作时你怎么排查？**  
> 我先看 ScrollRect 引用是否接上，再看 Viewport 是否有可视面积、Content 是否比 Viewport 高、Scrollbar 是否有高度。这个问题最后不是代码错，而是 RectTransform 和布局组件没形成正确结构。

**Q6：为什么主菜单要设置 CanvasScaler？**  
> 主菜单是全屏 UI，如果保持 Constant Pixel Size，分辨率变化时固定像素偏移会导致 UI 漂移。Scale With Screen Size 能按参考分辨率统一缩放，保证不同 16:9 分辨率下相对位置稳定。

**Q7：这节课对 Demo 交付有什么价值？**  
> 它补齐了外部试玩者的第一入口和结算后的回流路径。项目不再像一个编辑器测试场，而是一个能启动、能开始、能结束、能回菜单的完整 Demo。

## 七、习惯清单

1. 做 Build 前先检查 `EditorBuildSettings.asset`，不要信旧场景路径。
2. 场景切换前恢复 `Time.timeScale = 1f`。
3. Button 订阅写在 `OnEnable`，退订写在 `OnDisable`。
4. 判空要判马上要使用的对象。
5. 主菜单全屏 UI 使用 `Scale With Screen Size`，不要停留在 Constant Pixel Size。
6. ScrollRect 问题优先查 Viewport、Content、Scrollbar 三件套。
7. 制作者声明适合放主菜单，不放战斗 HUD。
8. 运行时代码提交前继续扫 `UnityEditor / ShadowCascadeGUI / Unity.VisualScripting`。
9. Demo 冲刺期优先补交付链路，不被低价值提示系统分散精力。

## 八、思考题（附复习参考）

**Q1：如果以后要加设置页，应该新建场景还是主菜单弹窗？**  
> Demo 阶段建议先做弹窗，因为设置项少，场景切换成本高。等设置复杂到包含分辨率、音量、键位、画质等多个分区时，再考虑独立设置面板或设置场景。

**Q2：为什么 Restart 可以用 buildIndex，而 Start 不推荐用 buildIndex？**  
> Restart 的语义是“重新加载当前场景”，当前场景 buildIndex 最准确。Start 的语义是“进入指定 Run 场景”，用名字更直观，也不容易被 Build Settings 顺序调整影响。

**Q3：如果主菜单背景图在 21:9 或 4:3 下变形，下一步怎么处理？**  
> 可以引入 `AspectRatioFitter` 或写一个轻量背景适配脚本，选择 Cover 策略：保持图片比例，铺满屏幕，允许裁切边缘。Demo 目前优先保证 16:9 稳定。

**Q4：为什么声明文本不用自动滚动？**  
> 自动滚动会抢玩家阅读节奏，声明面板不是片尾字幕。手动 Scrollbar 更符合“我想看就看，想关就关”的主菜单交互。

**Q5：如果 Build 中点击退出没有反应，应该怎么判断？**  
> 在 Editor 中 `Application.Quit()` 本来就不会真正关闭 Play。需要打包后验证，或在编辑器里临时加日志确认按钮事件被触发。不能把编辑器不退出误判为功能失败。
