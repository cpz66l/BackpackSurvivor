## 一、这节课实现了什么

第33课把项目从“系统已经能玩”推进到“截图和试玩更像一个可以交付的 Demo”。这一课没有开大系统，而是集中处理外部试玩第一眼能感受到的东西：场景地面、边界提醒、宝箱辨识、掉落反馈、背包 UI 占屏问题，以及光照和阴影。

本课完成后的 Demo 观感链路是：

```text
主菜单进入 Run
  ↓
冷灰/暗绿调地面 + 地图边界提醒
  ↓
宝箱模型更醒目，按稀有度区分
  ↓
敌人死亡掉落装备 / 经验 / 金币都有散落反馈
  ↓
Tab 打开 / 关闭背包，战斗视野更干净
  ↓
地面吃光照，玩家与场景能产生阴影
```

这节课的核心价值不是“美术大改”，而是 Demo 冲刺期的包装补强。别人第一次打开项目时，不会只看到一块测试地板和永远摊开的背包面板。

### 任务 1 · 场景视觉包装

- 地面换成定制贴图。
- 地图边界加入范围提醒。
- 宝箱换成更显眼的模型，并能区分宝箱稀有度。
- 掉落物、经验、金币都达到可见状态。
- 危险区表现暂缓到 Demo 后，不挤占 V0.2 冲刺期。

这里的取舍很正确：当前 Demo 已经有宝箱距离、波次压力和背包整理节奏，危险区视觉不是阻断项。先把已有系统包装清楚，比继续补一个新压力源更划算。

### 任务 2 · 装备掉落复用散落协程

原来经验和金币会从敌人身上飞散出来，装备掉落相对“硬落地”，反馈不统一。本课把装备掉落也接入 `DropItem.PlayScatterFlight()`。

改完后，敌人死亡掉落装备时会和经验、金币一样有短距离飞散，视觉语言统一：

```text
敌人死亡
  ↓
LootManager.TrySpawnDrop
  ↓
SpawnEntry(entry)
  ↓
Equipment → DropItem.Initialize(entry)
  ↓
DropItem.PlayScatterFlight(from, target)
```

装备不需要重新造一套飞行动画。复用现有协程，成本低、表现提升明显。

### 任务 3 · 背包改为 Tab 开关

背包一直显示会占据大量屏幕空间，尤其加了边框和美术后更明显。本课新增 `OpenBag` 输入，默认用 `Tab` 控制背包显示 / 隐藏。

现在背包的定位更接近：

```text
战斗时：默认关闭，保留视野
整理时：按 Tab 打开，管理背包
拖拽时：禁止关闭，避免临时态丢失
```

这让战斗画面更干净，也保留了背包幸存者的“空档期整理背包”节奏。

### 任务 4 · 背包 UI 美术与交互保护

- 背包加入边框和基础 UI 美术。
- 使用 `CanvasGroup` 控制显示、交互和射线。
- 背包关闭时隐藏 Tooltip。
- 拖拽过程中不允许切换背包开关，避免 ghost / dragItem 临时态被破坏。

本课继续贯彻一个 UI 规则：显示层可以隐藏，但交互状态必须同步关掉。只改 alpha 不关 `blocksRaycasts`，会变成透明面板吃射线。

### 任务 5 · 修复物品丢弃再拾取等级重置

试玩中发现：从背包丢弃物品，再捡回来，物品等级会回到 1 级。

本课把运行时等级纳入 `Item → LootEntry → Item` 往返链路：

```text
Item.Level
  ↓ DiscardToWorld
LootEntry.level
  ↓ CreateItemFromLootEntry
new Item(..., level)
```

这一步很关键，因为等级已经不只是 UI 显示，它会影响：

- 武器稀有度/等级伤害倍率。
- 芯片效果数值。
- 物品价值。
- 背包构筑决策。

所以等级必须是运行时状态的一部分，而不是每次落地都重置的临时显示。

### 任务 6 · 修复重新开始后状态未刷新

一局结束后点击重新开始，出现过状态疑似没有完整刷新的问题。本课重点补了静态运行时状态的重置。

涉及两类静态状态：

- `TargetRegistry`：敌人目标注册表。
- `LootChest`：未开启宝箱列表和场上宝箱计数。

修复方向是：每次 `GameSession.StartRun()` 都明确清理这些运行时静态状态，而不是假设场景重载一定会帮我们清干净。

### 任务 7 · 修复地面不受光照、角色没有阴影

地面不受光照的主要原因是材质 / Shader 路径不对，像 Unlit 一类材质只显示贴图，不参与光照计算。玩家没有影子，则要同时确认：

```text
灯光支持阴影
  + Renderer Cast Shadows 开启
  + 地面 Receive Shadows 开启
  + 材质使用 Lit Shader
  + URP Asset 支持阴影
```

本课新增 `M_Ground_Quarantine_Lit.mat`，让地面走 URP Lit 材质，并在 Run 场景中接到地面 Renderer 上；同时确认玩家模型和地面 Renderer 的投影 / 接影开关。

### 任务 8 · 最终验收通过

本课已完成用户实测与代码验收：

- 装备掉落会复用散落协程。
- 背包可以通过 Tab 打开 / 关闭。
- 拖拽中不会因为关包破坏拖拽状态。
- Tooltip 在关包时会隐藏。
- 丢弃再拾取保留物品等级。
- 一局结束后重开能正常刷新运行时状态。
- 地面材质开始参与光照，角色/地面阴影链路已接入。
- `dotnet build` 通过，危险 using 扫描干净。

## 二、最终代码（关键片段）

### 1. LootEntry 保留运行时等级

```csharp
[Tooltip("运行时物品等级，掉落配置默认 1")]
public int level = 1;
```

`LootEntry` 原本只承担静态掉落配置。现在它在“物品被丢到世界”这条链路中，也临时承载运行时等级。

注意这里不是让 ScriptableObject 记录运行时等级，而是让一次世界掉落实例携带等级信息。静态配置和运行时实例依然分离。

### 2. Item 构造时接收并钳制等级

```csharp
MaxLevel = 3;

if (level < 1) level = 1;
if (level > MaxLevel) level = MaxLevel;

Level = level;
```

构造函数负责把外部传入的等级压到合法区间。这样即使某个掉落配置填错，也不会生成 Lv.0 或超过上限的物品。

### 3. DiscardToWorld 写回 Level

```csharp
LootEntry entry = new LootEntry
{
    id = item.Id,
    rarity = item.Rarity,
    width = item.BaseWidth,
    height = item.BaseHeight,
    itemTag = item.Tag,
    connectableSides = item.LocalConnectableSides,
    scoreValue = item.BaseScoreValue,
    effectValue = item.BaseEffectValue,
    level = item.Level
};
```

丢弃物品时必须写 `BaseScoreValue / BaseEffectValue`，否则 Lv.2 当前值会污染 Lv.1 基础值；同时写 `Level`，让重新拾取还能恢复升级状态。

### 4. 装备掉落也播放散落协程

```csharp
if (entry.category == DropCategory.Equipment)
{
    Vector2 randomOffset = Random.insideUnitCircle * offset;
    Vector3 target = position + new Vector3(randomOffset.x, 0, randomOffset.y);

    DropItem dropItem = dropPool.Get(position).GetComponent<DropItem>();
    dropItem.Initialize(entry);
    dropItem.PlayScatterFlight(position, target);
    return dropItem.gameObject;
}
```

装备、经验、金币用同一种“从死亡点散开”的表现语言，玩家会更容易理解这是同一类战利品反馈。

### 5. DropItem 防止旧飞行协程污染池化对象

```csharp
if (flightRoutine != null)
{
    StopCoroutine(flightRoutine);
    flightRoutine = null;
}

survivalTimer = 0f;
itemCollider.enabled = true;
isCollected = false;
```

池化对象最大的问题是“上次运行态残留”。`flightRoutine` 是本课新增运行时字段，所以必须同一分钟放进 `OnGetFromPool()` 归零。

### 6. InputReader 新增 OpenBag 事件

```csharp
public event Action OnOpenBag;

public void OpenBag(InputAction.CallbackContext ctx)
{
    if (ctx.performed) OnOpenBag?.Invoke();
}
```

输入层只广播意图，不知道背包怎么显示。这样 `InputReader` 仍然是“输入翻译器”，不是 UI 控制器。

### 7. InventoryUIController 用 CanvasGroup 开关背包

```csharp
public void HandleOpenBag()
{
    if (bagPanelcanvasGroup == null || isDragging) return;

    isBagOpen = !isBagOpen;

    if (isBagOpen)
    {
        bagPanelcanvasGroup.alpha = 1;
        bagPanelcanvasGroup.interactable = true;
        bagPanelcanvasGroup.blocksRaycasts = true;
    }
    else
    {
        bagPanelcanvasGroup.alpha = 0;
        bagPanelcanvasGroup.interactable = false;
        bagPanelcanvasGroup.blocksRaycasts = false;
        HideTooltip();
    }

    Redraw();
}
```

这里同时控制三件事：可见、可交互、是否吃射线。UI 显隐不能只改 alpha。

### 8. 重新开始前清静态状态

```csharp
public void StartRun()
{
    playerRunStats.ResetToDefault();
    TargetRegistry.Clear();
    LootChest.ResetRuntimeState();
    timer.Reset();
    levelProgress.Reset();
    killCount = 0;
    totalGold = 0;

    SetState(GameState.Running);
    BroadcastXpChanged();
}
```

这一步的原则是：场景重载不是运行时状态重置的唯一来源。凡是 static 保存的局内状态，都应该有明确 Reset 入口。

### 9. 地面 Lit 材质

```text
M_Ground_Quarantine_Lit.mat
Shader: Universal Render Pipeline/Lit
BaseMap: 当前地面贴图
Scene: 01-Run.unity 地面 Renderer 引用该材质
```

材质从“不参与光照的贴图显示”转成“参与 URP 光照和接影的 Lit 材质”，地面才会真正融入场景灯光。

## 四、设计思考

### 1. 为什么第33课不继续开大系统？

现在 Demo 已经有 15 分钟节奏、背包构筑、波次压力、宝箱路线、金币/经验反馈和主菜单场景。此时再加一个大系统，收益不一定超过风险。

第33课选择做演示包装，是因为外部试玩会先看画面秩序：地面是否像场景、物品是否看得见、背包是否挡视野、重开是否稳定。它们不是炫技功能，但会决定 Demo 是否“像完成了一版”。

### 2. 为什么危险区暂缓？

危险区本身是好机制，但当前 V0.2 的核心体验已经成立：玩家会在战斗空档整理背包，同时看宝箱距离去找资源。危险区会额外改变路线压力和数值节奏，需要更多测试。

Demo 冲刺期的原则是：能显著提升观感且低风险的先做，会改变核心节奏的新压力源后放。

### 3. 为什么背包要做开关？

背包是核心系统，但不应该永远抢屏。玩家真正需要它的时刻是整理、拖拽、比较物品；战斗和跑图时，打开背包反而降低画面可读性。

用 Tab 开关后，背包从“常驻 HUD”变成“玩家主动调出的管理界面”，更符合幸存者类游戏的战斗节奏。

### 4. 为什么用 CanvasGroup 而不是 SetActive？

`SetActive(false)` 简单，但会触发生命周期变化，容易影响订阅、缓存和临时拖拽状态。`CanvasGroup` 更适合 UI 面板显隐：对象仍在层级中，脚本仍存在，只是显示和交互被关掉。

这也方便以后做渐隐动画。

### 5. 为什么拖拽时禁止关背包？

拖拽期间存在 `dragItem`、`ghost`、旧锚点、预览格子等临时态。如果这时关包，视觉和数据很容易不同步。

本课用 `isDragging` 作为保护门闸，先保证交互正确，再考虑以后更复杂的“关包自动取消拖拽”。

### 6. 为什么等级要跟着 LootEntry 走？

`Item` 是运行时物品，`LootEntry` 是世界掉落载体。玩家把物品从背包丢到世界，再捡回来，本质上是一次运行时状态转移。

等级不应该写回 ScriptableObject，因为那会污染静态配置；也不能丢失，因为它影响战斗和价值。所以正确位置是：临时 `LootEntry.level` 承载这一次掉落实例的等级。

### 7. 为什么重新开始要主动清 static？

static 字段不归场景对象生命周期管理。Unity 重载场景时，场景对象会销毁重建，但 static 列表、计数器仍可能保留旧内容，尤其在关闭 Domain Reload 或 Enter Play Mode 优化时更明显。

Demo 中凡是“本局状态”的 static，都应该在 `StartRun()` 或等价入口明确清理。

### 8. 为什么地面要换 Lit 材质？

贴图本身只解决“长什么样”，Lit 材质解决“怎么被光照”。如果地面用 Unlit，看起来会像贴在屏幕上的图片，不吃灯光，也不容易接住阴影。

想让角色、地面、宝箱处在同一个空间里，至少要保证主地面材质参与光照。

## 五、踩坑记录

### 1. 丢弃再拾取等级重置

- **现象**：背包里 Lv.2 物品丢到地上，再捡回来变回 Lv.1。
- **根因**：`Item → LootEntry → Item` 往返链路没有保存 `Level`，构造函数默认等级为 1。
- **修复**：`LootEntry` 增加 `level`；丢弃时写 `item.Level`；拾取创建 Item 时传入 `entry.level`；构造函数钳制合法等级。
- **沉淀**：运行时状态跨载体流转时，要画完整往返链路，不要只看生成入口。

### 2. 重新开始后运行态疑似残留

- **现象**：一局结束后点击重新开始，状态没有像新一局一样完全刷新。
- **根因**：部分本局状态放在 static 容器中，场景重载不一定清理。
- **修复**：`TargetRegistry.Clear()` 和 `LootChest.ResetRuntimeState()` 在 `GameSession.StartRun()` 中主动调用。
- **沉淀**：static 是跨场景状态，要么是全局配置，要么必须有重置入口。

### 3. 装备飞行协程需要池化归零

- **现象风险**：装备飞散过程中被回收，再出池可能继承旧协程或关闭碰撞器状态。
- **根因**：协程句柄是新增运行时字段，池化复用时不会自动清掉。
- **修复**：保存 `flightRoutine`，出池时 Stop 并置空，碰撞器重开，计时和 collected 状态归零。
- **沉淀**：池化类新增字段，同一分钟补 `OnGetFromPool()`。

### 4. 透明 UI 也会吃射线

- **现象风险**：背包 alpha 为 0 后，如果 `blocksRaycasts` 仍为 true，玩家看不见面板但点击会被挡住。
- **根因**：UGUI 可见性和射线阻挡是两套状态。
- **修复**：关包时同时设置 `alpha=0`、`interactable=false`、`blocksRaycasts=false`。
- **沉淀**：UI 开关要三件套同步，不要只隐藏画面。

### 5. 地面不受光照不是灯光一个人的问题

- **现象**：地板看起来不受光照影响，角色没有明显影子。
- **根因**：光照链路需要灯光、Renderer、材质、URP 设置共同成立；Unlit 地面不会按真实光照表现。
- **修复**：新增 URP Lit 地面材质，场景 Renderer 开投影/接影。
- **沉淀**：影子问题要查整条链路，不要只调 Directional Light 强度。

### 6. 资产移动要带上 meta

- **现象风险**：美术资产从旧目录迁到 `Art/Textures` 后，如果只提交 png 不提交 `.meta`，别人拉仓库可能丢引用或导入设置变化。
- **根因**：Unity 资产引用靠 `.meta` 里的 GUID，而不是文件名。
- **修复**：提交新路径下的资源和 `.meta`，同时提交旧路径删除。
- **沉淀**：Unity 项目可复现提交 = 资源文件 + `.meta` + 场景/Prefab 引用一起提交。

## 六、面试问答

**Q1：这一课你为什么先做演示包装，而不是继续加机制？**  
> 因为 V0.2 Demo 的系统闭环已经成立，当前最大短板是外部试玩第一眼观感和稳定性。场景、掉落反馈、背包开关和阴影都属于低风险高感知收益改动，更适合 Demo 冲刺期。

**Q2：装备散落为什么复用已有协程？**  
> 经验和金币已经有相同表现，装备只缺接入。复用能保证视觉语言一致，也避免多写一套动画逻辑。真正需要分化时，可以在参数层调整飞行距离、时间和高度。

**Q3：背包为什么用 Tab 开关？**  
> 背包是核心管理界面，但战斗时常驻会占视野。Tab 开关让玩家在安全空档主动整理背包，既保留背包玩法，又提升跑图和战斗画面可读性。

**Q4：为什么关包时要同时设置 alpha、interactable、blocksRaycasts？**  
> `alpha` 只影响视觉，`interactable` 影响 UI 控件交互，`blocksRaycasts` 影响射线阻挡。只改 alpha 会出现透明 UI 挡点击的问题，所以三者必须同步。

**Q5：你怎么避免物品丢弃再拾取后丢失等级？**  
> 我把 `Level` 从 `Item` 写入世界掉落实例 `LootEntry.level`，再在拾取时用这个 level 构造新的 `Item`。这样不污染静态配置，也能保留运行时状态。

**Q6：Unity 场景重载后为什么还要清 static？**  
> static 字段属于 AppDomain，不属于场景对象。场景重载只保证场景对象重建，不保证静态列表和计数清空。目标注册表、宝箱计数这种本局状态必须显式 Reset。

**Q7：地面不受光照时你会怎么排查？**  
> 我会按链路查：灯光是否开启阴影，URP Asset 是否支持阴影，角色 Renderer 是否 Cast Shadows，地面 Renderer 是否 Receive Shadows，地面材质是否使用 Lit Shader。

**Q8：这一课对简历展示有什么帮助？**  
> 它体现了我不只会堆功能，还会做可交付 Demo 的体验收口：输入、UI、场景表现、对象池状态、静态状态、资产可复现提交都被纳入验收。

## 七、习惯清单

1. Demo 冲刺期优先做低风险高感知收益的改动。
2. UI 显隐要同步 `alpha / interactable / blocksRaycasts`。
3. 拖拽期间的临时态要有门闸保护。
4. 运行时物品状态跨世界掉落流转时，必须检查 `Item → LootEntry → Item` 往返保真。
5. ScriptableObject 存静态配置，不写入局内运行状态。
6. static 本局状态必须有 Reset 入口，并在新一局开始时调用。
7. 池化类新增运行时字段，立刻补 `OnGetFromPool()` 归零。
8. 世界散落表现尽量复用同一套飞行语言，除非设计上需要差异。
9. Unity 资源移动必须提交新资源、新 `.meta`、旧路径删除和引用变化。
10. 光照问题按整条链路排查，不只调灯光强度。

## 八、思考题（附复习参考）

**Q1：为什么危险区表现可以后移，而背包开关应该现在做？**  
> 危险区会改变路线压力和数值节奏，需要更多平衡验证；背包开关主要改善画面可读性，不改变核心规则，风险更低、收益更直观。

**Q2：如果以后想让关包时自动取消拖拽，应该改哪里？**  
> 应该在 `InventoryUIController` 内部做统一取消拖拽流程，清理 ghost、恢复旧位置或执行丢弃，并补 Redraw。不能只在输入层强行关面板。

**Q3：为什么 `LootEntry.level` 不等于把运行时状态写进 SO？**  
> 因为这里的 `LootEntry` 是一次生成出来的掉落实例数据，来自 SO 的配置只是初始模板。只要不把运行时 level 回写到资产文件，就没有污染静态配置。

**Q4：如果别人拉项目后地面材质丢失，最可能漏提交什么？**  
> 最可能漏提交 `.mat` 或 `.mat.meta`，也可能漏提交贴图 `.meta`。Unity 引用靠 GUID，`.meta` 是资产可复现的关键。

**Q5：为什么重开问题常常不是 ResultView 按钮本身的问题？**  
> ResultView 只负责发起场景加载。真正的新局状态还取决于 `GameSession.StartRun()` 是否重置运行时数据，以及 static 容器是否清空。

**Q6：装备散落飞行期间为什么要关碰撞器？**  
> 飞行期间如果碰撞器开启，玩家可能在物品还没落地时就拾取或交互，导致视觉和状态不同步。落地后再打开碰撞器，交互节奏更稳定。

**Q7：为什么地面用 Lit 材质后画面会更“统一”？**  
> 因为玩家、宝箱、敌人和地面都参与同一套光照。即使素材不是同一个来源，只要光照响应一致，空间感就会更统一。
