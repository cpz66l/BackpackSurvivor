## v0.3.1 · 三选一升级候选池模块

### 状态

- 已正式开工。
- 本模块采用小快照推进：`v0.3.1.1` 到 `v0.3.1.x`。
- 核心生成逻辑与关键架构由用户亲写；重复枚举、文案、分支和低风险样板可由 AI 提供。

### 模块目标

- 将升级系统从“固定 3 个硬编码选项”升级为“可扩展候选池”。
- 第一批候选池扩展到 12 个以上，覆盖攻击、生存、机动、搜刮、构筑五类。
- 支持权重、等级门槛、同轮不重复、最大选择次数等基础规则。
- 新升级必须能被真实消费侧使用，避免出现“能选但无效果”的假内容。
- 保持 `LevelUpChoiceView` 只负责展示，不承担升级规则。

### 小快照安排

- `v0.3.1.0`：脚本目录轻量整理，只移动文件与 `.meta`，不改命名空间和代码逻辑。
- `v0.3.1.1`：升级定义层重构，新增候选定义结构，旧 3 个选项行为保持不变。
- `v0.3.1.2`：扩展 `PlayerRunStats`，承接更多运行期属性。
- `v0.3.1.3`：接入消费侧，让暴击、范围、拾取、金币、经验、减伤等属性真实生效。
- `v0.3.1.4`：扩容候选池、接入权重、等级门槛、同轮不重复和最大选择次数。
- `v0.3.1.5`：连续升级体验验收与首轮数值调参。
- `v0.3.1.6`：模块复盘、文档同步、提交版本节点。

### 验收标准

- 连续升级多次不会只反复出现旧 3 个选项。
- 每个选项都有明确分类、标题、描述、数值和真实消费侧。
- 重开一局后所有升级属性能回到默认值。
- 候选生成规则可解释，可继续扩展到后续更多升级项。

### 当前第一步

- 先插入 `v0.3.1.0`，整理脚本目录结构。
- 目录整理完成并通过 Unity 编译后，再进入 `v0.3.1.1` 定义层重构。

## v0.3.1.0 · 脚本目录轻量整理

### 目标

- 在正式扩展升级候选池前，先降低脚本目录拥挤度。
- 只移动 `.cs` 与 `.cs.meta`，不修改命名空间、不修改代码逻辑。
- 为后续升级、邻接、Boss、音频、存档模块预留清晰落点。

### 改动

- `Core` 拆为 `Pooling`、`World`。
- `Data` 增加 `Loot` 子目录。
- `GamePlay/Combat` 拆为 `Damage`、`Weapons`、`Projectiles`、`Targeting`。
- `GamePlay/Loot` 拆为 `Chests`、`Drops`、`Collection`、`Rolling`。
- `GamePlay/Upgrades` 拆为 `Definitions`、`Generation`、`Runtime`。
- `GamePlay` 增加 `Inventory` 子目录承接 `InventorySystem`。
- `GamePlay/Enemies` 增加 `AI` 子目录承接 `EnemyAI`。
- `Inventory` 拆为 `Core`、`Items`、`Adjacency`，保留 `BS.Inventory.asmdef` 在根目录以覆盖子目录。
- `Presentation` 拆为 `HUD`、`Inventory`、`LevelUp`、`MainMenu`、`Result`、`Feedback`、`Audio`、`Common`。

### 验收

- Unity 能重新编译通过。
- 场景中原有脚本引用不丢失。
- `BS.Inventory` 纯 C# asmdef 仍覆盖 `Inventory` 子目录。
- 扫描不到 `UnityEditor`、`ShadowCascadeGUI`、`Unity.VisualScripting` 运行时代码引用。
