## 一、这节课实现了什么

### 任务 1 · 经验成长从“显示字段”变成“规则系统”

- 新增 `LevelProgress`，把经验、等级、当前经验、下一级阈值拆成独立的纯数据状态。
- `AddXp()` 支持一次吃入多点经验，并返回本次连升次数。
- `StartRun()` 仍然负责每局初始化，经验相关状态统一回到 1 级 / 0 经验。

### 任务 2 · 升级奖励抽象成可扩展选项

- 新增 `LevelUpOptionId`，用枚举表达奖励类型，不再靠裸 `int`。
- 新增 `LevelUpOption`，承载 `Id / Title / Description / Value`。
- 新增 `LevelUpOptionGenerator`，统一生成 3 个不重复选项，UI 不再自己拼奖励。

### 任务 3 · 升级流程进入单独状态

- `GameState` 新增 `LevelUpSelecting`。
- `GameSession` 在升级时切到 `LevelUpSelecting`，并通过 `Time.timeScale = 0` 暂停战斗。
- 选完后恢复 `Running`，升级面板和暂停面板成为两条不同状态链。

### 任务 4 · 三选一 UI 只负责展示和回传

- 新增 `LevelUpChoiceView`，负责接收 3 个 `LevelUpOption` 并刷新按钮文案。
- 三个按钮分别回传第 0 / 1 / 2 个选项。
- UI 不直接改数值，只把选择结果交回 `GameSession`。

### 任务 5 · 运行时数值入口统一

- 新增 `PlayerRunStats`，作为本局升级效果的唯一落点。
- 当前先支持三种倍率：
  - `DamageMultiplier`
  - `FireRateMultiplier`
  - `MoveSpeedMultiplier`
- `Apply(option)` 里通过 `switch(option.Id)` 分发效果。

### 任务 6 · 消费侧接入升级倍率

- `PlayerController` 读取移速倍率。
- `WeaponBase` 读取伤害倍率。
- `AutoWeapon` / `ActiveWeapon` 读取射速倍率。
- 这样升级效果不会散落到多个系统里，后续加新奖励只要补 `PlayerRunStats` 和 `Apply()`。

## 二、最终代码（关键片段）

### LevelProgress：只管经验事实

```csharp
public int AddXp(int amount)
{
    if (amount <= 0) return 0;

    int levelUpCount = 0;
    currentXp += amount;
    totalXp += amount;

    while (currentXp >= XpToNextLevel)
    {
        currentXp -= XpToNextLevel;
        levelUpCount++;
        level++;
    }

    return levelUpCount;
}
```

### LevelUpOption：奖励数据本体

```csharp
public class LevelUpOption
{
    private LevelUpOptionId id;
    private string title;
    private string description;
    private float value;

    public LevelUpOptionId Id => id;
    public string Title => title;
    public string Description => description;
    public float Value => value;
}
```

### LevelUpOptionGenerator：统一产出 3 个不重复选项

```csharp
public List<LevelUpOption> Generate(int level, int count)
{
    List<LevelUpOption> result = new List<LevelUpOption>();
    List<LevelUpOption> candidates = new List<LevelUpOption>(optionPool);

    while (result.Count < count && candidates.Count > 0)
    {
        int index = UnityEngine.Random.Range(0, candidates.Count);
        LevelUpOption option = candidates[index];
        result.Add(option);
        candidates.Remove(option);
    }

    return result;
}
```

### GameSession：升级时暂停，选完后恢复

```csharp
private void RequestLevelUpChoice(int level)
{
    if (state != GameState.Running) return;

    Time.timeScale = 0f;
    SetState(GameState.LevelUpSelecting);

    List<LevelUpOption> options = levelUpOptionGenerator.Generate(level, 3);
    OnLevelUpChoiceRequested?.Invoke(options);
}

public void ChooseLevelUpOption(LevelUpOption option)
{
    if (state != GameState.LevelUpSelecting) return;
    if (option == null) return;
    if (playerRunStats == null) return;

    playerRunStats.Apply(option);
    CompleteLevelUpChoice();
}
```

### LevelUpChoiceView：显示三项，并把选择回传

```csharp
private void HandleLevelUpChoiceRequested(List<LevelUpOption> options)
{
    currentOptions = options;
    choiceOneTitle.text = options[0].Title;
    choiceTwoTitle.text = options[1].Title;
    choiceThreeTitle.text = options[2].Title;
    choiceOneDescription.text = options[0].Description;
    choiceTwoDescription.text = options[1].Description;
    choiceThreeDescription.text = options[2].Description;
    Open();
}
```

### PlayerRunStats：统一应用升级效果

```csharp
public void Apply(LevelUpOption option)
{
    switch (option.Id)
    {
        case LevelUpOptionId.DamageUp:
            damageMultiplier += option.Value;
            break;
        case LevelUpOptionId.FireRateUp:
            fireRateMultiplier += option.Value;
            break;
        case LevelUpOptionId.MoveSpeedUp:
            moveSpeedMultiplier += option.Value;
            break;
    }
}
```

### 消费侧：只读倍率，不认识升级 UI

```csharp
float finalMoveSpeed = moveSpeed * stats.MoveSpeedMultiplier;
float finalAttackInterval = attackInterval / stats.FireRateMultiplier;
float finalDamage = damage * stats.DamageMultiplier;
```

## 三、周期链路

### 前半段：经验进入三选一

```text
XpOrb.Collect()
  ↓
GameSession.HandleXpCollected()
  ↓
LevelProgress.AddXp()
  ↓
升级次数 > 0
  ↓
RequestLevelUpChoice(level)
  ↓
LevelUpOptionGenerator.Generate(level, 3)
  ↓
Time.timeScale = 0
  ↓
SetState(LevelUpSelecting)
  ↓
OnLevelUpChoiceRequested(options)
  ↓
LevelUpChoiceView 刷新按钮文案
  ↓
玩家点按钮 0 / 1 / 2
```

### 后半段：选择变成真实数值

```text
LevelUpChoiceView.SelectChoiceOne/Two/Three()
  ↓
GameSession.ChooseLevelUpOption(option)
  ↓
PlayerRunStats.Apply(option)
  ↓
DamageMultiplier / FireRateMultiplier / MoveSpeedMultiplier 改变
  ↓
PlayerController / WeaponBase / AutoWeapon / ActiveWeapon 读取倍率
  ↓
CompleteLevelUpChoice()
  ↓
Time.timeScale = 1
  ↓
SetState(Running)
```

## 四、设计思考

### 1. 为什么 `LevelUpOptionId` 用枚举，而不是 int？

因为枚举能保留语义。

`2` 这种数字很快会失忆，`LevelUpOptionId.FireRateUp` 不会。

### 2. 为什么奖励生成器要单独抽出来？

因为它只负责“出卡”，不负责“显示”也不负责“生效”。

这样后续想加：

- 按等级解锁
- 按稀有度加权
- 按职业池过滤
- 按已选奖励去重

都只改生成器，不动 UI 和消费侧。

### 3. 为什么升级效果集中到 `PlayerRunStats`？

因为它是本局的运行时状态主人。

以后加 `MaxHp / PickupRange / ProjectileSpeed / CritChance`，都可以继续往这里扩，不会把逻辑打散到 `PlayerController`、`WeaponBase`、`PickUpMagnet` 里。

### 4. 为什么 `GameSession` 负责暂停和恢复？

因为这是局内规则，不是 UI 规则。

升级面板只是“原因”，真正让战斗暂停的是 `GameSession`。

### 5. 为什么当前阶段适合 `switch(option.Id)`？

因为现在只有少量奖励，`switch` 简洁、好调试、好 review。

等奖励数量涨到很多，再考虑更数据化的配置方式也不迟。

## 五、踩坑记录

### 1. `Random.Range` 上界要注意

- `Random.Range(0, candidates.Count)` 才是正确写法。
- 写成 `Count - 1` 会少抽最后一个候选。

### 2. 奖励文案和 ID 容易对反

- `MoveSpeedUp` 对应移速。
- `FireRateUp` 对应射速。
- 标题和描述要和 `Value` 保持一致，不然 UI 会骗玩家。

### 3. 基类和派生类的 stats 缓存要统一

- `WeaponBase` 负责缓存 `PlayerRunStats`。
- 派生类不要自己再藏一份同名 `stats`，不然会读到不同对象。

### 4. 升级后必须回到正确状态

- 只有在 `LevelUpSelecting` 时才允许选择。
- 选完后必须恢复 `Running`，不能让战斗永远停在 0 倍速。

### 5. 提交前建议清掉调试输出

- `ActiveWeapon.Update()` 里现在还有临时 `Debug.Log`。
- `StartRun()` 里后续最好补一次 `PlayerRunStats.ResetToDefault()`，为重开做准备。

## 六、面试问答

**Q1：为什么要做 `PlayerRunStats`？**  
> 因为升级效果需要一个统一的运行时入口。它负责保存当前局的倍率，不让升级效果散落到多个脚本里。

**Q2：为什么三选一要先生成选项，再交给 UI？**  
> 因为 UI 只负责展示，不应该知道“怎么随机”和“怎么结算”。这样后续改奖励池不会动 UI。

**Q3：为什么升级时要切到 `LevelUpSelecting`？**  
> 因为升级面板和普通暂停不是一回事。这个状态能明确告诉系统：现在是“选奖励”，不是“玩家按了 Esc 暂停”。

**Q4：为什么武器和玩家都只读倍率？**  
> 因为它们是消费侧。消费侧只负责使用当前值，不负责决定奖励类型，这样边界最清楚。

**Q5：为什么当前用 `switch(option.Id)` 够用？**  
> 因为当前奖励数量少，`switch` 最直接、最容易 debug，也最适合 Demo 冲刺期。

## 七、习惯清单

1. 新增升级能力时，先想清楚它属于“出卡”“展示”还是“生效”。
2. 奖励数据不要让 UI 自己拼，统一从生成器拿。
3. 运行时数值统一放 `PlayerRunStats`，别往各个脚本里硬塞。
4. 消费侧只读倍率，不直接判断 `LevelUpOptionId`。
5. 升级状态和普通暂停分开，状态机要清楚。
6. 新增倍率后，先想“谁消费它”，再写代码。
7. 每次加完升级项，先跑一次 build，再进 Play 看链路。

## 八、思考题

**Q1：如果后面要加“最大生命 +20%”，应该改哪里？**  
> 先在 `LevelUpOptionId` 加新枚举，再在 `PlayerRunStats.Apply()` 加分支，最后让 `Health` 或 `GameSession` 读取这个倍率/加值。

**Q2：为什么不直接在 `GameSession` 里改玩家移速和武器伤害？**  
> 因为 `GameSession` 应该管流程，不该管具体消费细节。统一交给 `PlayerRunStats`，以后扩展才不会乱。

**Q3：如果一次吃到很多经验连升 2 级，当前结构还能接吗？**  
> 能接，但后面最好加一个待选择队列，让每升 1 级消耗 1 次选择，这样不会吞掉升级层数。

**Q4：为什么 `LevelUpChoiceView` 不直接 Apply？**  
> 因为 UI 不该是规则主人。它只负责把玩家点的结果传回去。
