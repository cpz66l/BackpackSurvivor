## 一、这节课实现了什么

### A 阶段 · 掉落数据分层（先掷品类，再掷子表）

- `LootEntry` 扩充字段：`category`（Xp/Gold/Equipment 品类）、`id`（名字）、`amount`（面额）、`width/height`（占格，供入包用）
- 新增 `DropChannel` 束结构：`probability`（这道门开不开）+ `subTable`（引用另一张表）→ **表引用表 = 递归成立**，一张表要么是束（channels 非空）要么是叶（entries 非空）
- `LootRoller.RollBundle()`：逐个频道掷概率，过了门的频道再对子表 `Roll()`，一次掉落可出多种物品（经验球 + 装备并行）
- **保底修正**：`Roll()` 里只有 `category == Equipment` 的条目才参与 pity 计数/清零——经验球必掉，不该稀释装备保底

### B 阶段 · 拾取方式分化（GDD 191/201/718 行背书）

- 新接口 `ICollectable`（`void Collect()`）："被收货口收走的能力"，`PickUpMagnet` 从依赖具体类改为依赖接口
- 新脚本 `XpOrb`（IPoolable + ICollectable）+ XpOrb 预制体 + 场景第三个 ObjectPool（货币池）
- `InventorySystem` 双频道分流：订 `DropItem.OnCollected` → 入包；订 `XpOrb.OnCollected` → 记经验
- **货币类磁吸自动拾取，装备类落地无磁吸**——有没有碰撞器决定走哪条道

### C 阶段 · 生成调度

- `LootManager.TrySpawnDrop(position, bundle)`：RollBundle 后按 entry.category 选池（装备 → dropPool，经验 → currencyPool 带随机偏移，Gold 留空挂账）
- `EnemyAI` 挂 `lootTable` 字段，普通怪/精英怪配不同束表

### 任务 4 · IInteractable 交互拾取

- 新接口 `IInteractable`（`GetPrompt()` / `Interact()`），独立于 Loot 目录，宝箱/撤离终端后续复用
- `DropItem` 摘掉磁吸、签第二份合同：`Interact()` 内部复用 `Collect()`，收货口一行不改
- 掉落物根物体加 trigger SphereCollider + 新 Layer `Interactable`
- `InteractDetector`（挂 Player）：OverlapSphereNonAlloc 节流扫描 → sqrMagnitude 找最近 → 目标变化发事件
- `InputReader` 加 E 键 action → `event Action OnInteract`（瞬时触发用事件，区别于 Attack 的持续状态位）
- `InteractPromptUI`（Presentation 层）：事件驱动显隐提示框，无 Update 轮询
- 地面物品自然清场：经验球 15s、装备加长消失时间（用户决策：折中方案 B）

### LootRoller.cs（纯 C#，可单元测试）

```csharp
public class LootRoller
{
    private int pityCount;
    private int pityThreshold;

    public LootRoller(int pityThreshold)
    {
        this.pityThreshold = pityThreshold;
        pityCount = 0;
    }

    // 束：逐频道掷概率，过门的频道对子表 Roll，一次可出多种
    public List<LootEntry> RollBundle(LootTableData bundle)
    {
        List<LootEntry> entries = new List<LootEntry>();
        if (bundle == null || bundle.channels == null || bundle.channels.Length == 0)
            return entries;
        foreach (var c in bundle.channels)
        {
            if (UnityEngine.Random.value < c.probability)
            {
                LootEntry entry = Roll(c.subTable);
                if (entry != null) entries.Add(entry);
            }
        }
        return entries;
    }

    // 叶：保底 + 权重随机。只有装备品类参与 pity
    public LootEntry Roll(LootTableData table)
    {
        if (table == null || table.entries == null || table.entries.Length == 0)
            return null;

        if (pityCount >= pityThreshold)   // 触发保底：只从 ≥蓝 条目里抽
        {
            LootEntry[] eligible = Array.FindAll(table.entries,
                e => e != null && e.weight > 0 && (int)e.rarity >= (int)Rarity.Rare);
            if (eligible.Length > 0)
            {
                LootEntry selected = PickByWeight(eligible);
                if (selected != null) { pityCount = 0; return selected; }
            }
        }

        LootEntry result = PickByWeight(table.entries);
        if (result == null) return null;
        // 中蓝以上清零；未中且是装备才累计（经验球不进保底循环）
        if (result.category == DropCategory.Equipment && (int)result.rarity >= (int)Rarity.Rare) pityCount = 0;
        else if (result.category == DropCategory.Equipment) pityCount++;
        return result;
    }

    private LootEntry PickByWeight(LootEntry[] entries) { /* 累加区间权重随机，total<=0 返回 null */ }
}
```

### LootManager.cs（按品类选池）

```csharp
public class LootManager : MonoBehaviour
{
    [SerializeField] private ObjectPool dropPool;      // 装备池
    [SerializeField] private ObjectPool currencyPool;  // 货币池
    [SerializeField] private int pityThreshold = 10;
    [SerializeField] private float offset = 0.8f;
    private LootRoller lootRoller;

    void Start() { lootRoller = new LootRoller(pityThreshold); }

    public void TrySpawnDrop(Vector3 position, LootTableData bundle)
    {
        List<LootEntry> list = lootRoller.RollBundle(bundle);
        foreach (LootEntry entry in list)
        {
            if (entry == null) continue;
            if (entry.category == DropCategory.Equipment)
            {
                DropItem dropItem = dropPool.Get(position).GetComponent<DropItem>();
                dropItem.Initialize(entry);
            }
            else if (entry.category == DropCategory.Xp)
            {
                Vector2 randomOffset = Random.insideUnitCircle * offset;
                Vector3 pos = position + new Vector3(randomOffset.x, 0, randomOffset.y);
                XpOrb xpOrb = currencyPool.Get(pos).GetComponent<XpOrb>();
                xpOrb.Initialize(entry);
            }
            else if (entry.category == DropCategory.Gold) { /* 挂账 */ }
        }
    }
}
```

### XpOrb.cs（货币：磁吸自动拾取）

```csharp
public class XpOrb : MonoBehaviour, IPoolable, ICollectable
{
    public static event Action<LootEntry> OnCollected;
    [SerializeField] private float survivalTime = 15f;
    private float survivalTimer = 0f;
    private ObjectPool pool;
    private PickUpMagnet pum;
    private LootEntry lootEntry;

    public void SetPool(ObjectPool p) => pool = p;

    // 池复用归零铁律：磁吸状态机 + 存活计时器，一个都不能少
    public void OnGetFromPool()
    {
        pum.StateReset();
        survivalTimer = 0f;
    }
    public void OnReturnPool() { }

    private void Awake() { /* 代码建球模型（黑）、Destroy模型碰撞器、GetComponent<pum> */ }

    private void Update()
    {
        survivalTimer += Time.deltaTime;
        if (survivalTimer >= survivalTime) Recycle();   // 自然清场
    }

    public void Initialize(LootEntry entry) { lootEntry = entry; }

    public void Collect()
    {
        OnCollected?.Invoke(lootEntry);   // 喊话，带上身份
        Recycle();
    }
    public void Recycle()
    {
        if (pool != null) pool.Return(gameObject);
        else Destroy(gameObject);
    }
}
```

### InteractDetector.cs（挂 Player：节流扫描 + 最近目标 + 事件）

```csharp
public class InteractDetector : MonoBehaviour
{
    public event Action<IInteractable> OnTargetChanged;   // 纯代码订阅 → C# event 而非 UnityEvent<T>

    [SerializeField] private float detectionRadius = 2.25f;
    [SerializeField] private LayerMask interactableLayerMask;
    [SerializeField] private float scanInterval = 0.1f;
    [SerializeField] private Collider[] buffer = new Collider[16];

    public IInteractable CurrentTarget { get; private set; }
    private IInteractable previousTarget;
    private Health playerH;
    private InputReader ir;
    private float timer;

    private void Awake() { ir = GetComponent<InputReader>(); playerH = GetComponent<Health>(); }
    private void OnEnable()  { ir.OnInteract += Interact; }
    private void OnDisable() { ir.OnInteract -= Interact; }

    private void Update()
    {
        timer += Time.deltaTime;
        if (timer >= scanInterval) { timer = 0f; Scan(); }
    }

    private void Scan()
    {
        int count = Physics.OverlapSphereNonAlloc(
            playerH.Position, detectionRadius, buffer, interactableLayerMask);

        IInteractable nearest = null;
        float minSqDist = Mathf.Infinity;
        for (int i = 0; i < count; i++)              // 只遍历 [0, count)，后面是上轮残留
        {
            var col = buffer[i];
            if (col == null) continue;
            var interactable = col.GetComponent<IInteractable>();
            if (interactable == null) continue;
            float sqrDist = (col.transform.position - playerH.Position).sqrMagnitude;
            if (sqrDist < minSqDist) { minSqDist = sqrDist; nearest = interactable; }
        }

        if (nearest != previousTarget)               // 只有变化才发事件
        {
            previousTarget = nearest;
            CurrentTarget = nearest;
            OnTargetChanged?.Invoke(nearest);
        }
    }

    private void Interact()
    {
        if (CurrentTarget == null) return;           // 对空气按 E 不炸
        CurrentTarget.Interact();
    }
}
```

private void OnEnable()
{
    DropItem.OnCollected += HandleCollected;   // 装备 → 入包
    XpOrb.OnCollected += HandleCurrency;       // 货币 → 记经验

private void HandleCollected(LootEntry entry)
{
    if (entry == null) return;
    Item item = new Item(entry.id, entry.rarity, entry.width, entry.height);
    if (Grid.TryFindFreeArea(item, out int x, out int y)) Grid.Place(x, y, item);
    else Debug.Log("背包已满");   // ⚠ 已知漏洞：此时物品已被 Collect 回收 → 被吞，挂账
}

private void HandleCurrency(LootEntry entry)
{
    if (entry == null) return;
    Debug.Log($"经验 +{entry.amount}");   // 经验系统接入前的临时账本
}

## 三、周期链路

### 掉落生成链路（两级表）

```
敌人 Die()
  → LootManager.TrySpawnDrop(尸体位置, lootTable束)
    → LootRoller.RollBundle(束)
        每个频道: Random.value < probability ? 过门 → Roll(子表)
        Roll(子表): pity 满? → ≥蓝条目池抽 → 清零 : 全表权重抽 → 装备才 pity++
    → 每个 entry 按 category 分流:
        Equipment → dropPool.Get → DropItem.Initialize(变色+存entry)
        Xp        → currencyPool.Get(带0.8随机偏移) → XpOrb.Initialize
        Gold      → （挂账）
```

### 经验球拾取链路（磁吸自动）

```
XpOrb 落地(Idle) → 玩家进 attractRange → StartAttract
  → Attracted: currentSpeed 累加封顶，朝玩家加速
  → ≤ collectRange → Collect() → OnCollected(entry)
  → InventorySystem.HandleCurrency → 经验 +amount
  → Recycle → 回池（OnGetFromPool: 磁吸状态+计时器双归零）
```

### 装备拾取链路（E 键手动）

```
DropItem 落地旋转 → 玩家进 detectRadius
  → InteractDetector 每 0.1s OverlapSphereNonAlloc → sqrMagnitude 找最近
  → 目标变化 → OnTargetChanged(target)
      → InteractPromptUI: text = GetPrompt() → 显示
  → 玩家按 E → InputReader.OnInteract → detector.Interact()
      → CurrentTarget.Interact() → Collect() → OnCollected(entry)
      → InventorySystem.HandleCollected → TryFindFreeArea → Place
      → grid.OnChanged → InventoryUIController.Redraw
  → 目标消失(回池/走出范围) → OnTargetChanged(null) → 提示框隐藏
```

## 四、设计思考（这节课真正学的东西）

### 1. 束结构 = "掉不掉"和"掉什么"拆成两道门

单表权重随机只能回答"掉什么"，回答不了"经验球必掉、装备 30% 掉、金币 10% 掉"这种**品类各有独立概率**的需求。束结构把每个品类包成一个频道：`probability` 管"掉不掉"，`subTable` 管"掉什么"。表引用表，递归天然成立——以后 Boss 表套三层也不用改代码。这是用户主动提出"现在就该做两级表"倒逼出来的设计，方向完全正确。

### 2. 保底修正：计数器只认目标品类

修正前的隐患：经验球必掉，如果每次掉落（含经验球）都重置或累计 pity，保底就失去意义。现在的规则一句话：**只有装备掷骰才进保底循环**——装备未出蓝则累计，装备出蓝则清零，其他品类路过不碰。做概率系统时，先问"这个机制的边界画在哪类事件上"。

### 3. 一个对象可以签多份接口合同

`DropItem` 同时是 `IPoolable`（能被池化）、`ICollectable`（能被收货口收走）、`IInteractable`（能被玩家交互）。三份合同互不干扰，关键是**每层职责只通过接口喊话**：磁吸组件不认识 XpOrb，只认识 ICollectable；探测器不认识掉落物，只认识 IInteractable。这就是"面向接口编程"在 Unity 组件里的落地形态。

### 4. `Interact()` 绕道 `Collect()` 而不是自己广播

交互 ≠ 收走。交互是"玩家发起了收走这个动作"，收走是"广播 + 回池"这套固定流程。`Interact() => Collect()` 让两条触发路径（磁吸碰取 / E 键）**汇合到同一个收货口**，下游的 InventorySystem 完全无感。如果 Interact 自己重写一遍广播+回收，就是复制粘贴出一个要同步维护的双胞胎。

### 5. 物理查询 vs 注册表：按"问题的空间形状"选方案

第 3 课敌人用 `TargetRegistry`（问的是"全图谁活着、谁离我最近"），这节课可交互物用 `OverlapSphereNonAlloc`（问的是"我周围 2 米有什么"）。口诀：**全图成员管理用注册表，局部空间询问用物理查询**。可交互物可以成百上千散落全图，但玩家只关心身边——物理引擎的空间加速结构就是为此而生；反过来敌人数量可控、AI 每帧都要全图索敌，注册表更省。

### 6. 拾取失败吞物品：收货口契约该升级了（挂账）

游玩实测暴露：空间够放 2×3 步枪，但因无法旋转放不下 → `HandleCollected` 只 Log → **物品已被 Collect 回收，凭空消失**。旋转（R 键）能缓解占位问题，但治标；本治是把收货口从"无条件收"改成**请求-确认**：`Interact()` 先问 InventorySystem"能放吗"，能才 Collect，不能就留在地上（并给"背包已满"反馈）。第 12/13 课择机修。

## 五、踩坑记录

| 坑 | 现象 | 根因 | 修法 |
|---|---|---|---|
| BUG-002 敌人死了不消失 | 尸体继续追人且不吃伤害 | 装备预制体摘了 PickUpMagnet，但 `DropItem.OnGetFromPool()` 里 `pum.StateReset()` 残留 → NRE 中断 Die() | 用户自己读 Debug 定位；清除 pum 全部引用 |
| BUG-003 经验球范围外秒吸 | 有的球正常、有的球一掉就飞脸 | `XpOrb.OnGetFromPool()` 空实现，复用球带 Attracted 状态+满档速度复活 | `pum.StateReset()` |
| BUG-004 经验球出生即死 | 不捡球一段时间后击杀不掉球 | 新加 survivalTimer 没进 OnGetFromPool，超时球带 15s+ 计时复活，首帧即 Recycle | `survivalTimer = 0f` |
| Input Actions 虚惊 | 以为删了 action | 编辑器改动未 Save Asset，只在内存；Git 零改动证实磁盘完好 | 关窗不保存即恢复；Git 是"写没写盘"的裁判 |
| Interact() 对空气按 E 炸 | NRE | CurrentTarget 无守卫 | 先判空再动手 |

**池化状态归零第四次复发，升级为机械流程：给池化类新增运行期字段的同一分钟，必须去 OnGetFromPool 归零它。**

## 六、面试问答

**Q：对象池复用为什么要重置状态？你们项目里怎么保证？**
A：池只关物体不动组件字段——这正是池省性能的意义。但复活的对象会带"前世记忆"：我们项目里因此出过四次事故（计时器未归零导致复用物秒消失/出生即死、状态机未归零导致范围外秒吸、残留调用导致 NRE）。保证手段是机械流程：凡池化类新增运行期字段，同一分钟在 `OnGetFromPool` 归零；review 时逐项问"这字段带旧值复活会不会出事"。

**Q：两级掉落表怎么设计的？**
A：束/叶双形态 SO。束表的每个频道是"probability 概率门 + subTable 子表引用"——先掷"掉不掉"，过门再对子表掷"掉什么"。表引用表形成递归，N 级不用改代码。保底只挂在叶子 Roll 上，且只有目标品类（装备）参与计数，避免必掉的经验球稀释保底。

**Q：OverlapSphereNonAlloc 的 buffer 为什么要预分配？遍历注意什么？**
A：避免每帧 GC 分配（探测是高频操作，0.1s 一次）。返回值是本次实际命中数，只能遍历 `[0, count)`——后面的槽位是上一次查询的残留，遍历整个数组等于信了下毒的数据，和池化不重置是同一个病。

**Q：装备手动捡、货币自动吸，架构上怎么实现分化？**
A：不写字类 if-else，靠**组件组合 + 物理层**分化：货币挂 PickUpMagnet（磁吸）、无碰撞器不进交互层；装备无磁吸、挂 trigger 碰撞器进 Interactable 层被探测器发现。两条路径最后汇合到同一个收货口事件，下游背包系统无感知。以后加新品类（如金币）只需选组件和层，不改任何已有代码。

**Q：UnityEvent 和 C# event 怎么选？**
A：需要在 Inspector 里可视化接线（策划/美术配回调）用 UnityEvent；纯代码订阅用 C# event——更轻、有编译期检查、支持 `?.Invoke`。本项目探测器到 HUD 是程序内部通信，选了 `event Action<IInteractable>`。另外泛型 UnityEvent<T> 不序列化显示在 Inspector，要显示得声明具体子类。

**Q：怎么探测玩家周围的可交互物？为什么不用注册表？**
A：OverlapSphereNonAlloc 节流扫描（0.1s）+ sqrMagnitude 比最近 + 变化才发事件。可交互物是"局部空间询问"——全图可以有几百个，玩家只关心身边 2 米，物理引擎的空间结构天然适合；注册表适合敌人那种"全图成员管理+每帧全图索敌"的形状。方案跟着问题的空间形状走。

## 八、思考题（附复习参考）

**Q1：敌人用注册表、可交互物用物理查询。如果反过来——敌人用物理查询、可交互物用注册表——各自会出什么问题？**
> 敌人用物理查询：每帧全图索敌变成每帧物理扫描，敌人多了开销爆炸，且物理查询只能答"周围"，答不了"全图最近"；可交互物用注册表：全图几百个静态物体注册/反注册纯属浪费，查询时还要遍历全表算距离，把 O(周围几个) 的事做成 O(全图)。方案要匹配问题的空间形状。

**Q2：`Interact()` 为什么不直接广播 OnCollected + 回收，非要绕道 `Collect()`？**
> 交互和收走是两件事。Collect 是收货口的标准流程（广播+回池），磁吸碰取和 E 键拾取只是两种"触发方式"。绕道 Collect 让两条路径汇合到一个出口，下游无感；自己重写就是复制一个要同步维护的双胞胎——以后收货口改了（比如加"请求-确认"），要改两处，必漏一处。

**Q3：提示框要升级成"跟着物品头顶走"的世界空间 UI，哪层要动、哪层不用动？**
> 只动 Presentation 层：提示框改世界空间 Canvas 或屏幕坐标投影（WorldToScreenPoint），订阅的 OnTargetChanged 事件里需要带上位置信息（或 UI 每帧读 CurrentTarget 的 transform——这种"跟着走"是合理的轮询场景，和显隐的事件驱动不冲突）。GamePlay 层的探测逻辑、Loot 层的物品本身都不用动。这就是分层的好处：表现升级不碰逻辑。

**Q4：束结构里"表引用表"为什么叫递归？三级表（比如 Boss 表套精英表套基础表）要改代码吗？**
> RollBundle 遍历频道时对 subTable 调 Roll，而 subTable 本身可以是又一张束表——方法调用了"和自己同类的数据结构"，这就是递归的数据形态。不用改代码：频道里嵌束表时 Roll 需要换成 RollBundle 转发（当前实现频道只接叶表，Boss 三层表时这是一个小扩展点，改 RollBundle 一行分支即可）。

**Q5：保底为什么只计装备品类？如果经验球也累计 pity 会怎样？**
> 经验球是必掉项，如果它也累计 pity，玩家永远攒不出保底（每次掉落都"未中蓝"……其实经验球根本不是装备，计数逻辑会被污染）；如果它触发清零更糟——保底永远触发不了。概率机制的计数边界必须精确画在它服务的目标事件上。
