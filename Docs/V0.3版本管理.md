# V0.3 版本管理约定

> 适用范围：《背包幸存者》V0.3 及后续 Demo 扩展阶段  
> 生效时间：2026-08-11  
> 核心变化：从“课时制推进”切换为“版本号 / 模块号推进”。

---

## 一、为什么切换

V0.1 和 V0.2 更像从零到一的学习与原型阶段，适合用“第几课”管理：每次一个清晰主题、一个验收目标、一个总结文档。

V0.3 开始，项目已经有正式 Build、Release、README、展示视频和公开复盘。后续工作不再是单线教学推进，而是围绕已有工程做内容扩展、架构补强和版本迭代。因此采用版本号管理更合适。

新的目标是：

```text
按模块拆版本
按小快照控制风险
按验收结果决定推进
按 commit 保留可回退节点
```

---

## 二、版本号规则

### 1. 大版本

```text
0.3.0
```

代表 V0.3 总体开发线，不直接对应一次小功能提交。

### 2. 模块版本

```text
0.3.1 升级候选池模块
0.3.2 邻接效果架构模块
0.3.3 新邻接效果实装模块
0.3.4 内容池扩展模块
0.3.5 音频与 BGM 模块
0.3.6 敌人移动优化模块
0.3.7 Boss 一期模块
0.3.8 Boss 二期模块
0.3.9 本地存档与纪录模块
0.3.10 V0.3 平衡、Build 与 Release
```

模块版本表示一个独立能力块，通常会包含多个小快照。

### 3. 小快照版本

```text
0.3.1.1 升级枚举与数据结构
0.3.1.2 PlayerRunStats 扩展
0.3.1.3 升级生成器权重与门槛
0.3.1.4 UI 文案与验收
```

小快照版本表示一次可验证、可提交、可回滚的小改动。

### 4. 版本号使用原则

- 一个版本号只解决一个明确目标。
- 小快照必须能被验收，不能只是“写了一半”。
- 如果一个功能风险高，先拆成更多小快照。
- 如果一个版本产生 Bug，优先在同一模块下开修复小版本。
- 每个模块完成后再写模块复盘，不再每个小快照写九章总结。


### 2. 本地私有文档

以下文档属于个人工作台，不提交公开仓库：


### 3. V0.3 开发日志格式

V0.3 不再每次写“第 NN 课总结”，改为在 `Docs/V0.3开发日志.md` 中追加：

```markdown
## v0.3.x.y · 标题

### 目标
### 改动
### 验收
### Bug / 风险
### 下一步
```

如果某个模块很大，可以在模块完成后补一份独立复盘，例如：

```text
Docs/V0.3.1升级候选池复盘.md
```

## 四、AI 协作规则

V0.3 开始，协作方式从“导师只给提示”升级为“核心逻辑亲写 + 重复样板由 AI 加速”。

### 用户亲手写

- 新模块核心架构。
- 关键规则判断。
- 影响系统边界的设计。
- 高风险重构。
- 需要真正理解的 Gameplay 主逻辑。

### AI 可以直接贴

- 枚举扩展。
- switch / case 分支。
- 重复字段和属性。
- UI 文案映射。
- 配置表样板。
- 简单 Getter / Setter。
- 低风险模板类。
- 重复测试剧本骨架。

### Review 规则保持不变

Review 继续分为：

```text
【必须改】影响正确性、稳定性、架构边界或打包风险
【建议改】影响可读性、可维护性、表现体验或后续扩展
```

## 五、提交规则

### 小快照提交

```text
v0.3.1.1 扩展升级选项枚举
v0.3.1.2 扩展PlayerRunStats
v0.3.1.3 升级生成器权重与门槛
```

### 模块完成提交

```text
v0.3.1 完成升级候选池模块
v0.3.2 完成邻接效果架构整理
```

### 修复提交

```text
fix(v0.3.1): 修复升级选项重复出现
fix(v0.3.5): 修复BGM跨场景重复播放
```

### 提交前检查

继续执行：

```powershell
dotnet build "BackpackSurvivor\BackpackSurvivor.sln" --no-restore
rg -n "UnityEditor|ShadowCascadeGUI|Unity\.VisualScripting" BackpackSurvivor/Assets/BackpackSurvivor/Scripts
git status --short
```

## 六、V0.3 能力展示目标

V0.3 的每个模块都应尽量覆盖一种可展示能力：

| 模块 | 展示能力 |
| --- | --- |
| 升级候选池 | 数值成长、随机生成、权重控制、玩家选择设计 |
| 邻接效果架构 | 规则系统、可扩展设计、战斗与背包解耦 |
| 内容池扩展 | 配置设计、掉落表维护、内容生产管线 |
| 音频与 BGM | 表现包装、AudioSource/AudioMixer 管理、反馈节奏 |
| 敌人移动优化 | AI 行为、性能取舍、群体移动与 Profiler 验证 |
| Boss | 状态机、技能系统、阶段战斗、HUD 与奖励闭环 |
| 存档纪录 | 本地持久化、JSON 数据、版本迁移、局外留存 |
| V0.3 发布 | Build、Release、README、版本复盘和交付能力 |

V0.3 不只是“多一些内容”，而是要证明：已有架构可以继续承载内容扩展。
