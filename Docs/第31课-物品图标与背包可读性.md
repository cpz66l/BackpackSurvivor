> 课程周期：2026-08-06  
> 前置：第30课《攻击芯片效果实装》  
> 关键词：ItemIconResolver、透明贴图、等级星星、邻接接边、矩形适配、UI 可读性

## 一、这节课实现了什么

第31课把背包格子从“文字 + 稀有度底色”的开发期显示，升级成了更接近正式 Demo 的视觉表达。现在玩家不需要逐个读文字，就能从图标、底色、星星和接边判断物品类型、稀有度、等级和邻接状态。

本课完成后，ItemView 的信息层级变成了：

```text
稀有度背景色
  ↓
透明物品图标
  ↓
邻接接边 / 激活武器角标 / 等级星星
  ↓
悬停 Tooltip 详细信息
```

### 任务 1 · 新增 ItemIconResolver

- 新增 `ItemIconResolver`，放在表现层 `BS.Presentation`。
- 通过 `ItemTag -> Sprite` 映射，为物品查找对应图标。
- `InventoryUIController.Redraw()` 负责查图标，再传给 `ItemView.Bind()`。
- `BS.Inventory` 不引用 Sprite，继续保持纯 C# 数据层。

这一步让图标系统只存在于表现层，不污染第9课建立的背包纯数据边界。

### 任务 2 · ItemView 接入透明图标

- `ItemView` 新增 `iconImage` 和 `iconSprite`。
- 有图标时隐藏格子文字，只显示透明 PNG 物品主体。
- 没有图标时保留 `item.Id` 文本兜底，避免配置遗漏后格子完全空白。
- `iconImage.preserveAspect = true`，防止 Sprite 被拉伸。
- `iconImage.raycastTarget = false`，防止透明区域吃拖拽射线。

透明贴图的价值在于：图标表达物品类型，稀有度底色继续表达品质，两套信息可以共存。

### 任务 3 · 等级显示升级为星星

- `ItemView` 新增 `LevelOne / LevelTwo / LevelThree` 三个星星 Image。
- Lv.1 显示 1 颗星，Lv.2 显示 2 颗星，Lv.3 显示 3 颗星。
- 星星固定在右上角，从右向左排列。
- 星星尺寸跟 `step` 走，不随大物品无限放大。

这一步把“等级文字”变成了“即时可扫的视觉符号”，玩家整理背包时更容易看出哪些物品已经合成过。

### 任务 4 · 邻接接口从点升级为接边

- 原来的 `topConnector / rightConnector / bottomConnector / leftConnector` 继续复用。
- 布局从小方块/小点改成边缘长条。
- 灰色接边表示“这条边可以参与邻接”。
- 金色接边表示“这条边已经触发真实有效效果”。
- 接边长度根据物品实际宽高计算，2x1、3x2、1x2 都能自然适配。

邻接规则本质是“边与边相连”，所以用整条边表达，比接口点更符合玩家直觉。

### 任务 5 · 图标从正方形适配升级为矩形适配

- 第一版用短边算 `iconSize`，对 1x1 物品有效，但 3x2 步枪、霰弹枪、防具会显得比例不协调。
- 最终改成根据物品实际占格矩形计算 `iconWidth / iconHeight`。
- 图标容器跟随物品比例，Sprite 本体通过 `preserveAspect` 保持等比。
- 透明 PNG 如果本身按物品占格比例切割，就能自然填满自己的视觉区域。

这一步解决了“长条物品被塞进正方形框”的观感问题。

### 任务 6 · 旋转状态下 UI 自动重排

- `HandleRotate()` 已经调用 `ghost.UpdateOverlayLayout(step)`。
- 图标区域、接边、星星、激活角标都依赖 `item.Width / item.Height`。
- 因此拖拽旋转时，表现层会跟随当前物品状态重算，不需要额外特判。

本课延续了第28课的原则：旋转相关表现从物品当前状态推导，而不是到处写补丁。

### 任务 7 · 最终验收通过

- 主要物品拥有类别图标。
- 透明图标能叠在稀有度底色上。
- 等级星星比文字等级更醒目。
- 邻接点升级为接边后，可连接方向更直观。
- 3x2 武器/防具通过矩形适配后观感明显改善。
- 拖拽、旋转、Tooltip、武器激活标记没有被图标系统破坏。
- `dotnet build` 通过，危险 using 扫描干净。

## 二、最终代码（关键片段）

### 1. ItemIconResolver

```csharp
public class ItemIconResolver : MonoBehaviour
{
    [System.Serializable]
    private class IconEntry
    {
        public ItemTag tag;
        public Sprite sprite;
    }

    [SerializeField] private List<IconEntry> icons;

    public Sprite GetIcon(Item item)
    {
        if (icons == null || item == null || icons.Count == 0)
            return null;

        foreach (var entry in icons)
        {
            if (entry.tag == item.Tag)
                return entry.sprite;
        }

        return null;
    }
}
```

这个类只做 `ItemTag -> Sprite`，不处理规则、不处理掉落、不处理战斗，所以放在 Presentation 层最合适。

### 2. Redraw 时传入图标

```csharp
Sprite sprite = itemIconResolver == null ? null : itemIconResolver.GetIcon(item);
itemView.Bind(item, step, this, sprite);
```

控制器仍然是投影器：从数据层拿 Item，从表现层拿 Sprite，再交给 ItemView 显示。

### 3. ItemView.Bind 接收 Sprite

```csharp
public void Bind(Item item, float step, InventoryUIController ctrl, Sprite sprite)
{
    controller = ctrl;
    this.item = item;
    iconSprite = sprite;
    label.text = "";

    GetComponent<RectTransform>().sizeDelta =
        new Vector2(item.Width * step, item.Height * step);

    UpdateOverlayLayout(step);
}
```

`Bind()` 仍是木偶入口，只是它现在接收该物品的表现资源。

### 4. 图标显示兜底

```csharp
if (iconImage != null && iconSprite != null)
{
    iconImage.sprite = iconSprite;
    iconImage.preserveAspect = true;
    iconImage.raycastTarget = false;

    LayoutEdge(iconImage, new Vector2(0.5f, 0.5f), iconPosition, size);
    iconImage.enabled = true;
}
else if (iconImage != null)
{
    iconImage.enabled = false;
    label.text = $"{item.Id}";
}
```

这里有两个要长期记住的 UI 习惯：

```text
preserveAspect = true   防止图标变形
raycastTarget = false   防止透明区域吃鼠标事件
```

### 5. 等级星星布局

```csharp
float starSize = Mathf.Clamp(step * 0.20f, 12f, 18f);
float starGap = Mathf.Clamp(step * 0.04f, 2f, 4f);

LayoutImage(LevelOne, new Vector2(1, 1),
    new Vector2(-inset, -inset - 3f), starSize);

LayoutImage(LevelTwo, new Vector2(1, 1),
    new Vector2(-inset - 1 * (starSize + starGap), -inset - 3f), starSize);

LayoutImage(LevelThree, new Vector2(1, 1),
    new Vector2(-inset - 2 * (starSize + starGap), -inset - 3f), starSize);
```

星星按右上角锚点排布，无论物品多宽，Lv.1 都在最右，Lv.2 和 Lv.3 向左展开。

### 6. 接边布局

```csharp
float edgeThickness = Mathf.Clamp(step * 0.08f, 4f, 7f);
float edgeInset = Mathf.Clamp(step * 0.05f, 3f, 5f);

Vector2 upAndDown = new Vector2(itemPixelWidth - inset * 2, edgeThickness);
Vector2 leftAndRight = new Vector2(edgeThickness, itemPixelHeight - inset * 2);

LayoutEdge(topConnector, new Vector2(0.5f, 1), new Vector2(0, -edgeInset), upAndDown);
LayoutEdge(rightConnector, new Vector2(1, 0.5f), new Vector2(-edgeInset, 0), leftAndRight);
LayoutEdge(bottomConnector, new Vector2(0.5f, 0), new Vector2(0, edgeInset), upAndDown);
LayoutEdge(leftConnector, new Vector2(0, 0.5f), new Vector2(edgeInset, 0), leftAndRight);
```

接边不是新规则，只是新表现。`visibleSides / activeSides` 仍然决定灰边和金边。

### 7. 矩形图标适配

```csharp
float availableW = itemPixelWidth - inset * 2f;
float availableH = itemPixelHeight - inset * 2f;

float iconWidth = availableW * 0.85f;
float iconHeight = availableH * 0.85f;
Vector2 size = new Vector2(iconWidth, iconHeight);
```

这一步把图标框从正方形升级成物品形状矩形，长条武器和防具不会再被压进方盒子里。

### 图标资源链路

```text

  ↓

  ↓

  ↓

  ↓

  ↓
```

## 四、设计思考

### 1. 为什么图标解析器放在 Presentation 层？

`Item` 属于纯数据层，不能知道 Sprite。Sprite 是 Unity 表现资源，只应该由 UI 层持有。如果把 Sprite 放进 Item，就会让 `BS.Inventory` 引入 UnityEngine，破坏第9课建立的纯 C# asmdef 边界。

### 2. 为什么透明图标要叠在稀有度底色上？

透明 PNG 不负责当底板，它只负责表达物品主体。稀有度颜色仍然由 `bg` 表达，这样玩家一眼能同时读到“这是什么物品”和“这个物品是什么品质”。

### 3. 为什么等级适合用星星？

背包格子空间很小，文字会跟物品名、价值、图标、接口抢空间。星星是更轻的等级符号，不需要玩家阅读，也不需要本地化。

### 4. 为什么邻接接口要从点变成接边？

邻接规则是“某条边能和另一条边连接”。用小点表示时，玩家容易把它理解成按钮或装饰点；改成整条边后，规则语言和视觉语言统一了。

### 5. 为什么图标不能一直用正方形适配？

手枪、芯片、收集品接近 1x1，正方形适配没问题。但步枪、霰弹枪、防具是 3x2 或 2x3 的占格物品，视觉上就应该更长或更宽。矩形适配能让图标尊重物品占格形状。

### 6. 为什么接边透明度要调低？

接边是规则提示，不是主体图标。透明度降低后，接边仍然能被看见，但不会压住透明图标和稀有度底板。Demo 阶段这种“刚好能看懂”的反馈，比过度炫更重要。

## 五、踩坑记录

### 1. 透明贴图也可能吃鼠标事件

- **现象风险**：图标看起来透明，但鼠标拖拽、悬停、点击被子 Image 挡住。
- **根因**：Unity UI 的 Image 按 RectTransform 参与射线检测，不按透明像素判断。
- **修复**：`iconImage.raycastTarget = false`，星星和接边也保持 Raycast Target 关闭。
- **沉淀**：凡是 ItemView 内部装饰性 Image，默认都不应该吃射线。

### 2. Preserve Aspect 在 Inspector 里不一定好找

- **现象风险**：UI Image 被矩形容器拉伸，图标比例变怪。
- **根因**：`Preserve Aspect` 是 Image 组件字段，不在 Sprite 导入设置里。
- **修复**：在代码里兜底写 `iconImage.preserveAspect = true`。
- **沉淀**：关键 UI 属性不要只依赖 Inspector，必要时运行时兜底。

### 3. 正方形图标框不适合长条物品

- **现象风险**：步枪、霰弹枪、防具这类 3x2 贴图显得比例不协调。
- **根因**：第一版用短边算正方形 iconSize，忽略了物品占格形状。
- **修复**：改为 `iconWidth / iconHeight` 矩形适配。
- **沉淀**：背包游戏的图标布局应该尊重占格形状，而不是统一头像框逻辑。

### 4. UI 透明度要控制在 0 到 1

- **现象风险**：颜色过亮或表现不符合预期。
- **根因**：Unity `Color` 的 alpha 语义是 0 到 1，写过大值没有设计意义。
- **修复**：金色激活边使用 `1f`，灰色未激活边使用较低透明度。
- **沉淀**：调表现时也要守住数值范围，不要让“看起来能跑”的参数留进正式代码。

## 六、面试问答

**Q1：你是怎么给背包物品接入图标的？**  
> 我没有把 Sprite 塞进物品数据层，而是在表现层新增 `ItemIconResolver`，用 `ItemTag -> Sprite` 做映射。`InventoryUIController.Redraw()` 时根据 Item 查 Sprite，再传给 `ItemView.Bind()`。这样 UI 能显示图标，同时 `BS.Inventory` 仍然保持纯 C#。

**Q2：为什么图标用透明 PNG？**  
> 因为稀有度已经由格子背景色表达。透明 PNG 只显示物品主体，可以让白绿蓝紫金底色透出来。这样一个格子里能同时表达“物品类型”和“物品品质”。

**Q3：为什么等级改成星星？**  
> 背包格子空间有限，文字等级会和图标、接口、价值信息抢位置。星星是更轻量的视觉符号，玩家不用读文字就能看出合成等级。

**Q4：为什么把邻接点改成接边？**  
> 因为邻接系统的规则本质是边连接。接边比点更直接地表达“这条边可以连”以及“这条边已经生效”，能降低玩家理解规则的成本。

**Q5：为什么 3x2 图标要用矩形适配？**  
> 因为物品占格本身就是规则表达。步枪、防具这种大物品如果被塞进正方形区域，会丢失占格感。矩形适配让图标区域跟随 `item.Width / item.Height`，更符合玩家预期。

**Q6：为什么要关闭图标和星星的 Raycast Target？**  
> 因为它们只是装饰层，不应该处理鼠标事件。透明 Image 仍然可能按矩形吃射线，如果不关，拖拽和 Tooltip 可能出现很隐蔽的问题。

**Q7：这节课和前面构筑系统有什么关系？**  
> 前面第21~30课让构筑规则真实生效，这节课让玩家能看懂构筑规则。灰边告诉玩家可连接方向，金边告诉玩家真实生效方向，图标和星星帮助玩家快速判断物品类型与等级。

## 七、习惯清单

1. 表现资源放 Presentation 层，不让纯数据层依赖 Unity Sprite。
2. 格子信息要分层：底色表达品质，图标表达类型，星星表达等级，接边表达规则。
3. 装饰性 UI Image 默认关闭 Raycast Target。
4. 关键 UI 属性可以用代码兜底，不完全依赖 Inspector。
5. 背包物品图标要尊重占格比例，长条物品不要强塞正方形框。
6. UI 颜色透明度控制在 0 到 1，不保留无意义参数。
7. 规则表现要贴近规则本质：边连接就用边来表达。
8. Tooltip 负责详细信息，格子内只放一眼能读懂的信息。
9. Demo 冲刺期优先做“立刻提升可读性”的轻量表现优化。

## 八、思考题（附复习参考）

**Q1：如果以后新增 30 种物品，ItemIconResolver 还适合手动 List 配置吗？**  
> Demo 阶段适合，因为简单、直观、风险低。物品数量变多后，可以考虑把图标放进 ItemDefinition ScriptableObject，或者做一个按 ItemTag 自动索引的配置表。

**Q2：为什么图标系统不能放进 BS.Inventory？**  
> 因为 `BS.Inventory` 是纯 C# asmdef，不应该引用 UnityEngine。Sprite 是 Unity 表现资源，属于 UI 层事实。数据层只提供 `ItemTag / Rarity / Level / Size`，表现层负责把这些数据翻译成图像。

**Q3：如果接边和星星重叠，应该优先保谁？**  
> 优先保星星和金色有效边。星星表达等级，金色边表达真实生效规则，二者都是高价值信息。灰色可连接边可以更透明、更细、更靠边。

**Q4：如果某张 PNG 本身透明留白太多，代码应该继续放大吗？**  
> 不应该无限调代码比例。代码负责统一布局，资产本身应该尽量裁紧。只有当个别物品确实需要差异化时，再考虑在图标配置里加单独 scale/offset。

**Q5：为什么这节课对 Demo 很有价值？**  
> 因为可玩 Demo 不只是系统能跑，还要让玩家看懂自己在做什么。图标、星星和接边把背包构筑从“开发者知道”变成“玩家能读懂”。
